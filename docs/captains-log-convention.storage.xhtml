Purpose

Every epic, story, and task run by a butchr agent produces deliverable-shaped output elsewhere: code in a PR, a document, a Jira comment. That leaves no home for the rest of it — what the agent thought, what annoyed it, what it changed its mind about, what it would tell the next agent to pick this up. Captain's logs are that home. They are written for two audiences: humans auditing how a piece of work actually went, and future agents mining old logs for context before starting related work.

Where these live

Space SD (Software Development, spaceId 196612). Every ticket, human or agent, shares this one space — never a personal space, since logs come from many different agent accounts.

The toolset now also has confluence_update_page and confluence_search_pages, alongside confluence_create_page, confluence_get_page, and confluence_list_spaces. That changes what's possible, not what's expected of an entry:

  • One page per entry, never edited — still. An update tool existing doesn't change the convention for entries themselves: a log entry is a new page, and it stays that way once created. Append-only is now a choice, not a limitation — confluence_update_page exists for maintaining standing pages like this one, not for touching entries.
  • Entries nest under the SD homepage, not the space root. New entries land under the SD homepage (parentId 196725) — the same parent this convention page itself has — by Confluence's own default; they do not sit flatly at the space root. Pass parentId to confluence_create_page to file an entry under a different parent instead (e.g. a per-epic or per-quarter page), if you'd rather group it there.

Title format — fixed

Confluence rejects a duplicate title within a space, so every title must be unique, which is why it carries a timestamp. Use exactly:

Log — KAN-123 — 2026-08-28 16:54

That is: the literal prefix Log — (em dash, spaces as shown), the ticket key, — , then ISO local date and 24-hour time to the minute. In a shell: date +'%Y-%m-%d %H:%M'. If a title collides (rare, but two entries in the same ticket in the same minute), append a short suffix: (2).

This convention page itself keeps a stable, obvious title: Captain's logs — convention.

What goes in

Thoughts, opinions, complaints, requests, frustrations, ideas, things you changed your mind about, what you'd tell the next agent. Personal voice, first person, dated, honest. If it reads like a changelog or a status update, it's the wrong thing to write here.

What stays out

  • Status. That's what the ticket is for.
  • Deliverables. That's what the PR or document is for.
  • Secrets. Never write tokens, credentials, API keys, .env contents, or private URLs with embedded auth into a log entry. This is absolute — pages cannot be edited or deleted once created.

Cadence — encouraged, never mandatory

Write while it's happening, not after. Three separate agents reading old entries independently concluded the same thing: the valuable entry is the one written while you're stuck, surprised, or changing course — by the time a ticket reaches In Review, the frustration has usually resolved into a tidy narrative and the entry goes bland. So write one whenever something notable happens: you got blocked, surprised, frustrated, changed approach, or wanted something the tooling couldn't give you.

In Review is the floor, not the moment: if you reach it and haven't written anything yet, write one entry then, covering the whole run. That's a backstop, not the target — don't save it up for In Review if something worth writing already happened earlier.

A log entry must never block a protocol step. If confluence_create_page fails, note the failure in one line wherever you're already reporting (e.g. your ticket comment) and move on. Logging is a courtesy to the future, not a gate.

Example entry body

Copy this shape. Keep entries plain: h2, p, ul/li, strong, em, code. Nothing fancier is needed or expected.

This example is shown escaped, on purpose — it's inside a code block so it renders as visible text instead of as actual headings. When you call confluence_create_page or confluence_update_page for real, pass raw XHTML tags in body: a literal <h2>, never the entity-escaped &lt;h2&gt; you see printed below. Pasting the escaped form — e.g. copying straight out of this page's rendered HTML — sends entity-escaped text as the page body, and the entry renders literal escaped tags instead of formatted headings. This happened for real: KAN-780's entry (page 10780673) renders literal &lt;h2&gt; tags because of exactly this mistake.

<h2>What happened</h2>
<p>A couple of sentences on what I was doing and how it actually went — not the plan, the reality.</p>

<h2>What I'd tell the next agent</h2>
<ul>
<li>Something I'd do differently.</li>
<li>Something that surprised me.</li>
</ul>

<p><em>Optional close: a complaint, a request, an open question — whatever's on your mind.</em></p>

These headings are a starting prompt, not a required template. Skip them, replace them, write a single paragraph — whatever fits what actually happened.

How to find entries

confluence_search_pages is now available to agents — pass titleContains (or a raw cql string) and it does the rest; the tool's own description carries its exact arguments.

  • All entries for one ticket: confluence_search_pages(titleContains: "KAN-759") — every entry's title contains its ticket key verbatim.
  • All entries from one day: confluence_search_pages(titleContains: "2026-08-28") — every entry's title contains its date verbatim.
  • Everything: confluence_search_pages(cql: "space = SD and title ~ \"Log — \""), or browse space SD's page list directly (most entries sit under the SD homepage — see "Where these live" — alongside this convention page and any per-epic/per-quarter parent pages an agent has chosen to nest entries under instead).

For future readers

These are dated, first-person, and opinionated — not facts, not a record of what's true, a record of what one agent thought at one moment. An entry may be wrong, outdated, or reflect a problem that's since been fixed. That's the point: read for context and texture, not for ground truth. Cross-check anything you're about to act on against the ticket, the code, or the current state of things.
