### Added
- **Validated, atomic, backed-up `rules.json` writes, as a library (FACTORY-658, FACTORY-643 slice 2, GitHub issue #616).** `src/rules/write-rules.ts`'s `writeRulesFile` is the one function every rules-file writer (the web write path, FACTORY-663) goes through: validates the whole resulting file through the same entry point the daemon's own startup uses before touching disk (a bad edit writes nothing, no temp file left behind), then — holding an in-process plus cross-process (`O_EXCL` lock file with pid/staleness detection) write lock across the whole read-validate-backup-rename span, so concurrent writers never interleave — backs up the current file to `rules.json.bak-<UTC timestamp>` (unique even across two writes in the same second; fsynced; pruned to the newest 20), then writes atomically — a unique `O_EXCL`+`O_NOFOLLOW` temp file in the same directory, fsync, rename, directory fsync — preserving the file's existing mode. An optional `opts.ifMatch` (sha256 etag) refuses a write whose expected prior content is stale, for optimistic concurrency; `rulesEtag` reads the current etag for a GET handler. `restoreBackup` restores a previous backup through that exact same validated/atomic/locked path, byte-identical to the backup's own bytes, for a web UI "Undo" — its `backupId` argument (planned to arrive straight from an HTTP path segment) is validated against an anchored pattern matching only the shape this module itself ever produces, refusing a path-traversal id before any path is built from it. `updateRulesFile(mutator, ...)` is the safe read-modify-write entry point — the mutator runs on the current text inside the same lock the write itself takes, closing the lost-update window a bare `writeRulesFile` call can't close without a fresh `ifMatch`. `assertOnlyChanged(prevText, nextText, allowedPaths)` deep-diffs two rules documents and can be threaded through `opts.allowedPaths` to restrict a write to an allowlist of changed paths. `setRuleEnabled` is a pure text-level editor that flips one rule's `enabled` field and leaves every other rule and byte of formatting untouched. ANY symlink at the rules file path (or a backup entry) is refused outright; backup pruning only ever touches names matching the strict backup-id shape, so a hand-made backup is never swept up; the cross-process lock never reclaims from a confirmed-live pid regardless of age, fails closed on unreadable lock content, and reclaims a dead lock via an atomic rename plus read-back verification so two racing reclaimers can never both believe they hold it; a directory fsync failure is only swallowed for a platform that genuinely cannot fsync a directory handle, never for a real disk error. No CLI or HTTP route in this slice — `butchr rules check` is unaffected.
