### Added
- **Validated, atomic, backed-up `rules.json` writes, plus `butchr rules enable|disable <id>` and `butchr rules add --from <file>` (FACTORY-658, FACTORY-643 slice 2, GitHub issue #616).** `src/rules/write-rules.ts`'s `writeRulesFile` is the one library function every rules-file writer (the CLI today, a web endpoint later) goes through: validates the whole resulting file with the daemon's own loader before touching disk (a bad edit writes nothing, no temp file left behind), backs up the current file to `rules.json.bak-<UTC timestamp>` (pruned to the newest 20), then writes atomically — a unique `O_EXCL` temp file in the same directory, fsync, rename — preserving the file's existing mode. `enable`/`disable` go through a pure text-level editor, `setRuleEnabled`, that flips ONE rule's `enabled` field and leaves every other rule and byte of formatting untouched. `rules add --from <file.json>` adds one rule object whose `id` must be new. All three report the backup path and which rule id(s) changed, and are documented in a new README "Editing rules safely" subsection.
