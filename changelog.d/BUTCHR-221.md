### Added
- **The stall deadlock-breaker now actually breaks deadlocks: a debounced wake comment on a stalled ticket (BUTCHR-221/BUTCHR-210).** `agent:stalled` (`src/agents/stalled.ts`) was a *visibility* signal only — a label plus a per-poll log line — and nothing in the codebase ever consumed it to wake the agent. This was not a bug in a working remediator; the remediator never existed, which cost the fleet two separate becalmings (roughly 2h and 7.5h) before a human noticed and intervened by hand. `src/agents/stall-remediation.ts` is the missing half: it posts exactly one observational wake comment per continuous stalled episode, deduped by adoption against the ticket's own comment history (survives a daemon restart with an empty in-memory map) and backstopped by a per-ticket rate cap, reusing the house `findMarked`/`RateCap` mechanism (`src/agents/escalation-helper.ts`) rather than inventing a second one. Wired as an optional dependency in `src/labels/sync.ts` (omitted = disabled) and constructed in `src/daemon/index.ts` alongside the other detectors, posting through the same `ops.addComment` seam `parked.ts` already uses — no second Atlassian writer.
- **Gated on the label as already APPLIED (read from Jira at the top of a poll), never on that same poll's newly-stabilized candidate.** This is not merely "no more eager than the label" (though it is that too — `agent:stalled` is itself delayed by `AgentLabelStabilizer`'s two-consecutive-poll confirmation, and a remediation comment is louder than the label, so it must never be cheaper to trigger): it is what keeps a wake comment from ever landing on the same poll as the label write that precedes it, which matters because `src/jira-watch/own-writes.ts`'s own-write ledger fires an async read-back of a ticket's `updated` field right after a label write and would otherwise be able to fold a same-poll comment into that read-back — silently swallowing the very wake this feature exists to deliver, for every watcher of the ticket including its own agent. Reproduced empirically (not just argued) in `test/unit/stall-remediation-own-write-race.test.ts`, against the real ledger.
- **A found-and-fixed prefix-collision defect in the reused dedupe mechanism, scoped to this module's own call site only.** `findMarked`'s identity match is a bare `body.includes(...)`, and Jira keys are not prefix-free (`"fingerprint: KAN-1"` is a substring of `"fingerprint: KAN-19"`). `parked.ts` is incidentally safe because its bodies always carry a `stage: N` line after the fingerprint; a single-shot remediator with no stages has nothing to force that ordering unless it deliberately arranges one. Fixed by keeping a line after the fingerprint and delimiting the identity check on the newline that guarantees (`fingerprint: ${issue}\n`), proven both ways — a prefix-related key is never falsely adopted, and genuine self-adoption still works — with the longer key posting first (`test/unit/stall-remediation.test.ts`'s AC8 regression test). `escalation-helper.ts` and every other detector are unchanged.
- Every stall-path poll outcome is now legible and log-flood-safe: acted / suppressed-with-a-specific-reason (adopted / rate-capped / already-remediated / stabilizer-not-confirmed-yet / could-not-verify) / attempted-and-failed-with-the-error / not-a-candidate, composing with (not duplicating) the existing `[labels] <key> stalled: ...` line, which now also reports the ticket's actual elapsed stalled-minutes so an operator can tell a 4-minute stall from an all-night one at a glance.
- The three-state "could not verify" result (`stalled.check()`'s `boolean | null`) is threaded through this entire new path uncollapsed: a `null` poll posts nothing and is never recorded as either "confirmed stalled" or "confirmed not stalled". `src/agents/stalled.ts` also grew an `elapsedMinutes(issue)` query (optional on `StalledCheck`, additive, no existing caller affected) so the wake comment can report the ticket's genuine measured idle duration instead of this module's own floor, which — since it acts on the very first eligible poll by design — would otherwise always read as "0 minutes".
