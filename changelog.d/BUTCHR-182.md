bump: minor

### Added
- **Every agent workspace now stamps build identity and currency into the ground-truth block every agent reads at spawn, so a fleet running an old build can say so instead of looking exactly like a current one (BUTCHR-182, implementing BUTCHR-176).** `ENVIRONMENT.md`/`CLAUDE.md`'s `{{GROUND_TRUTH}}` block already told an agent host/port/systemd unit/pid — never which build produced it, or whether that build is current. Concretely, agents had already done wrong work from this gap: BUTCHR-126 and BUTCHR-112 were filed as defects already fixed on `main`; BUTCHR-156 predicted a label wouldn't clear because the fix was merged-but-not-deployed, adopted four tickets anyway, and watched all four keep the label.
- New `src/agents/build-currency.ts` computes a three-state verdict — `current` / `stale`-or-`diverged` / `unknown` — comparing BUTCHR-54's frozen `buildIdentity.sha` (the RUNNING side, never re-read from a working tree near the daemon) against the local `refs/remotes/origin/main` (the BASE side, resolved through git and **never fetched over the network** — this runs on the agent-spawn path, and a network call there can hang a spawn). Comparison is by **tree-object content** (`<sha>^{tree}`), not ancestry: a squash merge makes `git merge-base --is-ancestor` say NO for a PR that landed cleanly, and both merge styles occur in this repo. Ancestry (`git rev-list --count`) is used only as supplementary `commitsBehind`/`commitsAhead` evidence inside an already-`stale` verdict. `commitsAhead > 0` renders as `diverged`, never a lying "behind by N" — a daemon running a non-`main` branch is a real case in this fleet.
- **The sharpest requirement, added after filing by this ticket's boss: a stale local base ref must never compare byte-equal into a false `current`.** If nothing has fetched `origin/main` in a while, a build a hundred commits behind can compare tree-identical to its own stale local ref — this ticket's own bug, one level down, inside its own fix. `current` is therefore gated on the base ref's own freshness (its reflog file's mtime, falling back to the loose ref file's) being determinable at all; an undeterminable freshness renders `unknown`, never `current`. A dirty running tree (`buildIdentity.shaDirty === true`) also forces `unknown` — a dirty sha doesn't truthfully describe what's running.
- **Nothing in the currency path may throw** (it runs on the agent-spawn path — an exception there would stop an agent being staffed at all): every git call is wrapped, time-bounded, and degrades to `unknown` with a reason. Equally, **a failure to compute must render**, not vanish — an omitted currency section reads to a skimming agent exactly like one where everything was fine, the same "confident zero" failure mode this epic exists to stop. Tested directly: every git call failing still produces a rendered `- currency: UNKNOWN — ...` line, never a silently absent section.
- **The rendering speaks in the first person, about the ONE daemon that computed it — never "the fleet", never "the deploy".** Added after filing: this host is confirmed to run more than one butchr daemon, under different Unix users, with different pids and `startedAt` values both correctly reported to their own readers. A currency claim is only ever true for the daemon that made it, and the rendered text says so.
- `groundTruthText` (`src/agents/ground-truth.ts`) grew `build`/`currency` parameters and now splices a `## Build identity & currency` section next to the existing host/port/pid lines, carrying: the sha (short + full), provenance (`baked`/`git-at-start`), dirty flag, and package version; the currency verdict, rendered so `unknown` can never be mistaken for `current` (pinned by a test asserting the literal token `CURRENT` never appears in an `unknown` rendering); the comparison base and its own freshness; and one sentence telling the reader what to do with anything other than `current` — test "this daemon is not running the code that does X" before filing "X does not work" as a bug.
- `src/workspace/registry.ts`'s `GROUND_TRUTH` entry is updated to describe the widened block, including what the new mechanism deliberately does **not** do: the currency verdict is itself a one-time snapshot (nothing rewrites it if the daemon is later redeployed or `origin/main` advances while a spawned agent keeps running), and even a `current` verdict only means "matched the last `main` this daemon's own checkout already had", never "matches `main` right now".
- `scripts/verify-workspace-ground-truth.ts` (manual/operator script, deliberately not wired into `bun run check`) extended to assert the new section against a real run: the section is present, a `current` verdict carries the base's own freshness, an `unknown` verdict's text never also contains a `CURRENT` line, and the section speaks in the first person about "this daemon".

### Scope
- **`/health` is untouched — neither `components` (BUTCHR-164's territory) nor `build`.** The `build` scope-out is a deliberate, approved decision, not an oversight: `buildIdentity`/`toBuildReport` are frozen at process start by design, while currency changes over time — placing a verdict there would either freeze-and-go-stale at the one endpoint meant to be honest, or spawn `git` on every health poll. If a future ticket wants live currency on `/health`, that tradeoff needs revisiting explicitly, not inherited from this one.
- Workspaces already on disk are not repaired retroactively — same reasoning `src/workspace/registry.ts` already documents under "THE RETROACTIVE QUESTION" for `{{PARENT}}`/`{{SUMMARY}}": no bulk-rewrite mechanism exists for files a currently-running agent may be reading, and workspace directories aren't centrally enumerable across hosts. A workspace built before this ships keeps the old, currency-free block for its lifetime.
- The deploy gap itself (nothing merge-triggered restarts `butchr.service`) is not fixed by this ticket — reporting it accurately is the whole increment.
