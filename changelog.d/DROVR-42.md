### Added
- **Managed-session definitions can opt into "lizard mode": `lizardMode: true` runs drovr's unattended permission auto-answer for that agent's pane.** A new standalone daemon timer (every 20s, independent of the Jira reconcile loop and the blocking-escalation watcher) calls `@brooswit/drovr`'s `autoAnswerPermissions` — but only across panes whose managed-session definition set `lizardMode: true`; every other pane (every definition that doesn't set the field, and every non-managed-session agent) is never scanned or touched. Pairing `lizardMode: true` with `permissionMode: "default"` (Claude's manual/ask mode) is the point: prompts still guard every tool call, but the "always allow" stored-rule option is pressed automatically within one tick instead of leaving the agent frozen for hours (the DROVR-37 incident this exists to fix). `lizardMode` is rejected at manifest load for `vendor: "codex"` (drovr's dialog recognition is Claude-specific). Every attempt is recorded to a JSONL audit log under the workspace root (`.permission-audit.jsonl`, `BUTCHR_PERMISSION_AUDIT_PATH` overrides), operator `butchr-daemon`, and answered/failed panes are named in the daemon's own journal by their definition file. See `docs/managed-sessions.md`'s "Lizard mode" section and `docs/permission-answer-loop.md` for the cadence justification and audit-visibility details.
