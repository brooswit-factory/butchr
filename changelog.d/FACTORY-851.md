### Added
- **`Rule.resumeOnRespawn` and `Rule.resumeTokenCutoff`** (epic FACTORY-843, story FACTORY-848): a rule may now declare whether its respawned worker(s) resume their prior Claude session on an unintended stop, and a token-count cutoff above which resume is skipped in favour of a fresh start. Both are optional and additive — a rules file that sets neither loads exactly as before. `resumeOnRespawn` has no tri-state: absence or an explicit `true` both mean "resume on"; only explicit `false` means off. `resumeTokenCutoff` must be a positive integer when set; absent means `DEFAULT_RESUME_TOKEN_CUTOFF` (100,000 tokens) applies. Config only — this PR wires nothing into the spawn/respawn path; that is story FACTORY-850.
- Both fields are now surfaced in the rules API response (`GET /api/rules`, including its committed fixture) and rendered on the dashboard's Rules page as a `resume: on/off (cutoff: ...)` cell, matching how `permissionMode`/`lizardMode` and `account`/`role` are already exposed. Display-only in this slice — not yet editable from `RuleEditDialog.tsx`, same as `account`/`role`.
