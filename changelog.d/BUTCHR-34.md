### Changed
- **Every boss wake-up now states why it fired, not just a `pr:*` transition (BUTCHR-34/BUTCHR-87).** A journal measurement across two sessions found 89.5%–84% of `[notify]` lines carried no reason at all, and zero ever named an `agent:*` turn flip — the single most common wake in the fleet. `NotifyReason` (`src/resources/types.ts`) widens from a one-member `{ pr }` union to also cover a resource appearing or disappearing, a status transition, a daemon-owned label transition (`agent:*`/`pr:*`, naming which namespace and its from/to values — see `daemonLabelTransition`, `src/jira-watch/diff.ts`), a summary edit, and a comment observed via the suppression stack's already-fetched comment cursor. `createIssueEventRules`'s `decide()` (`src/resources/issue.ts`) applies a deterministic precedence when more than one class is true of the same diff: the existing self-path `pr:*` exemption first (unchanged, before suppression), then appear/disappear, then — once a delivery clears the (unmodified) suppression stack — a delivery caused by an observed comment, then status, then daemon label (`pr:*` over `agent:*` when both changed), then summary. No new per-poll Jira calls: the comment class is named only where the suppression stack already learned the newest comment id moved while deciding whether to suppress.
- New `src/agents/change-nudge.ts` renders the agent-facing nudge (`changeNudge`) and the operator-facing `[notify]` log tag (`notifyReasonTag`) for every reason class except `pr:*`, which keeps its existing dedicated rendering (`prReviewStateNudge`, untouched) so the deployed merge-check guard (`test/unit/merge-check-guard.test.ts`) stays intact. A delivery the taxonomy genuinely cannot explain — every field identical but `updated` itself — renders as `updated (reason not determinable from the poll)` / ` (reason: not determinable)` rather than a bare, ambiguous "was updated": that phrasing is now distinguishable from "nobody wired this class up", per the epic's own ruling on this ticket.

Deploy impact: none beyond the usual pull + restart — the daemons run `bun run src/daemon/index.ts` straight from the checkout, so there is no separate build step to schedule.
