### Fixed
- **The BUTCHR-282 implausible-zero admission guard no longer false-triggers on a worker→sentinel reclassification (BUTCHR-449, BUTCHR-422 follow-up).** `roleOf` fails safe to `"worker"` for a ticket whose type hasn't resolved yet, so an early admission poll could trust a ticket as a worker before its `issueMeta` fill completed; once it resolved to `"sentinel"`, worker residency legitimately dropped, but the guard couldn't tell that from a real census miss and withheld every worker candidate for up to `MAX_IMPLAUSIBLE_POLLS` polls. The guard now tracks the last-trusted set of worker ids alongside the count, and treats an id from that set as explaining its own share of the drop when it is still resident but currently reads as a sentinel — the same way a stopping worker already explains a drop from stops. A genuine census miss (a resident vanishes, or an unrelated resident sentinel that was never a trusted worker) still withholds exactly as before.
