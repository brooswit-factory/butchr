### Added
- **`atRest` (BUTCHR-66/83) is now bounded in time, and a frozen resource speaks before it is reaped (BUTCHR-95/123).** `atRest` exists to protect a genuine, millisecond-scale race — a woken agent's last two acts are advance-watermark then exit, and a poll landing between those two acts must not stop it. It had no time bound at all, so an agent that advanced its watermark and then never exited (crashed, hung, OOM-killed) was protected from cleanup and repair *indefinitely*, and looked exactly like a healthy sleeping resource from the outside. `reconcileNow`'s new optional `checkFrozenAsleep` hook (`ReconcileOptions`, `src/daemon/loop.ts`) is given the ids that are both `atRest` and currently running, and — via the new `src/agents/frozen-asleep.ts` detector, wired for the project tier (the only resource type that can ever sleep today) — posts an audible, rate-capped, dedupe-by-adoption complaint on the resource's own channel (a project's Confluence root doc, via the existing `speakOnOwnChannel` seam) once a resource has read asleep-with-a-running-agent continuously for `BUTCHR_ATREST_MINUTES` (default 10). Only once that complaint has posted or been adopted does the id lose `atRest` protection and fall into `stop` — never `respawn`, which stays correctly unreachable for an asleep resource by construction. Speaking always precedes reaping; a resource still inside the bound is left alone in both directions, exactly as before.
