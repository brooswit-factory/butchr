### Fixed
- **The credential-death alert's close condition no longer gets stuck open forever after a genuine recovery, and no longer closes a live alert on a stray unrelated pane (FACTORY-363/FACTORY-399, FACTORY-357 changes-requested on PR #529).** `onLoginExpiredResolved` (`src/agents/login-expired-alert.ts`) previously closed the host-wide episode on `panes.size === 0` alone. That is wrong in both directions: if the LAST pane to leave the tracked set departed via `"pane-gone"` (not `"recovered"`) after an earlier pane genuinely recovered, nothing ever re-checked the close condition again and the alert stayed open forever with an empty `paneIds`. And once an episode's set emptied out via `"pane-gone"` departures alone (the deliberate "stays open" case), a stray `"recovered"` for some OTHER paneId this tracker never tracked was a no-op on the set but still satisfied `size === 0`, incorrectly clearing a live alert. The tracker now closes only when the set is empty AND some pane that was ACTUALLY a member of the set resolved with `reason: "recovered"` — a `"recovered"` for an untracked paneId contributes no evidence, exactly like the existing unknown-pane no-op elsewhere in this module. The deliberate invariant that an episode whose every pane departs via `"pane-gone"` alone (no `"recovered"` anywhere) never self-clears is preserved and now has its own explicit test.
