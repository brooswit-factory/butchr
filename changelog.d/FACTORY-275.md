### Added
- **`permissionMode` now also accepts `"manual"`, an alias for `"default"` (FACTORY-275).** Both `SESSION_PERMISSION_MODES` (managed-session definitions) and `RULE_PERMISSION_MODES` (rules) gained `"manual"` alongside the existing `"default"` — verified live against `claude` 2.1.251/2.1.283 that `default` is the launcher's real canonical value and `manual` is its own `--help`-advertised alias for the identical thing (real `-p` invocations reach argv validation; `--version`/`--help` do not and cannot answer this). Both spellings are forwarded to the launcher verbatim, with no normalization between them. Every existing definition or rule that already says `"default"` (or any other existing value, `"bypassPermissions"` included) keeps loading and launching byte-for-byte identically — no manifest edit required; covered by the existing generic per-union-member tests in `test/unit/argv.test.ts`/`test/unit/session-definition.test.ts`/`test/unit/rules.test.ts`, which now also exercise `"manual"`. `"auto"` is unchanged and keeps its one existing meaning throughout code, docs and CLI help text; this ticket does not touch the separate, pre-existing unconditional `permissionMode: "auto"` for `jira-project` agents (`agentLaunchConfig`, src/agents/argv.ts — owned by a different ticket).

### Fixed
- **Docs no longer claim `"auto"` and `"bypassPermissions"` are an equivalent no-prompt pair.** The installed `claude` binary's own option help describes them as genuinely different: `"auto"` runs a model classifier over each permission prompt (a real judgment that can still deny), while `"bypassPermissions"` skips every check unconditionally. `docs/managed-sessions.md`'s Lizard mode section and `docs/execution-modes.md`'s `permissionMode`/`lizardMode` table are corrected; `docs/execution-modes.md`'s stale claim that an absent `permissionMode` still falls back to Drovr's own `bypassPermissions` default (superseded by FACTORY-127/138's `acceptEdits` default) is also fixed. `"bypassPermissions"` gets a friendlier operator-facing name in prose, **"unattended mode"** — the wire value, validation, and every existing manifest are unchanged; butchr's web config page still renders `permissionMode` as read-only text with no dropdown to relabel (verified at this commit).
