### Fixed

- **A rule whose covering admission source is entirely ABSENT from the census (not merely declined or never-reported) still read `UNSTAFFED: no matching resources this poll` instead of `COULD NOT CHECK` (FACTORY-340, closing an epic-reviewer finding on FACTORY-136/FACTORY-323).** `admissionSourceCensusFor` (`src/agents/query-agent-inventory.ts`) returned `undefined` whenever the rule's own covering source had no entry at all in `admission.sources[]`, and `ruleStaffingReason` treated that the same as "reported and fine" — on the theory that a rule's own provider is always why its source is declared. That theory was false for `github-pr`: `src/daemon/index.ts` omits `ADMISSION_SOURCE_GITHUB_PR` from its conditional `sources:` list whenever `config.github` is unset, even with an enabled `github-pr` rule present, so a `github-pr` rule with no GitHub config fell through to a genuine-zero reading in exactly the state where a withholding could not be ruled out — a real, reachable case named in epic FACTORY-68's own acceptance criteria ("GitHub rules without a token").
- `admissionSourceCensusFor` now returns `{ source, absent: true }` instead of `undefined` in that case, and `ruleStaffingReason` reports the same `staffed: null` tri-state FACTORY-132/FACTORY-136 already established for a declared-but-unchecked source, worded to say the source is "not present in this poll's admission census" — closing the gap for any current or future provider, not just `github-pr`.
- `configReasonFor` (`src/daemon/index.ts`) now also covers `github-pr`, mirroring the existing `github-issue`/`zendesk-ticket` lines with `githubPrStaffingResult`'s own reason. Because this check runs before the admission-source-absent branch above, a `github-pr` rule with no GitHub config now reads the specific, accurate `UNSTAFFED: github-pr rules not staffed (<ids>): set GITHUB_TOKEN_FILE and BUTCHR_GITHUB_ORGS` — consistent with how `github-issue`/`zendesk-ticket` have always surfaced their own config problems — rather than either the old misleading zero or a generic COULD NOT CHECK naming no cause.
