### Fixed
- **The "no assertion weakened" review recipe in every brief's "Evidence and review" section was vacuous on repos it doesn't describe, in multiple independent ways.** The original command, `git diff <base>...<head> -- test/ | grep '^-.*expect(' || true`, hardcoded `expect(` as the assertion syntax — a `node:assert`-based suite (`assert.equal`/`assert.ok`, no `expect(` anywhere) matches nothing on every diff and reads as "clean" no matter what was deleted, identical output to a genuinely clean diff. It also hardcoded `-- test/` as the only place tests live, silently excluding colocated test files. Found reviewing agentcost-capture's collector tests under FACTORY-822/FACTORY-819.
- A first fix (widen the pathspec to `test/ tests/ '*.test.*' '**/__tests__/**'`, drop the library-specific pattern) was itself found on review (PR #792) to still miss a mixed `.test.ts`/`.spec.ts` suite — reproduced with a fixture where a real removed `assert.equal(...)` line in an unmatched `.spec.ts` file stays invisible because an adjacent, untouched `.test.ts` file satisfies the pathspec. No test-file naming enumeration is safe to assume.
- Final fix drops the pathspec entirely: `git diff <base>...<head> | grep -E '^-[^-]' || true`, applied in `briefs/task.md`, `briefs/story.md`, `briefs/epic.md`, `briefs/bug.md`, `briefs/default.md`, `briefs/project.md`, and `docs/expect-tally-non-determinism.md`. A pathspec can miss a file; running over the whole diff can't.
- `test/unit/assertion-check-guard.test.ts`'s `SAFE_COMMAND` updated to match, plus new behavioral fixtures that run the real command through a real `git diff` against scratch-repo commits (mixed `.test.ts`/`.spec.ts` naming, a no-op diff, and a conventional `test/`-style removal) rather than only pinning the command's literal text.
