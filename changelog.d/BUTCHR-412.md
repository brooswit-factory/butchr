### Added

- **`Rule.account` is now real at runtime, for every execution mode alike (BUTCHR-412).** `ensureAccount`/`releaseAccount` (BUTCHR-410's Rocket.Chat account manager) are wired into `reconcileNow`'s own spawn/stop/respawn — `src/agents/account-lifecycle.ts`, one shared instance across every rule loop (jira-work, github-issue, jira-idea, zendesk-ticket). `temporary` accounts are provisioned on spawn and unprovisioned on every genuine stop path (rule disabled, a singleton dropping to zero matches, a persistent rule's freeze, a `stand_down`/`check_in` exit, a done ticket leaving the query, and a reaper-detected self-exit — crash, `/exit`, quota); `permanent` accounts are provisioned and retained across all of those, plus restart and BUTCHR-394's future archive/restore. A respawn (stale argv) or a daemon restart never unprovisions — the same agent identity is coming back, not stopping, and `ensureAccount`'s own token-rotation contract (every call reissues the account's managed token) means a respawn always gets fresh connection material rather than reusing a stale one.
- **Connection material reaches the agent via a dedicated 0600 file, never argv/mcp.json/a log line.** `buildWorkspace` writes `.butchr-rocketchat.json` (`{ url, userId, authToken, username }`) inside the agent's own workspace directory when its rule's account was provisioned this launch, and removes it when not (a policy change back to `"none"`, or a refused launch) rather than leaving a prior launch's token looking current.
- **A Rocket.Chat account refusal (no RC configured, the 50-user guardrail, a non-managed username collision) withholds the agent's spawn rather than starting it without the account its rule requires** — logged loudly, and posted as a ticket comment for jira-work/jira-idea agents (reusing the same audible-failure plumbing `checkReconcileFailure` already has).
- A small periodic sweep (startup, then every 30 minutes) releases any Rocket.Chat account whose agent has genuinely stopped existing with no reaper run in between — the backstop for daemon shutdown, which has no stop handler at all and so releases nothing itself (agents keep running under herdr regardless of the daemon process's own lifetime).
- `docs/rocketchat-accounts.md` ("Wiring") and `docs/execution-modes.md` updated: the lifecycle is wired in, no longer a follow-up.
