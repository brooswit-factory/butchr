### Added

- **`Rule.account` is now real at runtime, for every execution mode alike (BUTCHR-412).** `ensureAccount`/`releaseAccount` (BUTCHR-410's Rocket.Chat account manager) are wired into `reconcileNow`'s own spawn/stop/respawn — `src/agents/account-lifecycle.ts`, one shared instance across every rule loop (jira-work, github-issue, jira-idea, zendesk-ticket). `temporary` accounts are provisioned on spawn and unprovisioned on every genuine stop path (rule disabled, a singleton dropping to zero matches, a persistent rule's freeze, a `stand_down`/`check_in` exit, a done ticket leaving the query, and a reaper-detected self-exit — crash, `/exit`, quota); `permanent` accounts are provisioned and retained across all of those, plus restart and BUTCHR-394's future archive/restore. A respawn (stale argv) or a daemon restart never unprovisions — the same agent identity is coming back, not stopping.
- **Corrected credential design (BUTCHR-391 design correction, superseding this ticket's own first round): an agent never holds a Rocket.Chat credential.** `rocketr` is Nexus's central bridge, holding every token; an agent's MCP binding names only its own account, non-secret, in a header (`x-rocketr-account` by convention) — `McpServerBinding.accountHeader` (`src/rules/rules.ts`) is the small, explicit extension to BUTCHR-411's `Rule.mcpServers` this needed (a per-AGENT literal, alongside `headersEnvVar`'s per-RULE, env-resolved value), resolved at launch time from the new `SpawnSpec.rocketchatAccount` (`resolveAccountHeader`, `src/agents/workspace.ts`). The earlier per-agent `.butchr-rocketchat.json` credential file is REMOVED outright — nothing in this codebase writes, chmods, or reads it any more, and no token value ever reaches an agent's workspace, argv, mcp.json, or logs.
- **Butchr mints the token and hands Nexus a file, never a value.** `ensureAccount` writes each managed token to a 0600 file in a configurable, daemon-owned directory (`AccountManagerDeps.tokenDir`, `ROCKETCHAT_TOKEN_DIR`) and `AccountManager.manifestEntries()` lists every `{ account, tokenFile }` pair on record; `src/agents/account-lifecycle.ts`'s `publishBatch()` writes those to a batched, 0600 Nexus hand-off manifest (`src/accounts/nexus-manifest.ts`, `ROCKETCHAT_NEXUS_MANIFEST_FILE`) that Nexus reads to register each account with rocketr.
- **Token rotation, fixed to not fight Nexus's own registration.** The original contract (every `ensureAccount` call revokes-then-reissues the token) would silently invalidate a token Nexus already registered with rocketr on any routine re-ensure (a respawn, a permanent account's adopt-on-every-start, a daemon restart). `ensureAccount` now reuses an existing, still-valid recorded token file untouched (no RC token API call at all — only a read-only liveness check, preserving stale-record recovery) and mints fresh only when there is none, or it's missing/invalid.
- **Batch provisioning.** Each rocketr registration reconnects the whole fleet, so the Nexus manifest is published AT MOST ONCE per reconcile poll (`reconcileNow`'s new end-of-poll `publishBatch()` call), covering every account this poll actually minted or released — never once per agent start, and never at all when nothing changed. The periodic orphan sweep (below) flushes the same shared batch after its own round.
- **A configurable cap on concurrently-existing TEMPORARY accounts**, separate from the existing 50-user RC-wide guardrail (`ROCKETCHAT_TEMPORARY_CAP_THRESHOLD`, default 8 — about 10 of RC's 50 seats are free, shared with test accounts). Reached: withhold + log why + retry next poll, same discipline as the RC-wide cap; a `permanent` account is never refused for this reason and never counts toward it.
- **The managed username prefix is now configurable** (`ROCKETCHAT_MANAGED_PREFIX`, default unchanged) — the actual naming convention is Nexus's to agree on; this ships the knob.
- **A Rocket.Chat account refusal (no RC configured, either cap, a non-managed username collision) withholds the agent's spawn rather than starting it without the account its rule requires** — logged loudly, and posted as a ticket comment for jira-work/jira-idea agents (reusing the same audible-failure plumbing `checkReconcileFailure` already has).
- A failed release (e.g. a transient Rocket.Chat outage right after a successful `herd.stop`) is queued in-memory and retried every poll, independent of `plan.stop` — the id is no longer running by then, so it could never land in a future `plan.stop` on its own; `ensure` cancels a queued release for the same id if the agent is spawned again before the retry lands.
- A safe periodic sweep (`src/agents/account-orphan-sweep.ts`; startup, then every 30 minutes) is the crash-safe backstop for the same failure mode across a daemon restart, and for daemon shutdown itself (which has no stop handler at all — agents keep running under herdr regardless of the daemon process's own lifetime). Uses a real per-pane liveness check (`HerdrHerd.residentIssues()`, immune to the ambiguous-pane/respawn-overlap false positives a raw `runningIssues()` snapshot has) plus a minimum record age and a two-consecutive-sweep grace before ever releasing anything.
- `docs/rocketchat-accounts.md`, `docs/execution-modes.md` and `docs/mcp-server-bindings.md` updated for the corrected design.
