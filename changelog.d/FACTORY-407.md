### Fixed
- **A rule with a live agent read UNSTAFFED on `/configurations` and `/config-inventory` on every real daemon, because `AgentDashboardRow.resourceKey` was a bare provider-native resource id, not the full agent key `decodeAnyAgentKey` needs (FACTORY-406/FACTORY-407).** `src/daemon/index.ts` fed `buildDashboardRows` the value of `resourceOfCwd(a.cwd)`, which deliberately discards `resourceProvider`/`ruleId` down to the bare resource id — correct for the label-sync status map that also reads it, but the wrong shape for the correlation `query-agent-inventory.ts`'s `live`/`withheld` sets and `config-inventory-links.ts`'s cross-links were already written to decode. A bare id never decodes (`src/rules/agent-key.ts`'s own header), so `live`/`withheld` were always empty and no rule could ever reach `staffed: true`; the existing test suite stayed green because its fixtures hand-built rows with the correct (full) shape directly, a shape the daemon itself never actually produced.
- Fixed by giving `DashboardAgent` a second field, `agent_key` — the full owned key, undiscarded — which `buildDashboardRows` now uses to build `AgentDashboardRow.resourceKey`; the pre-existing bare `resource_key` is untouched and still feeds the label-sync status map. `buildTier` decodes the (now full) key internally wherever it still needs the bare provider-native id. The admission census's own withheld-key shape needed no change — `admissionController.admit()`'s candidates were already the same full `unitAgentKey` shape a real rule loop spawns under — so this also fixes the "agent wins" row-precedence check in `updateWithheldRows`, which previously compared a withheld row's full key against agent rows' bare keys and could never match.
- A `swarm` rule's per-resource agent correlates to its own rule via the `ruleId` already embedded in its own agent key — never by re-matching the bare resource id, which would be genuinely ambiguous when several rules match one resource. No guessing: each rule's own agent is attributed by its own key, unconditionally.
- Tests: `buildDashboardRows`/`createDashboardFeed`/`buildQueryAgentInventory` now have coverage driven through the REAL `DashboardAgent` → `buildDashboardRows` path (the specific gap that let this ship), including a matched-but-withheld resource reaching `staffed: false` via the real `createAdmissionController`, and two distinct swarm rules matching the same resource each staffed correctly by their own agent.
