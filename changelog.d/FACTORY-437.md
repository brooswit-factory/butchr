### Changed
- **A top-level Bug's `new_worker` now spawns an Epic, not a Story (FACTORY-437).** This instance's native Jira `parent` field is structurally Epic-only-as-parent — setting a Story's `parent` to a Bug, or a Task's to a Story, both fail live with "Given parent work item does not belong to appropriate hierarchy." Under the old Bug -> Story -> Task convention, nothing in a Bug's whole fix chain could ever carry a native `parent`, only butchr's own Implements link. Routing a Bug's fix through an Epic first means the Epic's own Stories/Tasks can now carry a real native `parent` set to the Epic, closing that gap for the whole tree at once.
- `src/tools/relationship.ts`'s `CHILD_TYPE` table changes its `Bug` row from `"Story"` to `"Epic"`; `newWorker`'s assignee-inference branch now staffs a Bug's Epic child from `roles.epic` (`BUTCHR_ASSIGNEE_EPIC`), the same role `newProjectWorker` already uses to staff a project-created Epic, instead of misrouting through the Story/Task role branches.
- `briefs/bug.md` is rewritten to describe filing and reviewing Epics instead of Stories throughout, including that an Epic — unlike the old Story child — usually has no PR of its own for a Bug to formally review; the `[review]` line instruction is now conditional on a review genuinely involving a PR of the Epic's own, mirroring `briefs/project.md`'s own Epic-reviewing language.
- Bug's top-level (bossless) triage-root status, and Epic -> Story / Story -> Task inference, are unchanged. Existing in-flight Bug -> Story chains are not retroactively converted.
