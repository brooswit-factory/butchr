### Added
- **`set_doc`/`set_project_doc` now refuse a write that is both over a 50,000-character budget AND larger than what is currently stored (BUTCHR-250).** Guards the only place a doc's size can grow, on both write-path callers (a ticket's own doc and a project's root doc), so a monotonically-growing shared page like a project root doc can no longer silently outgrow the MCP result cap `docs/tool-result-size-cap.md` measured. The refusal names the current stored size, the proposed size, the budget, and the remedy (a linked child page under the root doc's index). Deliberately **not** a plain ceiling: a page already over budget can still be corrected, compacted, or shrunk — an estimated-post-storage `proposed` no larger than `stored` is always allowed regardless of budget — so an oversized page is never bricked, only prevented from growing further. Both comparisons run against `estimateStoredLength(proposed)`, not a bare `proposed.length`: Confluence's storage layer re-encodes a character into a longer named XML entity if and only if that character has a standard HTML 4 named character reference — measured with a 37-character live probe with zero exceptions either direction — and comparing raw lengths against an already-post-transform `stored` was measurably unsound in the permissive direction (a write that swapped stored entities for their shorter literal form could score as a shrink while the stored page did not shrink at all). `estimateStoredLength` now applies the complete, 252-entry HTML 4.01 named-entity table, vendored from the W3C spec itself (`scripts/vendor/html4-entities.ts`, not hand-typed) via `src/tools/html4-named-entities.generated.ts`, making it an exact model of the measured transform rather than an approximation. Verified not to be BUTCHR-specific: the guard is a pure size predicate taking no project key, and `test/unit/docs.test.ts` exercises it against non-BUTCHR project keys, plus a regression arm using real non-ASCII characters that fails against the pre-fix raw comparison; `test/unit/html4-named-entities.test.ts` pins the vendored table's exact size and representative rows. See `docs/root-doc-write-budget.md` for the budget's derivation method, the read/write-path argument, the per-ticket-vs-root-doc scope decision, the entity-encoding finding, and a blast-radius table measured across every project this bound protects.
