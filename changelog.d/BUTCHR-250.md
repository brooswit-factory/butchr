### Added
- **`set_doc`/`set_project_doc` now refuse a write that is both over a 50,000-character budget AND larger than what is currently stored (BUTCHR-250).** Guards the only place a doc's size can grow, on both write-path callers (a ticket's own doc and a project's root doc), so a monotonically-growing shared page like a project root doc can no longer silently outgrow the MCP result cap `docs/tool-result-size-cap.md` measured. The refusal names the current stored size, the proposed size, the budget, and the remedy (a linked child page under the root doc's index). Deliberately **not** a plain ceiling: a page already over budget can still be corrected, compacted, or shrunk — an estimated-post-storage `proposed` no larger than `stored` is always allowed regardless of budget — so an oversized page is never bricked, only prevented from growing further. Both comparisons run against `estimateStoredLength(proposed)`, not a bare `proposed.length`: Confluence's storage layer re-encodes a character into a longer named XML entity if and only if that character has a standard HTML 4 named character reference — measured with a 37-character live probe with zero exceptions either direction — and comparing raw lengths against an already-post-transform `stored` was measurably unsound in the permissive direction (a write that swapped stored entities for their shorter literal form could score as a shrink while the stored page did not shrink at all). `estimateStoredLength` applies a vendored HTML 4.01 named-entity table (`scripts/vendor/html4-entities.ts` fetches and parses the W3C spec itself, not hand-typed, via `src/tools/html4-named-entities.generated.ts`) — 248 of the spec's 252 entries, deliberately EXCLUDING `quot`/`amp`/`lt`/`gt` (`"`/`&`/`<`/`>`): those four are Confluence's own storage-format markup syntax (tag brackets, attribute quotes, an entity's own leading `&`), not content the storage layer re-encodes, and including them (an earlier round of this fix did) inflated realistic storage-markup bodies by ~12–14% and caused false refusals of genuinely under-budget writes — the opposite failure direction from the one this bound exists to prevent. With the exclusion, `estimateStoredLength` is an exact model of the measured transform, not an approximation. Verified not to be BUTCHR-specific: the guard is a pure size predicate taking no project key, and `test/unit/docs.test.ts` exercises it against non-BUTCHR project keys, plus regression arms using real non-ASCII characters and realistic storage markup (a `<p>` tag, a quoted `href`, an already-present entity) that each fail against their respective pre-fix code and pass against this fix; `test/unit/html4-named-entities.test.ts` pins the vendored table's exact size (248), representative rows, and the four deliberately-excluded codepoints. See `docs/root-doc-write-budget.md` for the budget's derivation method, the read/write-path argument, the per-ticket-vs-root-doc scope decision, the entity-encoding finding, and a blast-radius table measured across every project this bound protects.
