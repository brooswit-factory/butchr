### Added
- **`set_doc`/`set_project_doc` now refuse a write that is both over a 50,000-character budget AND larger than what is currently stored (BUTCHR-250).** Guards the only place a doc's size can grow, on both write-path callers (a ticket's own doc and a project's root doc), so a monotonically-growing shared page like a project root doc can no longer silently outgrow the MCP result cap `docs/tool-result-size-cap.md` measured. The refusal names the current stored size, the proposed size, the budget, and the remedy (a linked child page under the root doc's index). Deliberately **not** a plain ceiling: a page already over budget can still be corrected, compacted, or shrunk — `proposed.length <= stored.length` is always allowed regardless of budget — so an oversized page is never bricked, only prevented from growing further. Verified not to be BUTCHR-specific: the guard is a pure size predicate taking no project key, and `test/unit/docs.test.ts` exercises it against non-BUTCHR project keys. See `docs/root-doc-write-budget.md` for the budget's derivation method, the read/write-path argument, the per-ticket-vs-root-doc scope decision, and a blast-radius table measured across every project this bound protects.
