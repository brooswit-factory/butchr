### Added
- **`scripts/audit-alias-calls.ts` — one identity can now answer whether any agent called a deprecated alias, and whether that call was drift or sanctioned use.** The alias-removal condition ("the audit log shows zero alias calls across a full fleet lifetime after that respawn") was previously unevaluable: every tool call is audited into the journal of the daemon that served it, different tiers run on daemons owned by different Unix users, and a journal you lack permission for returns *empty*, not an error — so an observer who greps, gets zero, and declares the condition met has measured nothing while concluding exactly what they hoped. The command discovers every butchr daemon identity via `ss -ltne` (`uid:`/`cgroup:` for every listening socket, including one owned by another Unix user whose process an unprivileged `ss -ltnp` shows with no process at all — never by process visibility, never by a hardcoded port), confirms each with a live `/health` round trip, and reuses `parseCgroup` (`src/agents/ground-truth.ts`) unchanged rather than adding a second parser. A `/health`-confirmed daemon-shaped listener under some other unit name is printed as an explicit `SKIPPED CANDIDATE` naming its unit rather than silently dropped. Readability is decided by positive evidence only — a `/health`-confirmed-live daemon returning zero lines is proof the *read* failed, not proof the daemon was quiet — so "read it, found nothing" and "could not read it" never share a zero. `computeVerdict` checks unreadable identities first and short-circuits, making `CONDITION_MET` structurally unreachable while any discovered identity is unread; exit codes `0`/`1`/`2` carry met / not-met / inconclusive. An operator command, deliberately outside `bun run check` (the `scripts/verify-*.ts` precedent), since it needs a real systemd unit and a real journal to prove anything (BUTCHR-49).

### Changed
- **A deprecated alias's audit line now says whether the call indicates drift or is sanctioned permanent use.** Previously `jira_link_issues` stamped *every* call `[deprecated alias; …]`, including a non-Implements link its own description calls "still the only way" to make — so even a perfectly aggregated log would have overcounted and never honestly reached zero. Every alias audit line now ends with a machine-readable `[alias tool=<name> class=drift|sanctioned|ambiguous]` (`src/tools/alias-audit.ts`), with the rule documented tool by tool beside the code. `ambiguous` is a deliberate third value, not a hedge: `adopt_worker`'s own refusal tells a boss to reach for `jira_link_issues` to steal a worker deliberately, and that blessed call is an *Implements* link — the same shape as habitual drift, indistinguishable from `{from, to, type}` alone. `jira_assign` and the three `confluence_*` aliases are ambiguous for the same reason, each keeping one blessed permanent use their arguments cannot separate from drift. An honest third value beats a confident wrong one — the classification-side twin of refusing to read an empty journal as a quiet one. `jira_transition` and `jira_set_priority` are always drift; `jira_create_issue` is sanctioned for an Epic or a deliberate orphan and drift otherwise; `jira_get_issue` and `jira_search` stay unmarked, being permanent lookups on no removal clock. Only drift (and unknown) block the removal condition — sanctioned and ambiguous never do (BUTCHR-49).
- **Old-format alias lines are counted as `unknown`, never dropped.** Merging does not restart anything, so running daemons keep emitting the previous unclassified format until they are restarted. A pre-existing `[deprecated alias;` line is a real alias call whose classification cannot be recovered, so it is counted and labelled `unknown` — silently dropping it would be the same lie as a silent zero, by a different door — and `unknown` blocks a pass exactly as drift does (BUTCHR-49).
