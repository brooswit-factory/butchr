### Added
- **`/` now serves a real, honest dashboard page instead of the old `/state`-polling template (BUTCHR-339).** One row per agent this daemon runs, plus one row per ticket the fleet-wide admission cap is currently withholding, rendered by a pure, synchronous, server-side `renderDashboard` function (`src/web/dashboard-page.ts`) driven directly off the real `/dashboard` response (`src/agents/dashboard.ts`) — no client-side rendering logic left to go untested. Every row carries its own freshness; a whole-page could-not-check (a failed `agent.list()` read) renders a loud, unmissable banner rather than a calm empty page; a row's could-not-check `issuetype` is styled distinctly from a withheld row's structurally not-applicable `pane`/`agentStatus`, even on the same row; the time-in-status floor is the most visually prominent value on the page and is marked "since daemon start" whenever it is only a lower bound (`exact: false`); each admission census source's state is shown on its own, never smeared onto another source. The header shows this daemon's own build sha and, when present, its build-currency verdict (never turning the page red on its own — being behind `main` can be deliberate).
- **New `GET /resource/:key/open` redirect route.** Resolves a dashboard row's resource key to its correct external target — the Jira issue for an issue key, the project's Confluence root doc for a project id — and 302s there, only when a human actually clicks (never on `/dashboard`'s or `/`'s own request path, which still do no I/O). The resolution itself is a small, directly-tested pure function, `resolveResourceLink` (`src/resources/resource-link.ts`); an unresolvable key (or a project whose root doc can't be read) is refused with a specific, human-readable reason in plain text, never a blank page or a silent failure — the same honesty bar the existing `/agents/pane/:pane/attach` terminal-attach route already holds itself to.
- `src/web/page.ts` (the old client-rendered live view) is removed; nothing else referenced it.
