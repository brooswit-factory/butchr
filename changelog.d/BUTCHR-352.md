### Added
- **`check_worker` gains a fourth staffing verdict, `"withheld"` — admission control is holding this worker at the fleet-wide agent cap, correctly, and will admit it when a slot frees (BUTCHR-352).** Previously a ticket withheld at capacity was indistinguishable from one about to be spawned or silently never spawned at all — all three read as `"not-staffed"`, and only the daemon journal (which no boss reads) separated them. The information already existed: admission control's own census already computes it every poll.
- **Carried on a NEW, SEPARATE `admission:withheld` label — deliberately NOT a new `agent:*` value.** The fleet's daemons deploy independently, so a new-build daemon can write a new state while an old-build `checkWorker` is still reading it; a new `agent:*` value would map to a confident, wrong `"staffed"` on every not-yet-upgraded reader (any label other than `agent:none` already reads as running). A wholly separate, non-`agent:`-prefixed marker is structurally invisible to that same old code, so an unupgraded reader instead degrades to today's honest, incomplete `"not-staffed"` — never a confident wrong answer. `admission:withheld` is layered ALONGSIDE `agent:none`, never in place of it, and never alongside any other `agent:*` value.
- **Cross-daemon-correct by construction, the same way `agent:*` labels already are**: written by whichever daemon's admission census actually staffs the worker, read by any caller regardless of which daemon it talks to. A caller whose own herd probe cannot see the worker (`probeOutOfScope: true`) still gets the right answer from the label.
- **Never a guess**: only ever written from a TRUSTED (`checked: true`) admission census read. A poll where the census could not check (`checked: false` — residency threw, an untrusted implausible zero, or the tier has never reported) re-emits whatever `admission:withheld` marker the ticket already carries instead of flipping it off from an observation never made (the same sticky-but-falsifiable pattern `prState: "unknown"` already uses, KAN-832/837) — bounding a withheld episode to exactly two label writes (on, then off) regardless of how many declined polls fall in between.
- The same-daemon herd-probe path is covered too: a `probed === false` result no longer short-circuits straight to `"not-staffed"` without checking for a withheld marker — the worker-withheld-on-the-caller's-own-daemon case that looked easy but silently kept the old wrong answer.
- New `admission:` label namespace (`src/labels/plan.ts`), with its own compile-time completeness door (`AdmissionLabel`/`ALL_ADMISSION_LABELS`) mirroring `AgentLabel`'s. Recognized by `isDaemonLabel` (so the sync loop can add/remove it) and by a new `isActiveStatusLabel` predicate shared between `src/labels/sync.ts`'s disappearance-cleanup pass and `src/labels/sweep.ts`'s startup sweep, so `admission:withheld` is cleared/swept exactly when `agent:*` is — never left stranded on a ticket that goes inactive while the daemon staffing it is down.

### Known limitation
- An unupgraded (old-build) daemon's own notify/wake gate is not label-namespace-aware, so a caller running old code gets an extra wake nudge on each withheld transition (on, and off) that new code would otherwise suppress as daemon-only bookkeeping. This is a deliberate, accepted trade — a noisy nudge, never a confident wrong answer — and only affects a daemon that has not yet picked up this change.
