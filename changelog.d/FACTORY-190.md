### BREAKING
- **`BUTCHR_PARKED_MINUTES` is removed (FACTORY-190).** It configured the parked-ticket escalation detector's threshold, and that detector is removed in the same change — see the Removed entry below for why. A daemon whose environment still sets this variable does not fail to start; the variable is simply never read, exactly like any other unrecognized environment variable. If you previously set it, remove it — it does nothing.

### Removed
- **The dormant parked-ticket escalation detector (BUTCHR-24) is retired.** `src/agents/parked.ts`, its `checkParked` hook on `LoopDeps`/`GenericLoopDeps` (`src/daemon/loop.ts`), its daemon wiring (`src/daemon/index.ts`), the `parkedMinutes` config field (`src/config/config.ts`, `src/web/settings-api.ts`, `.env.example`), and `test/unit/parked.test.ts` are deleted outright. Re-verified before removal: the sole production call site (`src/daemon/index.ts`) always passed `related=[]` into `parkedDetector.check`, and `parkedCandidates` derives its candidates exclusively from `related` — so the detector could never actually produce a candidate or post an escalation comment on any deployed daemon. This is a removal of dead wiring, not a behavior change for any running fleet.
- **`butchr:shelved` (`EXEMPT_LABEL`) moves to `src/labels/plan.ts`**, a neutral shared module, ahead of `parked.ts`'s deletion. Its exact value, semantics, and every real consumer — `src/agents/stop-cause.ts`, `src/labels/registry.ts`, `src/tools/relationship.ts`, and their regression tests — are unchanged; only the import path moves.
- `src/agents/escalation-helper.ts` (the generic dedupe/rate-cap primitives `parked.ts` and several other detectors share) is untouched — this is not a general escalation rewrite.
- `test/unit/abandoned.test.ts`'s `parkedCandidates` import and its cross-detector "parked/abandoned mutually exclusive" proof are removed; `abandonedCandidates`'s own coverage (already asserting the same live-boss/Done-boss cases independently) is untouched. `test/unit/loop.test.ts`'s fetch-stage wiring regression coverage (runs every poll regardless of hash change; a detector rejection is caught and never surfaces as `onError`) is retargeted from `checkParked` onto the surviving `checkAbandoned` hook, which shares the identical mechanism, rather than being dropped.
- Doc/comment/tool-wording references that attributed `butchr:shelved`'s semantics or described current wiring in terms of the retired detector (`docs/agent-model.md`, `docs/zendesk-ticket.md`, `.env.example`, `src/tools/defs.ts`'s `shelve_worker`/`file_where_it_belongs` descriptions, and assorted doc comments in `src/daemon/loop.ts`, `src/daemon/index.ts`, `src/labels/registry.ts`, `src/tools/relationship.ts`, `src/tools/docs.ts`, `src/rules/resource-type.ts`, `src/atlassian/types.ts`, `src/resources/types.ts`, `src/resources/issue.ts`, `src/jira-watch/diff.ts`) are updated accordingly. Historical design-rationale comments in sibling detectors (`abandoned.ts`, `idle-poke.ts`, `frozen-asleep.ts`, `crash-loop.ts`, `pinned-active.ts`, `stall-remediation.ts`, `escalation-loop.ts`, `stalled.ts`) that cite `parked.ts` as prior art for a design choice are left as-is — they describe why those modules were built the way they were, which the removal doesn't change.
