### Fixed

- **The managed-session Rocket.Chat escalation post is hardened before the `butchr-escalation` poster is ever turned on (FACTORY-607 follow-up, from agentsafety's independent probe of 8f4242d).** All of the following were found and fixed before any live post goes out:
  - **Fence breakout.** The previous "widen the fence past the content's longest backtick run" strategy does not survive Rocket.Chat 8.8's own parser (`@rocket.chat/message-parser` 0.32.0), which recognizes ONLY a fixed 3-backtick fence — a quoted run of 3+ backticks could still end the code block (or prevent it forming at all), letting mentions/links/`#channel`/emoji go live. The fence is now always exactly 3 backticks, and every run of 3+ backticks in quoted content is broken by interleaving a zero-width space between each backtick instead. Bidi-control characters (U+202A-202E, U+2066-2069, U+200E, U+200F, U+061C) and the Unicode line/paragraph separators (U+2028, U+2029, U+0085) are now also stripped from quoted content. Every generated post is now parsed through the real parser in tests (dev dependency, pinned to exactly `0.32.0`), asserting exactly one `CODE` node and no stray `MENTION_USER`/`MENTION_CHANNEL`/`LINK`/`EMOJI` node outside it, across mentions, links, `#channel`, emoji, large/small backtick runs, an unterminated fence, forged `fingerprint:` lines, CR/CRLF, bidi/line-separator controls, and a lone-surrogate truncation boundary — with a positive control proving this suite would have caught the original bug.
  - **Secret redaction.** The existing `redact()` (already used on the Jira escalation path) is now applied to the question and every option before quoting, and before truncation so a secret can never straddle the cut. The capture-file path (which embedded the operator's home directory layout) is now quoted as its basename only.
  - **The 3-per-hour per-pane cap now actually bounds posts.** A cap-denied episode previously left tier 1 unlatched, so the very next poll of the SAME (now-tracked) episode posted anyway, bypassing the cap entirely — measured at 360 posts/hour for a fingerprint drifting every 2nd poll. A capped episode is now flagged and stays journal-only (no tier 1/2/3 Rocket.Chat post) for its entire lifetime, with one clear WARNING line when the cap is first hit.
  - **Tier clock keyed to blocked-since, not fingerprint.** Tiers are now keyed to a `blocked-since` instant for the pane, reset ONLY when the pane actually clears — never by a text/fingerprint change while still blocked. Previously every fingerprint change started a brand-new episode with a fresh tier clock, so a pane blocked 40 minutes on text that changed every minute produced 40 tier-1 posts and zero tier 2/3, and the director was never reached. A fingerprint change within an ongoing episode now only updates the quoted text in place (logged once); the original blocked-since and per-tier latches are untouched.
  - **Retry backoff and a whole-message size budget.** A persistently refusing poster is now retried (and its own WARNING logged) no more than once per ~60 seconds per tier, instead of on every ~5s poll — closing a measured 361 attempts/warnings in 30 minutes. The whole composed message (header, fences and every field included) is now budgeted to ~4,500 characters against Rocket.Chat's 5,000-character limit, shrinking the question and options proportionally (with the existing truncation markers) rather than risking an oversized post being refused outright.
  - **Smaller hardening:** a quoted multi-line question/option can no longer start a line that looks like one of this message's own labelled fields (every quoted field is now flattened to a single visible line); truncation no longer cuts in the middle of a UTF-16 surrogate pair; the `[managed-escalation]` journal line's own interpolation of raw question/option text is now sanitized against forged journal lines; the zero-width-space mention-neutralisation is kept as defence in depth even though the fence itself now provably holds.
  - **Docs:** `docs/managed-sessions.md` no longer claims the fence is "uncloseable" (corrected to the fixed 3-backtick behaviour above), and now documents redaction, the whole-message budget, the cap's journal-only behaviour, and the tier clock's blocked-since semantics. It also states the operational prerequisite that the `butchr-escalation` bot must be a member of both `#team-admin` and `#team-engineering` with post rights, with a one-time smoke post to each room before enabling — a refused room currently fails and retries forever rather than surfacing clearly.

Enabling the poster itself, any credential/token work, deploys and restarts remain explicitly out of scope for this ticket.
