### Fixed
- **The BUTCHR-55 coverage guard now scans every file under `src/`, not just `.ts` files, so it can no longer silently miss a build-time asset import in a non-`.ts` file (BUTCHR-40/72).** `test/unit/release-gate.test.ts`'s `walk()` helper filtered to `name.endsWith(".ts")` before handing candidates to the `ASSET_IMPORT` regex — narrower than the `describe` block's claim of "every build-time asset import reachable from `src/`". Latent today (all 42 files under `src/` are `.ts`, verified with `find src -type f | sed 's/.*\.//' | sort | uniq -c`), but if a `.mts`/`.cts`/`.tsx`/`.js` file carrying an asset import to an ungated path ever landed under `src/`, the scan would skip it and both tests in that block — including the anti-vacuity check — would stay green. The extension filter is removed entirely rather than widened to an allowlist: the `ASSET_IMPORT` regex already decides whether a file contributes a path, so a non-code file simply contributes nothing, and there is no allowlist left to go stale.
- **Verified with a RED/GREEN swap.** A scratch `src/agents/scratch-BUTCHR-72.mts` with an asset import to an ungated path turned exactly the coverage test red (`these build-time embedded assets are NOT on the gated path list: scratch-ungated-asset.txt`), 19 pass / 1 fail, as predicted before running; removing it restored 20/20 green. Two further predict-then-run checks confirmed the existing guard wasn't weakened: reverting `/^briefs\//` from `GATED` fails exactly two tests in this file, and injecting an asset import at an already-gated path (`schema/`) fails none — the false-positive case a prior round of this work already had to fix stays fixed.
- **A deliberate trade, tested and documented at the scan.** Walking every file (not just code) means the unanchored `ASSET_IMPORT` regex can also match an illustrative asset-import example inside a prose/doc file, not just a real import. Tested both directions: an example whose relative path stays inside `src/` stays green (harmless); one whose relative path resolves outside `src/` to an ungated location fails the coverage test even though nothing real imports anything. Accepted deliberately — failing loud on a correct file beats silently missing a real asset import, which is the defect this ticket exists to close — and written down as a comment at the scan (`test/unit/release-gate.test.ts`) so the next author who hits it knows why and what to do (gate the path, or move the example).
