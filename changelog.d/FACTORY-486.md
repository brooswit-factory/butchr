### Fixed
- **`parsePrompt`/`parseUnnumbered` close the in-frame chatter gap FACTORY-481 left open: chatter scrolled in BETWEEN a dialog's real question and its options — still below the dialog's own opening frame rule — can no longer displace `question` or move the escalation fingerprint, for dialogs whose real question is separated from its options by a blank line (FACTORY-486, follow-up to FACTORY-481/FACTORY-378).** FACTORY-481 anchored `question` to start fresh after the frame's opening `─+` rule, which defeats chatter scrolled in ABOVE the rule, but did nothing about chatter injected BELOW it, still above the options — the ticket's own reproduction (chatter inserted directly above the option block) and FACTORY-367/FACTORY-369's pinned regression test both measured this: on the merged FACTORY-481 branch, `pane-cap-weekly-limit-real.txt` with N=0/1/3 in-frame chatter lines gave three different questions ("What do you want to do?" → "... [butchr] chatter 0" → absorbing all three) and three different fingerprints.
- Fixed by measuring every real dialog capture in this repo's `.captures/` corpus that draws a frame rule (34 of 84 files; the rest are non-dialog "unrecognised" captures): the option block is always preceded by exactly one blank line, with nothing else in between, whether the question is one line, several, or preceded by its own header/tab-bar block. `question` now walks back from that blank line and takes the contiguous block above it, skipping whatever content touches the options with no blank of its own — that content can never be a real dialog's own question by the same evidence, however much of it there is.
- Stated limitation, not papered over: a real dialog with a numbered menu but NO blank line anywhere between its own content and its options (no example in the `.captures/` corpus; the KAN-756-era hand-authored `TRUST`/`REAL` fixtures used elsewhere in this repo's own tests are exactly this shape) has no structural signal to tell a real question apart from chatter landing beside it, so extraction falls back to the pre-FACTORY-486 undiscriminated tail for that case and remains exactly as vulnerable to in-frame chatter as before this fix.
- `fingerprint` itself is UNCHANGED — still `question + options`. Both `parsePrompt`'s numbered-menu branch and `parseUnnumbered` got the identical fix. No real corpus capture uses `parseUnnumbered`'s bare-marker (no digits) shape, so that branch's invariance is proven only against synthetic fixtures, not measured real-world captures — called out explicitly rather than claimed as corpus-verified.
- Disclosure: `escalationComment` already calls `redact()` over `question`/`options`, so credential-shaped content was never posted un-redacted. This fix narrows the remaining non-secret-prose leakage window further: chatter injected inside the frame can no longer reach `question` at all (previously bounded but still 6 lines' worth), except for the stated no-blank-separator shape above, which is no worse than before this fix.
