### Added

- **Archiving a managed-session definition now releases its Rocket.Chat account (BUTCHR-460).** `butchr session archive`'s definition-file move already stops the agent (its next daemon poll); this ticket wires BUTCHR-410's `releaseAccount(agentKey, "archive")` into that same path — daemon-side, not through the CLI (which is credential-free/daemon-free by design and would otherwise race the daemon's own account-store writes and leave the Nexus manifest stale). `src/agents/managed-session-account-release.ts`'s `wireManagedSessionArchiveRelease` upgrades an ordinary `"stop"` release to the already-modeled `"archive"` reason the moment it can confirm the definition now lives in the archive directory under its original basename — including an archive done by hand-moving the file, which a CLI-side hook could never see. `stop`/`archive` behave identically in `releaseAccount` (both unprovision `temporary`, retain `permanent`); this is purely an honest audit trail. A failed release is queued and retried exactly like every other provider's (BUTCHR-412).
- **A managed-session definition's own `account` field is now real, not just stored** — the same `ensure`/`release` lifecycle every other provider already has (BUTCHR-412) is wired into the built-in managed-sessions loop too, keyed per-definition (`managedSessionAccountPolicies`, mirroring `managedSessionRoles`'s own per-file seam) since the built-in rule is one shared `Rule` for every heterogeneous definition file.
- **The Rocket.Chat account lifecycle is now always constructed**, not gated behind a startup check of whether anything currently wants one. `butchr session create` can add an `account`-requesting managed-session definition at any time the daemon is running, no restart involved — a startup-time decision could never account for that, and the daemon previously risked spawning such a definition with no account hooks wired at all (a silent, unaccounted spawn — review round 1, blocking). The Rocket.Chat HTTP client itself still stays dormant (`null`) when unconfigured, reusing the existing `"rc-not-configured"` withhold-and-log refusal; the accepted cost is the periodic orphan sweep now always runs (one `.butchr-rc-accounts.json` read every 30 minutes) even on a daemon that never provisions anything.
- `docs/rocketchat-accounts.md` ("Wiring"/"Archive release" sections) and `docs/managed-sessions.md` (manifest format table, "Post-archive hook seam") updated; the hook seam itself (`archiveSessionDefinition`'s `onArchived`) stays a documented no-op in production — it still works for any future caller with real Rocket.Chat credentials to inject.
