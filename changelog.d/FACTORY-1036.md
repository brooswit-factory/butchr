### Fixed
- **The launch kickoff command could be truncated mid-flight, stalling an agent before Claude ever started (FACTORY-1036).** The kickoff prompt (`KICKOFF_PROMPT`/`AGENTS_KICKOFF_PROMPT`, `src/agents/argv.ts`) duplicated the entire shared "before you stop or go idle" section into every launch's shell argv, and a managed-session kickoff inlined a rule's whole `brief` text too — together producing a kickoff command large enough (observed: 5,970 bytes) to be truncated by a canonical-PTY input path at 4095 bytes. Both kickoffs are now short, fixed strings (`follow your CLAUDE.md.`/`follow your AGENTS.md.`, plus a one-line `cd` instruction for a managed session) — the shared text is no longer duplicated anywhere in argv, and a managed session's own brief reaches the agent through its own `brief.md` instead of argv.
- **A resumed (`--resume`) Claude session could run its entire first turn against stale CLAUDE.md/brief.md/ENVIRONMENT.md.** `writePreLaunchClaudeFiles` (`src/agents/workspace.ts`), the one function both the fresh-spawn and in-place-resume launch paths call before (re)launching, used to write only `mcp.json` and the file-execution-veto hook; the instruction files themselves waited for the full `buildWorkspace()` call that only runs *after* a resume is confirmed alive. It now also writes CLAUDE.md/brief.md/ENVIRONMENT.md, so a resume sees exactly what a fresh spawn would — before the relaunch is even attempted. The staleness-bookkeeping files (model/effort/permission-mode/etc.) are untouched by this and still wait for confirmed success, exactly as before.

### Added
- `briefs/CLAUDE.md`/`briefs/AGENTS.md` now carry the shared before-you-stop section too (previously only `brief.md` did), so it reaches the agent's own memory/system context at every (re)launch rather than needing a kickoff-argv copy to survive compaction.
- `briefs/_before-you-stop.md` now distinguishes a concrete, unresolved *question* blocking progress (prefer a Needs-Feedback-style status when this issue's workflow offers one) from a genuine non-question hold (unconditionally still "To Do" — unchanged).
