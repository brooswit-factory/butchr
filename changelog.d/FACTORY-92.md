### Fixed
- **`reap.ts`'s stranded-workspace reclamation and its account-release call both derived the agent key from herdr's own `workspace.label`, a free-text field a human can type or a later rename can change (FACTORY-92).** `strandedCandidates()` reconstructed the expected workspace directory from `label` and matched it against a pane's `cwd`; `StrandedCandidate.label` was then documented as "IS the agent key" and passed straight into the reaper's `release` hook, which uses it to derive the Rocket.Chat account to release. This is the same bug class as FACTORY-47: two subsystems each decoding structure out of a shared string, one of them trusting a field the other treats as arbitrary. `strandedCandidates()` now derives the real agent key from a pane's `cwd` via the shared `agentIdOfWorkspacePath` (src/agents/workspace.ts — the same helper `residency-census.ts`'s `groupOwnedPanes` already uses), added to `StrandedCandidate` as a new `agentKey` field; ownership is proven by that cwd-derived key existing at all, never by the label. `label` is still carried on `StrandedCandidate` for log/display only, and `ReaperDeps.release` is now called with `agentKey`, not `label`. Behaviour with today's labels (label == agent key) is unchanged; this only matters once a future story (FACTORY-90) changes what string butchr sends as the herdr label.
