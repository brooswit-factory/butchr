### Added

- A herdr-restored pane whose agent stays mid-turn (`herd.resumeInPlace()` returning `"deferred"`/`"stuck"` on every poll, forever — by design, so a genuinely busy agent's conversation is never destroyed) now escalates instead of degrading silently. `src/agents/restored-pane-escalation.ts` tracks the WALL-CLOCK time (never a poll count) of each issue's first consecutive restored-pane deferral and posts an escalation — a ticket comment where the agent has one, a journal line always — at a first threshold (`RESTORED_PANE_ESCALATION_FIRST_MS`, ~10 minutes) and repeating (`RESTORED_PANE_ESCALATION_REPEAT_MS`, ~1 hour) for as long as the streak continues, naming the agent, how long it has been unable to take butchr's full flag set, that it is running degraded without them, and that its conversation has not been discarded. Nothing about the retry itself changes: `stop()`/`spawn()` is never called on this path, however long the deferral lasts. Reachable on the managed-session path (`buddy`/`genius`, the canary set) as well as the issue/rule-agent tier — `ManagedSessionsLoopDeps.checkRestoredPaneDeferred` (`src/daemon/session-definitions-loop.ts`) is wired alongside the existing `checkCrashLoop`, since the existing `onResumeWaiting`/`onResumePreserved` hooks were found to be unwired for managed sessions entirely (a pre-existing gap, reported separately, not fixed here). The shared model/effort-only resume path (FACTORY-312/PR #551) is untouched: it keeps its old poll-counted, once-only `onResumeWaiting` notice with its old wording, and never gains a wall-clock or repeating escalation — the split is made from the stale-issue's own reason string via the new `RESTORED_PANE_STALE_REASON_PREFIX` constant (`src/agents/herd.ts`).
