### Changed
- **`jira-project` agents no longer get their own unconditional `permissionMode: "auto"` override — they inherit butchr's ordinary `acceptEdits` default like every other rule kind (FACTORY-129, follow-up to FACTORY-127/FACTORY-138).** `agentLaunchConfig` (`src/agents/argv.ts`) used to apply `permissionMode: "auto"` to every `jira-project` Claude agent whose spec named no `permissionMode`, silently ignoring FACTORY-138's new `acceptEdits` default. That override is now removed: a `jira-project` Claude agent with no explicit `permissionMode` gets `DEFAULT_PERMISSION_MODE` (`acceptEdits`) exactly like a `jira-work`/`github-issue`/`github-pr`/`filesystem` agent, and a `jira-project` rule that sets its own `permissionMode` still wins (FACTORY-87, no regression). Safety: `jira-project` agents launch through the rule engine, whose `ruleLizardModeOf` (`src/agents/permission-answer-loop.ts`) already resolves an absent `Rule.lizardMode` as eligible — unlike the managed-session path, this does not special-case vendor — so `acceptEdits`'s Bash/MCP prompts are auto-cleared for `jira-project` agents exactly as they are for every other lizard-eligible rule kind; this is pinned by the existing parameterized "jira-project" case in `test/unit/permission-answer-loop.test.ts`.
- **One-time respawn for `jira-project` agents at deploy.** Every currently-running `jira-project` Claude agent was launched with `--permission-mode auto`; after this change the expected argv for a spec with no explicit `permissionMode` carries `--permission-mode acceptEdits`, so `staleIssues()`'s stale-argv check flags each such agent once and it is respawned with the new default — the same one-time-respawn shape FACTORY-127/FACTORY-138 already used for the rest of the fleet, not a loop (the stale check and the launch argv are derived from the same builder). `jira-project` rules with an explicit `permissionMode` are unaffected. Rollback: set an explicit `permissionMode: bypassPermissions` (or `auto`) on the affected `jira-project` rule(s), or revert this change — either triggers one more respawn; nothing persisted needs migrating.

### Fixed
- `docs/execution-modes.md`'s `permissionMode`/`lizardMode` section no longer describes `jira-project`'s now-removed unconditional `"auto"` override.
