### Added
- **A React 19 + Vite build pipeline for the Butchr dashboard (FACTORY-432, implements FACTORY-390, epic FACTORY-427).** New `dashboard-app/` holds a minimal React 19 app (`vite.config.ts` at repo root, `dashboard-app/tsconfig.json` for its own DOM-lib/JSX TypeScript config, kept deliberately separate from the server-side `tsconfig.json`, which stays untouched); `bun run dev:web` runs Vite's dev server for local iteration, `bun run build:web` (now also part of `bun run build`) produces a production bundle at `dist/web/`, and `bun run typecheck:web` (now part of `bun run check`) type-checks it. New `src/web/static-assets.ts` serves that built bundle from the running daemon at `GET /dashboard-app` (and `/dashboard-app/*`), resolving `dist/web`'s location relative to its OWN module file — same discipline as `src/agents/build-identity.ts`'s `MODULE_DIR` — so it works both from a `Bun.build` bundle and from a from-source `bun run start`, with a path-traversal guard and a 404 (never a crash) for anything missing.
- React 19, react-dom, and the rest of what `@launchpad-ui/components` will need later in the epic (react-aria, react-aria-components, react-stately, react-router, react-hook-form) are installed as real dependencies now, unused by this Task, for the page-conversion Stories that build on top of this pipeline (FACTORY-428 onward).
- **No behavior change to the currently-served dashboard.** `/` and `/configurations` (`src/web/view.ts`) are untouched — this Task stands up plumbing only; `/dashboard-app` is a new route nothing else links to yet.

### Tests
- New `test/unit/static-assets.test.ts`: the static-file handler's own contract in isolation — serves a real built-app-shaped temp dir (`index.html` + a hashed `assets/*.js`, the same layout `vite.config.ts`'s `build.outDir` actually produces), the extensionless-path→`index.html` SPA fallback, path-traversal refusal (never resolves outside root), a 404 for a missing file, and `resolveWebRoot`'s bundled-vs-from-source resolution.
- `test/unit/app.test.ts` gains one route-level smoke test proving `GET /dashboard-app` is actually wired into the real app (never a 500), deliberately not asserting 200 vs. 404 since that depends on whether `bun run build:web` has been run in the checkout.
- `bun run typecheck`, `bun run typecheck:web`, `bun run test:unit` (`bun test test/unit test/load` + the coverage gate), and `bun run build` all pass.
