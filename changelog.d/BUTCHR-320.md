### Added
- **The daemon's spawn path now emits a denominator, not just a numerator (BUTCHR-320).** A successful `HerdrHerd.spawn()` used to write no journal line at all, and its caller (`reconcileNow`) logged nothing on success either — so no spawn measurement anywhere in the fleet had a denominator, only a failure count. Every spawn attempt — the ordinary spawn path and the spawn half of a respawn alike — now emits exactly one `[spawn]` outcome line from the single place both callers go through: `succeeded — pane <id>` (written only after `verifyKickoff`, never right after `agent.start` resolves — "success" means the kickoff was actually verified, not merely attempted), `failed — <reason>` (independent of `reconcile-failure.ts`'s own complaint latch, which only ever gates a Jira comment, never this journal line), or `noop — already has a live agent` for the no-op early return (an issue that already has a live agent attempts nothing, and is neither a success nor a failure). `attempts = successes + failures + noops`, derivable from the `[spawn]` tag alone.
- **The admission line now fires on every poll with a candidate, not only when something is withheld, and carries the admitted count.** The `[admission]` line was a withholding log: guarded on `withheld.length > 0`, so a poll that admitted everything logged nothing, and any admissions total summed from it was a floor, never a count. It now fires whenever there is at least one candidate (a zero-candidate poll stays silent, documented at the call site, with its existing side effect preserved), under a new `[admission2]` tag carrying both the admitted and withheld counts. The new tag is a deliberate, mechanical discontinuity — never a version marker appended to the old `[admission]` tag — so a reader of mixed journal history spanning this deploy can tell, from the line's shape alone, which of the three formats (the pre-aging bare-id list, the post-aging `id(count)` list, or this new line) produced any given line, without knowing the deploy date. **Before/after comparisons of admissions across this change must be re-baselined** — the apparent rise is the instrument gaining sight of polls it could not observe before, not a real change in admission volume.
- **The startup banner now names the build**, reusing the exact `buildIdentity`/`toBuildReport` singleton `/health`'s `build` field already serves (never a second sha derivation) — so a journal window can be attributed to a build, not only to a pid (a pid only bounds one daemon generation).
