### Fixed
- **The daemon's own PR-review-state nudge no longer teaches the stale-approval merge check.** `gh pr view <n> --json reviewDecision,headRefOid` can't detect a stale approval — `headRefOid` is the PR's CURRENT head so it keeps matching local HEAD after every push, and `reviewDecision` stays APPROVED because this repo doesn't dismiss reviews on push, so both signals survive exactly the event they exist to catch. The nudge (`src/daemon/index.ts`'s `notify` closure) is now built by an exported pure function, `prReviewStateNudge` (`src/agents/pr-nudge.ts`), and teaches the same principle the briefs already do: verify the last decisive review's own `reviews[].commit.oid` against the current head before merging. `docs/agent-model.md`'s prose merge-check line is fixed to match.

### Added
- **A new guard, `test/unit/merge-check-guard.test.ts`, asserts the forbidden `reviewDecision`+`headRefOid` pair is absent from every covered agent-facing instruction channel, and that every channel explicitly named as merge-instructing names `reviews[].commit.oid` and the last-decisive ordering.** Covered channels: briefs — read from the actual files `buildWorkspace()` writes to a real workspace directory (`CLAUDE.md` **and** `brief.md`, for every issue type it serves, not just the `brief.md` template — `CLAUDE.md` is the first instruction file an agent reads and was found uncovered in review); tool descriptions (`atlassianTools()`'s real registry); `docs/*.md` read as files; and the daemon's PR-state-change nudge (reached through the exported `prReviewStateNudge`, not by pattern-matching daemon source text). The forbidden-pair check sweeps ALL of every channel, including every doc, since a new unrelated file must never reintroduce the pair; the positive "names the right field" check targets only an explicit `MERGE_INSTRUCTING_BRIEFS`/`MERGE_INSTRUCTING_DOCS` list (also found in review — a channel-wide positive sweep wrongly required an unrelated doc to teach the merge check), guarded against silently matching nothing by asserting the explicit list's length against what's actually found. Exclusions are an enumerated `{path, reason}` array in the guard file rather than prose. Deliberately NOT covered, and stated as such: `CHANGELOG.md`/`changelog.d/*.md` (history of the defect, not instruction), this guard file and `test/unit/workspace.test.ts` (name the pair in negative assertions/comments, not as instruction), `src/labels/pr.ts`'s code comment (documents the GitHub REST API's own field semantics, not an agent instruction), and the Confluence glossary named upstream as a fifth channel (outside this repo, invisible to a unit test). Mutation-tested in both directions: reintroducing the forbidden pair into the nudge, a brief's `brief.md`, a brief's `CLAUDE.md`, `docs/agent-model.md`, or a tool description each turns the guard red; deleting `reviews[].commit.oid` from the rendered nudge (while leaving it in the source file's own doc comment) also turns it red, confirming the guard reads the delivered string, not source text; adding an unrelated doc stays green; breaking the docs glob to a nonexistent directory turns the non-vacuity assertion red. Mutating a brief's `] | last` to `] | first` (the ordering bug this whole feature exists to prevent) is caught by the pre-existing `test/unit/workspace.test.ts` guard, not by this new one — this guard pins the field name and ordering prose, not the jq operator itself, so it adds no new coverage for that specific mutation.
