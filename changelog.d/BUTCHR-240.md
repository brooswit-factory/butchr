### Added
- **The abandoned-worker detector now also catches a worker that never started at all: a To Do ticket whose `Implements` boss is already Done (BUTCHR-240, BUTCHR-237's archetype case).** Before this, a To Do worker under a Done boss was invisible to every detector in the fleet: `parked.ts` requires the boss to be `In Progress` in the active set; the orphan machinery requires the worker to have no boss at all (this one's link is intact, so `adopt_worker` correctly refuses to touch it); and `abandonedCandidates` (`src/agents/abandoned.ts`) — though already structurally correct for this case — only ever saw workers `ISSUE_JQL` returns (`status IN ("In Progress", "In Review")`), which a To Do ticket never is. Nothing was burning, so nothing complained, so a boss that closed without ever discharging a worker it hadn't yet staffed stayed silent forever.
- `createAbandonedDetector` takes a new optional dep, `todoWorkers: () => Promise<readonly JiraIssue[]>` — a fetch seam, not a widening of the predicate: `abandonedCandidates` itself needed no change (it was already total over any `"To Do"`-status worker carrying a Done inward `Implements` stub), so the network call lives entirely in `check`, outside the pure predicate, and is concatenated with the poll's own `issues` before the predicate ever runs. Wired in production via `createTodoWorkersFetch` (`src/resources/issue.ts`), a single `deps.search(TODO_WORKER_JQL)` call — `TODO_WORKER_JQL` (`assignee = currentUser() AND status = "To Do"`) is a deliberately SEPARATE, narrower query from `ISSUE_JQL`, never folded into it: `ISSUE_JQL` is the fleet's active set (spawning, stall detection, the label layer and reconcile all read it), and widening it to include "To Do" would staff an agent for every To Do ticket in the backlog.
- Fail-open on the query, fail-closed on the status — two deliberate, opposite rules for two different subjects: if `todoWorkers()` throws, the poll's existing In Progress/In Review coverage over `issues` still runs unaffected (a WARNING is logged, nothing else); a link stub with no `status` at all was already, and remains, treated as UNKNOWN rather than Done.
- `butchr:shelved` is deliberately still NOT exempted here (unchanged from `abandoned.ts`'s existing decision — `shelve_worker` moves a worker to To Do by contract, so this ticket makes that decision load-bearing for the first time: a shelved worker under a Done boss can never be reactivated by anyone, since only its own Done boss could ever call `start_worker` on it again, so it is MORE abandoned, not less).
