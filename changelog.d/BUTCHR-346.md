### Fixed
- **A raw newline in daemon-captured free text (agent pane content, and by the same construction anything else this daemon logs but does not control) could still forge a genuine `[tools2]` outcome record or `[tools]` alias-audit line, even after BUTCHR-343's own anchor fix.** `journalctl` gives every PHYSICAL line of a multi-line write its own full transport prefix, so a raw newline let uncontrolled text plant a second "line" indistinguishable from a fresh journal entry — and if that text happened to be tag-shaped, both `parseOutcomeLine` and `parseAliasAuditLine` (`src/tools/outcome.ts`/`src/tools/alias-audit.ts`) parsed it as genuine, including a forged `finish_worker` **success**. No reader-side pattern can close this: the information distinguishing a continuation line from a fresh entry is genuinely not present on the line.
- **Fixed at the daemon's log sink, not at the one observed emitter.** A new `installLogSink()` (`src/daemon/log-sink.ts`) wraps the process's real `console.error` once, at daemon boot — before anything else logs — so every `log`/`deps.log` seam across `src/` that defaults to or calls `console.error` (there is no single existing call site all of them already funnel through) has every raw newline in a string argument replaced with the same visible `" ⏎ "` marker `src/tools/outcome.ts`'s `boundMessage` already established, before the text ever reaches the actual writer. This closes the vector for every current emitter (the escalation loop's `blocked with no parseable dialog` line, at minimum one observed forgery) and, by construction, every future one that reaches for `console.error` — the idiomatic thing to do in this codebase — rather than only the one instance this ticket could observe directly. At least four other call sites were identified as interpolating pane-derived or otherwise uncontrolled text (two in the session-limit watcher, two in the escalation loop) without an observed newline forgery from any of them; the sink closes the class regardless of whether each is independently exploitable today.
- No verb's behavior changed — only what is recorded. Structured-field-before-free-text ordering and the "no message bodies in the journal" constraint are both unaffected; the sink only ever replaces a raw newline character, never widens what reaches the log.
