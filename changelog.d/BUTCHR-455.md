### Added
- **`butchr session archive <name>` / `unarchive <name>` (BUTCHR-455, implementing BUTCHR-394 T2).** Moves a managed-session definition file OUT of the active definitions directory into a sibling archive directory (`BUTCHR_SESSION_ARCHIVE_DIR`, else `<definitions-dir>-archive`, resolved by the one function `sessionArchiveDir` — `src/resources/session-archive.ts`), and back. Archiving drops a definition from the built-in query's directory listing, so the existing reconcile (`reconcileNow`) stops its agent on the daemon's next poll — same mechanism as removing the file any other way; unarchiving restores it to the SAME file name, making it eligible again next poll. The move is atomic (same-filesystem `rename`), with a safe cross-filesystem fallback (copy to a temp name in the destination directory, rename into place, unlink the source) that never leaves a partial file in either directory.
- **Identity is preserved exactly.** An agent's key, and the freeze-store gate keyed off it, is derived from the definition's file path — archive/unarchive therefore restore the EXACT original basename (never a caller-supplied destination name) and refuse outright (nothing moved) on a name collision in either direction, rather than silently renaming. Neither verb touches the file's byte content or the manifest's own `frozen` field, so a definition frozen via the manifest gate, the store gate, or both comes back exactly as frozen (or unfrozen) as it left, through both moves.
- **`butchr session list --archived`** lists the archive directory with the same columns and "show invalid entries, don't hide them" discipline as plain `list` — but computes each entry's freeze gates against the path it would have once RESTORED to the active directory, not its current archive-directory path, since the store gate is path-derived. Plain `list` never shows an archived definition.
- **`create <name> ...` now refuses a name collision against an archived definition too**, closing the gap BUTCHR-454 flagged: previously only the active directory was checked, so creating a name that collided with an archived definition would succeed, setting up a later `unarchive` collision.
- **Post-archive hook seam for S4.** `archiveSessionDefinition` accepts an injected `onArchived({ agentKey, path })` hook (default no-op), run once after a successful move, for S4's (BUTCHR-395) Rocket.Chat account cleanup to wire into once that story reaches `main` — this ticket imports nothing from that branch. A hook failure is reported (CLI: stderr; core: `ArchiveResult.hookError`) but never undoes the already-successful move.
- **Carried BUTCHR-454 review follow-ups:** `freeze`/`unfreeze` output now also prints the resolved definitions directory and freeze-store root (same discipline `archive`/`unarchive` use); docs/managed-sessions.md gains a "Shell/daemon environment mismatch" section explaining that the CLI resolves the definitions directory, archive directory and `DROVR_CONTROL_HOME` from the INVOKING SHELL's environment, not the daemon's (a systemd user unit can differ), and what each kind of mismatch actually does (a definitions/archive-directory mismatch fails loudly; a freeze-store-root-only mismatch does not, which is why the root is always printed).
