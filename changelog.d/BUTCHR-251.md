### Fixed
- **`TODO_WORKER_JQL` now carries a stable `ORDER BY created ASC, key ASC` (BUTCHR-251).** `AtlassianClient#search` (`src/atlassian/client.ts`) caps results at `maxResults = 100` and never paginates, so a query with no `ORDER BY` had no ordering contract at all — which rows survived the cap was decided by a property Jira never promised (the defect class BUTCHR-195 exists for). `updated`, used by `ISSUE_JQL`, is deliberately rejected as the key here: it mutates on every touch, so under the same cap the window's membership would still shift as tickets are edited — a differently-unstable set, not a stable one. `ISSUE_JQL` gets away with `updated` only because its population (In Progress/In Review) is bounded by what the fleet can staff and cannot approach the cap; the To Do backlog `TODO_WORKER_JQL` reads is bounded by nothing. `created` is immutable per issue (oldest-first, so the longest-stranded tickets stay visible under a cap); `key` is unique and immutable and breaks any `created` tie, making the order total.
- A test (`test/unit/issue-resource-type.test.ts`) pins the exact ordering clause, mutation-tested to fail by name both when the `ORDER BY` is dropped and when the key is swapped for `updated`.
