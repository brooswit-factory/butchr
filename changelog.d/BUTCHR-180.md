### Fixed
- **A malformed tool call could swallow one argument's text into an earlier one — silently, with a normal-looking success result — and now fails loudly at call time instead (BUTCHR-177/BUTCHR-180).** Measured twice in this corpus (BUTCHR-127 via BUTCHR-102, BUTCHR-164 via BUTCHR-156), always the same shape: `file_where_it_belongs`'s `destination` argument absorbed a premature closing tag plus the entire next argument's own opening tag and text, so the created ticket's real description ended up sitting, whole and readable, inside the wrong field. Nothing errored; the only trace was a `destination` many times longer than any genuine reason.
- `guardShortProse` (`src/tools/relationship.ts`, beside `classifyDestination`/`destinationRefusal` — the existing `destination` validator this shares a module with) catches the SHAPE, not a length bound: an embedded closing tag (`</name>`) or this harness's own `<parameter name="...">` opening wrapper. A pure length cap was considered and rejected — `MIN_REASON_CHARS` already guards the *opposite* bound, and a real destination reason in this corpus runs well over a thousand characters of legitimate prose that a length cap would have refused.
- **Every short-prose argument across the relationship verbs is now guarded, established by reading `src/tools/defs.ts` against `src/tools/relationship.ts`, not assumed**: `destination` and `summary` on `file_where_it_belongs`; `why` and `summary` on `correct_worker`; `reason` on `shelve_worker`; `summary` and the shelve `reason` on `new_worker` (both the issue-caller and the PROJECT-caller path, which carries its own independent copy of the check); the shelve `reason` on `adopt_worker` (one check point, ahead of its own PROJECT-caller routing, covers both paths). A `description`, a doc `body`, and comment `text` (`tell_worker`/`report_to_boss`/`ask_boss`) are deliberately NOT guarded this way — they may legitimately contain this shape, including to describe this very defect — and `priority`/`key` arguments are excluded as controlled, non-prose values with no realistic swallow risk.
- Every guard call fires before its verb's first side effect (documented per verb in relationship.ts and covered by tests asserting no ticket, comment, label, or transition happened on refusal). The refusal message names what was detected (a closing tag or an opening wrapper, and the argument name it referenced) without ever reproducing the corrupted shape as one contiguous literal — a caller pasting the refusal back into a new call must not be handed the exact text that trips it.
- Both historical specimens (BUTCHR-127, BUTCHR-164) are pinned as regression fixtures (`test/fixtures/swallowed-argument-specimens.ts`), read back from their `[correction]`-tagged archive comments and reconstructed at runtime from separate parts rather than written as one literal, for the same reason the guard's own refusal message avoids doing so.
