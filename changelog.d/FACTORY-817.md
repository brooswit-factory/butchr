### Added
- **"Included in capacity" toggle for `role` in the rules API/catalog and the Rules page form (FACTORY-817, story FACTORY-756, epic FACTORY-748).** `role` (`"worker"` | `"sentinel"`, default `"worker"` = counted toward `BUTCHR_MAX_AGENTS`) was file-only until now — an operator had to hand-edit `rules.json` to change a rule's capacity inclusion. `PUT /api/rules/:id` now accepts `role` as an editable top-level field, validated against `AGENT_ROLES` through the same catalog-validated write/audit-line path every other rule field already uses (`src/rules/rules-write-registry.ts`). `GET /api/rules/catalog` additionally serves `capacityRoles: { values, default }` alongside the per-harness catalog, since `role` applies uniformly across every provider rather than per-harness.
- The Rules page's first-rule setup form (`FirstRuleSetup.tsx` — the only surface the catalog-sourced dropdowns/lizard toggle ship on today; editing an existing rule's form is a different epic's still-shelved work) gained the "Included in capacity" toggle, in the same field/validation/layout pattern as the lizard toggle. It renders ON (counted) by default, with copy spelling out what each state means, and is shown disabled with an explanatory note for a `jira-project` rule (which is sentinel by construction regardless of this field).
- **`role: "sentinel"` requires an explicit `confirm: true`** on the write that sets it — the same discipline a risky `permissionMode` or `lizardMode: true` already carries — since opting a rule's agent(s) out of the fleet cap entirely must never slip in silently alongside an unrelated edit. The plan route's `confirmReason` names this gate `"capacity-sentinel"`. `role` is deliberately NOT a restart-triggering field: the admission controller reads it fresh every reconciliation poll, so a change never requires restarting an already-running agent.

### Changed
- `AGENT_ROLES`/`AgentRole` moved from `src/rules/rules.ts` into the dependency-free leaf module `src/rules/agent-harness.ts` (re-exported from `rules.ts` unchanged for every existing importer), the same split `AGENT_HARNESSES`/`RULE_PERMISSION_MODES` already went through — needed as a real value in browser-bundled code (the new toggle) without dragging `rules.ts`'s `node:fs`/`node:crypto` graph into the Vite client bundle.
- `docs/execution-modes.md`'s "Fleet capacity role" section documents the new API/form surface: capacity inclusion is now a per-query choice, default counted, no longer inferred from the Jira issue type.
