### Fixed
- **The stall comments gate keyed on comment AUTHOR, but the daemon's own account and every agent's own account are the SAME credential — so an agent that reported its own progress (exactly what every brief asks for) permanently disqualified its ticket from ever being labelled `agent:stalled`.** `createStalledCheck` (`src/agents/stalled.ts`) used to resolve stall candidacy with `!rows.some((c) => c.authorEmail === deps.accountEmail)`: since `config.atlassian.email` builds both the daemon's Atlassian client and every `report_to_boss`/`ask_boss`/`tell_worker` write, that check could never distinguish the daemon narrating its own state (`[butchr:reconcile]`, `[butchr:respawn]`, …) from an agent's own real progress report. And because `AtlassianClient.comments` fetches the newest N comments (count-windowed, not time-windowed), a stalled ticket's own old report never aged out — disqualification was permanent, not temporary. Verified independently on BUTCHR-272's own comment history: its `[butchr:reconcile]` line and its own `[BUTCHR-272]` report carry an identical `accountId`.
- **The guard now keys on what a comment IS and WHEN it arrived, never who wrote it.** A ticket is disqualified from stall candidacy only if a comment that is NOT daemon chatter (`body.startsWith("[butchr:")` — the same convention `findMarked` in `src/agents/escalation-helper.ts` already uses repo-wide) was created at or after the CURRENT idle streak's start instant (`StalledTracker.streakStart`, exposed alongside the existing `elapsedMinutes`). This is strictly MORE protective than the old rule in one direction (a boss's or a human's comment during the streak now protects the ticket, where authorship never did) and narrower in another (an old report that predates the current streak no longer immunises the ticket forever — disqualification re-anchors every time the streak breaks and re-arms, rather than lasting for the ticket's lifetime).
- **One accepted behaviour change, thought through rather than glossed:** the stall remediator's own wake comment (`[butchr:stall]`-prefixed) is daemon chatter, so — unlike before, when it flipped `stalled.check()` to `false` on the next poll and the label self-cleared — `agent:stalled` now STAYS applied once written. No flood results: the remediator's own `spokenAt` latch plus its evidence-based `findMarked` adoption (which outlives daemon restarts and survives the label going non-applied and re-applying later — proven end-to-end, including a full work → idle → stall → wake → agent responds → idle again → re-stall cycle) already fully own the debounce; the comments gate this ticket touches was never part of it. That bound is count-windowed like the detector's own fetch (`maxResults` 20, `orderBy: -created`) — a genuinely quiet, stalled ticket never scrolls its own wake comment out of that window, so the one-wake-per-episode property holds in practice, though it is not an unconditional per-lifetime guarantee.
- **Every outcome is now legible.** The decline path (a non-chatter comment landing during the streak) logs which comment id disqualified the ticket, deduped so a still-disqualified ticket logs once per disqualifying comment rather than every ~15s poll it re-enters the branch — previously silent, indistinguishable from a ticket never examined.
- `deps.accountEmail` is removed from `StalledCheckDeps` (dep type, daemon wiring in `src/daemon/index.ts`, and every test fixture) — no longer meaningful once authorship stopped being the axis. `deps.comments`' return type widened from `{ authorEmail }` to `{ id, body, created }`, which needed no daemon rewiring: `AtlassianClient.comments` already supplied all three.
