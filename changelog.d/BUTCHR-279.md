### Fixed
- **A post-work stall (worked, then went idle/done and stayed there) could never reach the stall remediator — the idle-streak floor was anchored to "since first observed running", latched permanently the moment an agent was ever seen working (BUTCHR-272/BUTCHR-279).** `StalledTracker` (`src/agents/stalled.ts`) tracked a single `firstObservedAt` plus a `streakBroken` boolean that, once set by any non-idle/done observation, never cleared for the life of the ticket's active period (only `forget()` — called when the ticket leaves the active set — reset it). Any agent that had ever been seen `working` was therefore permanently ineligible for `agent:stalled`, no matter how long it later sat idle with zero comments: `desiredLabels` never wrote the label, `stall-remediation.ts`'s `labelApplied` gate never saw it, and the wake comment that breaks a stalled deadlock never fired for the single most common shape of becalming — an agent that did real work and then quietly stopped.
- **Re-anchored the floor to "continuously idle since the agent LAST STOPPED WORKING."** `Entry` now holds a single `idleSince: number | null` instead of `firstObservedAt`/`streakBroken`: a `working`/`blocked`/`none` observation sets it to `null` (breaking the current streak) rather than latching a permanent flag, and the next `idle`/`done` observation re-arms a fresh floor from that moment. The candidate check (`now() - idleSince >= minutes`) is unchanged in shape — only what `idleSince` means changed.
- **The "a busy agent is never libelled stalled" guard survives, and now means something narrower and correct: "an agent CURRENTLY working is never stalled, and any streak must hold for the full configured window,"** not the old, broader (and wrong) "an agent that has EVER worked is never stalled." `agent:none` remains structurally ineligible — `desiredLabels`' `label === "idle"` gate is untouched, and `observe()` treats `none` exactly like `working`/`blocked`: breaks the streak, re-arms the floor, never itself qualifies. This is deliberate: a ticket with no agent has no pane at its prompt to read a wake comment, and the reconciler (`src/reconcile/plan.ts`/`src/daemon/loop.ts`) already respawns a no-agent active ticket on every poll — unchanged by this PR.
- **The tradeoff being accepted, named explicitly:** widening eligibility to worked-then-idle agents extends the existing "idle/done for the whole window looks identical to a becalmed agent" risk from never-worked agents to worked ones too. What still holds it back, unchanged: the full-window requirement itself, the zero-daemon-comments check inside `createStalledCheck`, the two-consecutive-poll `AgentLabelStabilizer` delay before `agent:stalled` is ever written, and the remediator's own gating on the label as already APPLIED (read back from Jira), never a same-poll candidate.
- **Every prose string and doc comment asserting the old "since first observed" semantics is updated to match** — the wake comment text (`stall-remediation.ts`), the per-poll `[labels] ... stalled: ...` log line (`labels/sync.ts`), the `stalledMinutes` config doc (`config/config.ts`), the `DesiredInput.stalled` doc (`labels/plan.ts`), and the `agent:stalled` entry in the label registry (`labels/registry.ts`).
- **Proven both directions, including the whole path, not just the tracker:** `test/unit/stalled.test.ts` covers `StalledTracker`/`createStalledCheck` directly (post-work stall qualifies after the full window; a currently-working agent is never a candidate; a dip to idle between turns that returns to working before the window elapses does not accumulate toward a later streak; `blocked` and `none` both break and re-arm; `none` never qualifies even sustained). `test/unit/labels-sync.test.ts` adds two end-to-end tests wiring the real `createStalledCheck` + `createStallRemediator` through `createLabelSync` exactly as `src/daemon/index.ts` does: one drives a worked → idle → stalled ticket through enough polls to show the tracker qualifying, the label stabilizing, and Jira read-back all have to land before the remediator actually posts (the tracker qualifying alone is not sufficient); the other drives a worked-then-`none` ticket through many polls to show it never reaches `agent:stalled` and never invokes the remediator's `addComment`, pinning the no-agent case as still exclusively the reconciler's job.
