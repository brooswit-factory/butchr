- **A pane the herd reports blocked, whose text does not parse as a recognized dialog, sustained for `BUTCHR_UNRESPONSIVE_MINUTES` (default 5) consecutive minutes, now escalates instead of sitting silent (BUTCHR-124).** Previously `onNoPrompt` (`escalation-loop.ts`) only debounced and logged this case — nothing reached a human or the blocked agent's boss, even after an hour (the incident BUTCHR-102 measured). A new comment, marked `[butchr:unresponsive]` and visibly distinct from `[butchr:blocked]`, is posted on the resource's own channel (a Jira comment for an ISSUE key, a Confluence root-doc footer comment for a PROJECT key via `speakOnOwnChannel`), names the resource, states how long it has been stuck, and asks a human to look — deliberately carrying no fingerprint and no ANSWER protocol, since there is no parsed dialog to answer. Rate-capped at 3/ticket/hour (`RateCap`), restart-adoption via a bracket-delimited `pane: [<id>]` dedupe key against prior comments (`findMarked`), and the read-back used for that dedupe fails closed on any error rather than risking a duplicate post. No behaviour change to the existing parseable-dialog escalation path.
