### Added
- **Rules reload without a daemon restart (FACTORY-657, FACTORY-643 slice 1, GitHub issue #616).** The daemon's loaded rules now live behind a `RulesHolder` (`src/rules/rules.ts`) that every rule-consuming codepath reads through per poll instead of a startup-captured snapshot. Sending the daemon `SIGHUP` re-reads the rules file (`src/rules/reload.ts`'s `reloadRules`, the exact same `loadRules`/`parseRules` validation `butchr rules check` dry-runs) and swaps the holder's contents in place; an invalid file (bad JSON, a schema violation) leaves the running rules untouched and logs the problem(s) once, with the daemon still up. A successful reload logs `butchr: rules reloaded from <path>: N enabled (ids)` plus which ids were added/removed/changed. A rule removed or disabled by a reload does not kill its agent(s) mid-ticket — the existing reconcile/reap path ends them on a later poll, exactly as a restart's first poll already does today. `reloadRules(holder)` is also exported for FACTORY-663's in-process web write path to call directly after it writes `rules.json` itself — no HTTP endpoint or CLI subcommand added in this slice, per this ticket's own scope correction. README's "Applying a change" and "First run" sections now describe `SIGHUP` instead of "there is no reload path".
