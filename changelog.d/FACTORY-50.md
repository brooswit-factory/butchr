### Added
- **A keyless managed-session escalation now durably captures the pane's full text (FACTORY-50, Part C of FACTORY-44).** When `markManagedSessionStalled` (`src/agents/escalation-loop.ts`) marks a genuinely NEW (pane, fingerprint) episode — the shared choke point both Butchr's own dialog parser and drovr's `onUnknownDialog` hook funnel into — it now also writes the pane's full, unredacted, ANSI-stripped text to the same local capture store BUTCHR-16 built for the keyed-issue escalation flow (`EscalatorDeps.captures`), under its own disjoint filename shape (`<agentKey>-managed-escalation-<paneId>-<timestamp>.txt`, capped at 50 files, oldest evicted first) so it never collides with, evicts, or is evicted by either sibling capture kind. The capture's path is appended to the `[managed-escalation]` journal line so an operator can find it directly. A capture that ERRORS is logged once and never blocks that journal line; a capture that HANGS (the underlying pane read carries no deadline of its own) is bounded by its own timeout (`MANAGED_ESCALATION_CAPTURE_TIMEOUT_MS`, injectable in tests) so a stuck read/write can only ever delay the alarm by that bound, never suppress or indefinitely block it — either way the escalation proceeds with no capture path, logged distinctly. Keyed and non-managed-keyless escalation behavior is unaffected; dialog matchers/answering logic are untouched, per this ticket's own scope. See `docs/managed-sessions.md`'s "Pane-text capture" section.
