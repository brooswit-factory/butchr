### Added
- **A new `[tools2]` outcome record is written after every MCP tool call resolves or throws** (`ok`/`refused`/`error`), independent of the pre-existing `[tools]` pre-operation audit line, which keeps firing unchanged before the verb runs. `parseOutcomeLine` reads it back; `preIdentityRefusalLine` covers a connection refused before any `x-issue` was ever read. See `src/tools/outcome.ts`'s own doc comments for the full design, and its cross-daemon and SDK-validation limits.

### Fixed
- **`parseOutcomeLine` no longer forges a genuine outcome record out of a `[tools2]`-shaped fragment embedded in ANY daemon log line's free text** — not only an OLD `[tools]` line's echoed `jql`/`cql`/title/`why`/`destination`, but any other line carrying caller- or daemon-captured text (e.g. an escalation loop logging captured pane content verbatim). The reader now requires `[tools2]` to be the line's own first token, and requires nothing follow the record's last field, rather than merely checking that no OLD `[tools]` tag precedes the match. Pinned by fragments produced by the real `jira_search` handler and the real `createEscalator().onNoPrompt` path, not hand-written fixtures.
- **`parseAliasAuditLine` no longer forges a drift-classified deprecated-alias call out of a `[tools]`-shaped fragment embedded in another line's free text** — including a `[tools2]` line's own `msg=` (caller-reachable via `jira_transition`'s caller-supplied `status`, echoed verbatim by `ops.transition`'s no-match error) and, closed at the same time for consistency since predating this story, any other daemon line. The reader now requires `[tools]` to be the line's own first token, the same structural anchor as the fix above. Real OLD-format lines that BUTCHR-35's alias-removal evidence chain depends on are unaffected, pinned by a regression test.
- **Both readers' transport-prefix tolerance now covers every `journalctl --output=` mode that emits one line per entry** (`short`, `short-precise`, `short-iso`, `short-iso-precise`, `short-full`, `short-unix`, `short-monotonic`, `with-unit`, all combinable with `--utc`), not only the default. A genuine record read with a non-default `-o` flag previously returned a silent `null`, indistinguishable from "not a record" — the one confusion this story exists to keep apart. `verbose`/`export`/`json`/`json-pretty`/`json-sse`/`json-seq` remain out of scope: confirmed multi-line/structured per entry, a different consumption model entirely, not a silent-failure case. See `src/tools/journald-prefix.ts` (new, shared by both readers) for the full accounting and real captured samples of each mode.
