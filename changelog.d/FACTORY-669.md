### Added
- **First-run seed: one disabled `ui-first-rule` template, written once, at true first run (FACTORY-669, epic FACTORY-659 slice T1, agentsafety-accepted design).** When the daemon starts with no rules file at all — the default path absent, no `BUTCHR_RULES_FILE` override, and no prior `.bak-*` backup in that directory — `src/daemon/index.ts`'s own startup now seeds exactly one rule, `ui-first-rule` (the reserved `ui-` prefix FACTORY-662's web write path alone may edit), `enabled: false`, query set to the sentinel `PLACEHOLDER_QUERY` (enabling is refused until it's edited — see FACTORY-662), `resourceProvider: "jira-work"`, `execution: "singleton"`, `account: "none"`, `role: "worker"`, `agentPreferences: [{harness: "claude", model: "sonnet", effort: "low"}]`, `permissionMode: "default"` + `lizardMode: true` (the FACTORY-76 pairing that keeps the safest manual permission mode from leaving a worker frozen on its first unambiguous dialog). This happens before `loadRules` runs for real, through a new `src/rules/write-rules.ts` primitive, `createRulesFileExclusive` — true no-clobber via a fully-fsynced temp file hard-linked onto the destination (never `rename`'s silent-replace): an existing, empty, or invalid file, or a symlink, at the rules path is never touched, and the candidate text is validated through `loadRules` before anything reaches disk. Not reachable from HTTP, MCP, a reload, or a file watcher — deleting the seeded file while the daemon runs does not recreate it, since nothing else ever calls the new `src/rules/seed-first-run.ts`. A successful seed logs one line and raises one ops alert; a `.bak-*` found with no current file (an established install whose rules file vanished, not a fresh one) skips seeding and instead logs a warning plus a non-deduped ops alert; a seed failure (e.g. a read-only config dir) warns and the daemon starts with no rules, exactly as if the file were simply absent. `PLACEHOLDER_QUERY` now lives canonically in `src/rules/rules.ts` (re-exported, unchanged, from `src/rules/rules-write-registry.ts` for every existing importer). README's "First run" section and `src/rules/rules.ts`'s own header comment are updated to describe the seed.
