### Added
- **New `get_doc_comments` verb: a PROJECT caller can now read the footer comments on its own root doc (BUTCHR-107).** `report_to_boss`/`ask_boss` already post there for a project caller, but nothing returned that text back — `get_doc()` only ever read the page body, so a comment left on a project's root doc was invisible to the project itself; the wake fired, but re-reading never surfaced the message. `get_doc_comments` takes no arguments (same reasoning as `check_in`/`report_to_boss`: the only doc it can ever read is the caller's own, resolved server-side, so there is no key to get wrong) and returns `{ results: [{ id, body, author }] }` — `author` (the commenter's Atlassian accountId) is new on `AtlassianOps.getPageComments` too, widened rather than duplicated, since `check_in` already reads the same op for its watermark. Refuses an ISSUE caller with an explanation that points at the read it already has: `jira_get_issue`'s response already embeds an issue's own comments.
