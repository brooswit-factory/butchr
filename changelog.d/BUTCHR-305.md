### Added
- **A project pinned `"active"` by an agent that has stopped acting — parked, hung, or a turn that ended without ever calling `check_in` — is now bounded by an observe-and-speak backstop (BUTCHR-305, implementing BUTCHR-238).** A resource id that is `desired` (`"active"`), `running`, and not argv-stale was never touched by any existing `ReconcileOptions` hook — `checkFrozenAsleep`/`checkDeclaredDone` only ever see `atRest`, which an `"active"` verdict is never a member of; `checkCrashLoop`/`admission` only ever see `plan.spawn`; `checkReconcileFailure` only ever sees a rejected operation; `checkReap` only ever sees ids with no agent — so `planReconcile` never put such an id in `spawn`, `stop`, or `respawn`, on any poll, forever. New `src/agents/pinned-active.ts` (`createPinnedActiveDetector`) reuses `StalledTracker` (`src/agents/stalled.ts`) for the idle/done streak floor and `findMarked`/`RateCap` (`src/agents/escalation-helper.ts`) for the same dedupe/rate-cap house mechanism `frozen-asleep.ts`/`stall-remediation.ts` already use, and posts through `speakOnOwnChannel`/reads back through `createOwnChannelComments` (`src/tools/speak.ts`) — the same project-aware seams that keep a complaint from becoming a fresh wake trigger on the project it is complaining about. Wired into a new optional `ReconcileOptions.checkPinnedActive` hook (`src/daemon/loop.ts`), called with `desired ∩ running` and its `void` return discarded — never gates or reaps, only observes and speaks, same contract as `checkCrashLoop`/`checkReconcileFailure`.
- Wired into the PROJECT loop only (`src/daemon/index.ts`) — the issue tier already covers this same shape via `syncLabels`/`stallRemediation`, which gates on the `agent:stalled` Jira label; a project key carries no Jira issue to label at all. Reuses `config.stalledMinutes` (same phenomenon, same threshold semantics as the issue tier's own stall detection), the existing `agentStatuses` `herdr.agent.list()` seam (extracted to a shared closure so `syncLabels` and this new detector read from the same reader rather than each building their own), and the same `quotaGate.isBlocked` predicate `stallRemediation` already wires — a quota-blocked agent cannot act on a wake comment and is left to the session-limit path, which owns that case (see `docs/wake-watermark-and-project-sleep.md`'s new section for the full division-of-labour argument).
- One deliberate departure from `frozen-asleep.ts`/`stall-remediation.ts`'s own bare per-id dedupe fingerprint: this module needs a genuinely fresh idle episode (agent worked, then stalled again) to be able to complain again, rather than being latched shut forever by an earlier, closed episode's complaint. It tracks in memory when a spoken-for episode closes and only adopts an existing channel comment when it was not posted before that closure — see the module's own top comment for the bounded, documented cost this trades against perfect restart-adoption (a rare, narrow window where a restart could produce one extra, still truthful, still rate-capped comment; never a fabrication and never a permanent loss of coverage).
- Registered on `/health`'s coverage tracker (`src/daemon/coverage.ts`) under `"pinned-active"`, same BUTCHR-179 convention `stalled` already follows: a resolved comments fetch counts as checked, a rejected one as declined.
