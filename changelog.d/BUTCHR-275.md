### Added
- **A project agent whose verdict reads `"asleep"` now stops occupying its pane promptly after its own `check_in`, instead of sitting there until `checkFrozenAsleep` reaps it roughly `BUTCHR_ATREST_MINUTES` minutes later (BUTCHR-275, implementing BUTCHR-271).** New `src/agents/check-in-exit.ts` (`createCheckInExitRegistry`) gives the daemon a positive, one-shot, in-process "I have checked in" signal — `declare(id)` is called from `check_in`'s own tool handler (`src/tools/defs.ts`, new optional `declareCheckInDone` seam on `atlassianTools`, same absent-by-default shape as BUTCHR-244's `isStaffed`) STRICTLY AFTER its `advanceProjectWatermark` write has resolved without throwing — never before, never speculatively — so "check-in lands before teardown" is structural: a process that dies mid-`check_in` declares nothing and the project simply wakes again next poll, exactly as before this ticket. `reconcileNow`'s new optional `checkDeclaredDone` hook (`ReconcileOptions`, `src/daemon/loop.ts`) consumes that declaration and removes the id from `atRest` before `planReconcile` runs, so the existing, working `herd.stop()` route releases the pane on the very next poll while the agent is still in `agent.list()` — deliberately not a literal self-exit, since `herd.stop()` on an id that has already left `agent.list()` is a silent no-op forever. `checkDeclaredDone` is a separate hook from `checkFrozenAsleep`, not folded into it (that hook's own contract is "never on a bare timeout, only after an audible complaint" — a defect report; a declared-done project has not frozen), and it runs BEFORE `checkFrozenAsleep` and narrows the candidate set that hook receives — an id that checked in this same poll, after already sitting past the frozen bound, must never be offered to `checkFrozenAsleep` as a candidate, or it can draw a `[butchr:frozen]` complaint about an agent that did exactly the right thing. `atRest` itself is untouched — this adds a positive per-id signal that makes one resource eligible for immediate release, not a loosening of the guard for anyone who has not declared. The declaration is one-shot, consumed the moment `checkDeclaredDone` returns it: a later, unrelated sleep episode of the same project id needs its own fresh `declare()` and never inherits an old one, so a declaration cannot outlive the poll that acts on it and cannot stop a later, genuinely-pending agent for the same project.
- The stale module comment in `src/resources/project.ts` (previously claiming the version/epic watermarks had "no call site to advance them from" and named an unbuilt "exit hook") is corrected in place to describe the seam as it now is: `check_in` is that call site, and its own handler now also declares the exit signal described above.
