### Added
- **A cold-boot settle gate (FACTORY-710/FACTORY-708/FACTORY-704): butchr no longer fresh-spawns a definition with a resumable Claude transcript while herdr's own pane-restore listing is still catching up.** Root cause: `HerdrHerd.byIssue()` builds its "what is running" map purely from `herdr.agent.list()`, which reads identically whether nothing is running or the restore simply hasn't populated it yet — so `reconcileNow`'s ordinary `plan.spawn` path (fresh-spawn, no `--resume`) picked up a perfectly resumable workspace the instant herdr's socket was up but its pane list was still empty, discarding the conversation. The hazard window was specifically "herdr socket up, pane list not yet populated"; a socket genuinely DOWN still throws and spawns nothing, unchanged.
- `RestoreSettleGate` (`src/agents/restore-settle.ts`) holds any fresh-spawn candidate that has a resumable transcript on disk (same `workspaceSessionId`/`claudeTranscriptExists` check `resumeInPlace()` itself uses) until herdr's restored-pane listing is stable across two consecutive polls, bounded by `BUTCHR_RESTORE_SETTLE_BOUND_MS` (default 60000ms) past which it falls back to today's fresh-spawn behaviour and logs why. A definition with no resumable transcript is never held. Emits exactly one `[restore-settle] N resumed, M fresh` log line when the settle resolves (including on the bounded-wait fallback), and never re-arms after its first settle — this is a one-time, cold-boot condition for the daemon process's lifetime, not a steady-state guard. Wired into the issue tier's reconcile loop only (`ReconcileOptions.restoreSettleGate`, `src/daemon/loop.ts`); the project tier has no Claude transcript to resume.
- Does not touch the existing FACTORY-470/472/491/500/501 safeguards (the 3-flag `isHerdrRestoredPane` discriminator, the `launch_pending` guard, the `BUTCHR_RESTORED_RESUME` canary/kill switch) — this gate sits upstream of all of them, acting only on `plan.spawn` candidates that herdr has not listed at all yet, never on an already-listed stale/resumable pane.
- The settle signal is not independently observable from herdr's API — there is no call that answers "is your restore done" on its own. Stability-across-two-consecutive-polls, with a hard bound, is the documented fallback; this gate does not invent a richer signal herdr cannot actually provide.
