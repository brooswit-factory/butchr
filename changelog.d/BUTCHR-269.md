### Added
- **A read-only `/dashboard` endpoint serves one row per agent this daemon runs — resource key, tier, agent status, pane, and time-in-status — with per-row freshness, and "could not check" representable and distinguishable from "nothing is wrong" (BUTCHR-269).** Per BUTCHR-263's ruling, the route does NO I/O: it reads a poll-fed in-memory snapshot, tee'd off the same `agent.list()` call `createLabelSync`'s `agentStatuses` provider already makes (`src/daemon/index.ts`) rather than a second fetch, so `lastConfirmedAt`/`confirmedAt` can actually go stale and the status-floor tracker sees every transition, not just the ones that happen to coincide with a page load.
- **`time-in-status` is a floor, not an elapsed time** — a new, dedicated `StatusFloorTracker` (`src/agents/status-floor.ts`), in-memory only like every other liveness tracker in this daemon, deliberately NOT a widening of `StalledTracker` or the frozen-asleep tracker (both load-bearing for a different question each). Every row carries both a machine-readable `since`/`sinceMs` and a glanceable `humanDuration` ("6d 3h 12m"), plus `exact: false` whenever the floor is only a lower bound (first-ever observation of an id, or a daemon restart) — never silently indistinguishable from a genuine zero.
- **"Could not check" reuses the existing `src/daemon/coverage.ts` vocabulary** rather than inventing a second one: the whole-response `agent.list()` failure (measured live in this fleet — see the ticket) leaves the prior snapshot's rows in place, stale and honestly labeled, rather than discarding them or re-serving them as freshly confirmed; a row's unavailable `issuetype` reads as `{checked: false, declinedAt}`, never a guessed task/story/epic default. `issueMeta` in `src/daemon/index.ts` is `summary` widened to also retain `issuetype` — a field the issue loop's `search()` already returns on every poll and was previously thrown away, not a new Jira call.
- **The row type does not foreclose BUTCHR-288's future agent-less ("withheld") row**: `DashboardRow` carries an explicit `kind` discriminator (today only `"agent"`), and is written as a union-of-one type alias so a future second kind is additive rather than a redefinition. `pane`/`agentStatus` are not shared with any future kind, so a withheld row would omit them structurally rather than needing a sentinel (`"unknown"` is already a real `agentStatus` value and means something else) — and that structural omission is deliberately a THIRD concept ("not applicable, by construction"), never folded into the coverage checked/declined vocabulary used for `tier.issuetype`.
