### Added
- **Description-derived link discovery is now live in the `jira-work` poll (BUTCHR-431, story 1/4 of epic BUTCHR-421).** BUTCHR-429 shipped pure parsers for Jira-key/browse-URL, Confluence, GitHub issue, GitHub PR, and generic-webpage links found in an issue's description text, but nothing fed them in production — `SEARCH_FIELDS` (`src/atlassian/client.ts`) never requested `description`, and `logLinkedDiscovery` (`src/rules/resource-type.ts`) never passed it to `discoverLinkedItems`. Both now do: `description` rides the same `search()`/`searchAll()` call every `jira-work` poll already makes (Jira's ADF flattened to plain text via the existing `adfToText`), so this adds **zero new Jira API calls**. `[linked-discovery]` lines now include `jira-key`/`confluence`/`github-issue`/`github-pr`/`webpage` kinds for real matches, gated on change exactly as `issuelink`/`parent` already were, and still capped (with skipped extras logged) by a rule's `maxLinkedItems`.
- `discoverLinkedItems` (`src/resources/linked-discovery.ts`) takes a new optional `ownKey`: when set, it excludes that key from the returned set, so a ticket whose own description mentions its own key (e.g. a story's description naming itself) is never reported as linking to itself. `logLinkedDiscovery` always passes the match's own key.

### Changed
- `JiraIssue` (`src/atlassian/types.ts`) gained an optional `description?: string` field, mapped the same way `issuelinks` already is (present only when the response carried the field; `undefined` means unknown, never a fabricated empty string). Existing fixtures and other constructors of `JiraIssue` are unaffected — the field is optional and nothing reads it unless it's there.
- Remote Jira issue links remain NOT wired to any routine poll — still a separate per-issue REST call, still deferred to the story gated on `linkedEventing`. No behavior change for anything except the new description-derived `[linked-discovery]` log kinds: `changedKeys` (`src/jira-watch/diff.ts`) never reads `description`, so a description-only edit still does not count as a change anywhere it didn't before.
