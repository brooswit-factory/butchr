### Added
- **A GET link target for the dashboard's terminal-attach row action, keyed by pane rather than issue (BUTCHR-267).** The existing `POST /agents/:issue/open` isn't something an `<a href>` on a dashboard row can reach, and it's keyed by issue while the row data carries the pane. `GET /agents/pane/:pane/attach` closes that gap: it decodes the `:pane` path segment (colon-bearing pane ids like `w1:p3` survive both raw and percent-encoded), validates the pane against the daemon's own live agent registry via a new pure `resolveAttach` decision function in `src/terminal/open.ts` (reusing `terminalCommand`/the daemon's resolved terminal prefix — no second emulator table or spawn path), and refuses anything else with one of three specific, human-readable plain-text messages: unknown/not-live pane, no display to reach (`DISPLAY`/`WAYLAND_DISPLAY` unset), or no terminal emulator found (naming the `BUTCHR_TERMINAL` override). On success the response says only that a terminal was launched — the spawn is fire-and-forget, so it never claims a window actually appeared. The existing issue-keyed `POST /agents/:issue/open` route and page are unchanged.
