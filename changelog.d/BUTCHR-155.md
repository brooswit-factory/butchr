### Fixed
- **The startup sweep's `agent:*` label selection is now derived from the `AgentLabel` union, so `agent:stalled` (and any future member) is reached (BUTCHR-144/BUTCHR-155).** `sweepStaleAgentLabels` (`src/labels/sweep.ts`) retracts stale `agent:*` labels left on a ticket that went inactive while the daemon was down — the only thing that ever revisits such a ticket, since the poll loop is scoped to active statuses. Its `SWEEP_JQL`'s `labels IN (...)` clause was a hand-written list of four values that never included `agent:stalled`: a ticket carrying `agent:stalled` when it went inactive was never selected, so it kept the stale label indefinitely. The sweep's removal step (`filter(isAgentLabel)`) already stripped every `agent:*` label off an issue it selected — the hole was entirely in selection, never reach.
- The one-line fix (adding `"agent:stalled"` to the list) was deliberately rejected: it would leave the next `AgentLabel` member in the same position. Instead, `src/labels/plan.ts` gains `ALL_AGENT_LABEL_KEYS`, derived from a new `ALL_AGENT_LABELS: Record<AgentLabel, true>` — a value-level anchor pinned to the `AgentLabel` union (TypeScript types are erased at runtime, so the bare `type AgentLabel` alone cannot produce this list). Extending `AgentLabel` without adding a matching key to `ALL_AGENT_LABELS` fails to compile ("Property '<newlabel>' is missing"), the same closed-`Record` door `src/labels/registry.ts`'s `LABEL_REGISTRY` already uses — a second, independent anchor for a different consumer, deliberately not shared with (or imported from) `registry.ts`, whose own header requires it stay unimported by `plan.ts`/`sync.ts`/`sweep.ts` so it stays pure documentation with zero runtime effect. `SWEEP_JQL` is now built from `ALL_AGENT_LABEL_KEYS` instead of a hand-written literal list.
- Deliberately no exclusion mechanism: every `AgentLabel` member is always selected, because all five currently belong in the sweep's selection and `Record<AgentLabel, true>` makes silent, by-omission exclusion impossible today. A future deliberate exclusion would require changing that Record's value type, not just leaving a key out.
- New tests (`test/unit/labels-plan.test.ts`, `test/unit/labels-sweep.test.ts`) whose failure mode is "someone added an `AgentLabel` member and the sweep does not select it" — not an assertion that today's five values are listed. One proves, at compile time (`@ts-expect-error`, checked by `bun run typecheck`), that `Record<AgentLabel, true>` cannot omit a key; the other proves, at runtime, that `SWEEP_JQL`'s quoted `agent:*` terms are exactly `ALL_AGENT_LABEL_KEYS` — closing the gap a purely compile-time check can't: that `SWEEP_JQL` is genuinely built from that array, not just coincidentally consistent with it today.
- `src/labels/registry.ts`'s header (AC-9(a)/AC-9(b)) and its `agent:*` lifecycle notes updated to reflect this: the hole they documented as live is now closed, and the four `agent:*` string characters that used to sit together in `SWEEP_JQL`'s hand-written literal no longer exist anywhere in `src` as text (the label-literal scanner's "zero of nine daemon-owned values" finding is unchanged either way — it never counted them).
