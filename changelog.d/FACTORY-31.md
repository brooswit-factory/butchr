### Added
- **Comments capability wired in for `confluence-page` (FACTORY-31, implementing FACTORY-29).** `readComments`/`addComment` (`src/resources/comments.ts`) now cover five providers instead of four, reusing `AtlassianOps.commentOnPage`/`getPageComments` (`src/tools/atlassian.ts`/`atlassian-real.ts`) over Confluence FOOTER comments only — inline comments are not read or written through this interface. `CommentClients` gains an optional `"confluence-page"` field typed as `Pick<AtlassianOps, "commentOnPage" | "getPageComments">`.
- **Body format is asymmetric by direction, and documented as such:** `addComment`'s `body` is plain text, converted to escaped storage-format XHTML by `comments.ts` itself (`& < > " '` escaped; blank-line-separated paragraphs become `<p>…</p>`, single newlines become `<br/>`); `readComments`' returned `Comment.body` is `getPageComments`' storage-format XHTML as-is, never converted to plain text. A caller needing raw storage-format XHTML on write must call `AtlassianOps.commentOnPage` directly.
- **Ordering is sorted client-side:** `getPageComments` deliberately requests no server-side `sort`, so `readComments` for `confluence-page` sorts by `created` ascending itself; comments missing `created` sort after every dated comment, in stable original order.
- **`commentOnPage`'s return id is honestly verified, never faked:** its declared return is `Promise<unknown>` and confluence.js's own schema marks `id` optional — a missing/unusable id is a documented rejection stating the comment WAS posted and must not be retried, the same precedent `zendesk-ticket`'s null-id case already set.
- **`capabilities.ts`'s MATRIX now declares `comments: true` for `confluence-page`** — the pinned-matrix test and `docs/provider-capabilities.md` are updated together; `jira-project`, `filesystem` and `webpage` remain the only providers with `comments: false`.
