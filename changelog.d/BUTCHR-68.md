bump: minor

### Added
- **The project resource type (BUTCHR-67) is now wired into daemon startup, as a second `runResourceLoop` instance beside the existing issue tier** (`src/daemon/index.ts`), using `createProjectResourceType`/`PROJECT_POLL_INTERVAL_MS` and the same `realAtlassian` ops object and Jira search client the issue tier already uses — no second Atlassian client, no third credential path.
- **OPT-IN, default OFF: `BUTCHR_PROJECT_ALLOWLIST` (comma-separated project keys, empty/unset by default).** A deploy of this change with no configuration edit staffs zero projects. The allowlist is enforced inside `loadProjects` (`src/resources/project.ts`) itself — the sole discovery path `createProjectResourceType` exposes — so an unlisted project can never reach `eligible`/`active` by any route this daemon takes. The project loop always starts (even at an empty allowlist) rather than being conditionally constructed, so `/health` and the daemon's own startup banner (`describeConfig`) give an operator a truthful answer to "is the project tier deployed?" either way.
- **Closed a mutual-eviction hazard found before this shipped: two `runResourceLoop` instances sharing one `Herd` would stop each other's agents on every poll.** `HerdrHerd` maps every `butchr-*` agent into one flat namespace with no resource-type scoping, so `reconcileNow`'s `stop = running − desired − atRest` (`src/reconcile/plan.ts`) would read the OTHER loop's running agent as "running but not desired" and stop it — measured, in both directions, against the shipped `planReconcile`. Fixed by construction: `GenericLoopDeps<T>` gains a new REQUIRED `ownsId: (id: string) => boolean` field; `runResourceLoop` (`src/daemon/loop.ts`) scopes the herd it hands to `reconcileNow` through it before `stop`/`respawn` are ever computed, so a foreign agent is invisible to a loop's reconcile step by construction rather than by a filter someone has to remember to apply. The issue loop and the project loop use `isIssueKey`/`isProjectId` (`src/resources/id.ts`) — mutually exclusive by construction, via disjoint regexes.
- The project loop is wired with `syncLabels` and `checkParked` deliberately omitted: both are issue-shaped throughout (`status`/`key`-keyed), and `stalled.check` reports stalled unconditionally on a failed comment fetch, which a project's comment endpoint always is (404 — a project key is not a Jira issue) — adapting either onto a `ProjectResource` would convert a compile-time type error into a live false-positive detector plus a write to a ticket that does not exist.

### Changed
- None to the issue tier's own resource-type module: `src/resources/issue.ts` is byte-for-byte unchanged. The issue loop's own `runResourceLoop` call site in `src/daemon/index.ts` gains the new required `ownsId: isIssueKey` field (the other half of the eviction fix, above) — a no-op whenever no project agents are running, which was the status quo before this change (no project agent has ever existed).
