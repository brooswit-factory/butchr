### Fixed

- **Extension-origin guard rejections are now diagnosable from the journal, and bounded against flooding.** A `403` from `GET`/`POST`/`OPTIONS /resources/for-url` or the `GET /agents/:agentKey/pty` upgrade path used to leave no record anywhere — "origin required" vs "origin not allowed" vs "allowlist empty" (an operator misconfiguration) could not be told apart without reproducing the request by hand. Each rejection now emits one `[origin-guard]` journal line with the method, the request's route PATTERN (never a raw, attacker-controlled path segment such as the PTY route's agent key, and never the query string — it carries the page URL), the `Origin` header verbatim or the literal `"absent"`, and the reason. Rate-limited/deduped to at most one line per distinct (method, route pattern, origin, result) per minute. Four independent bounds keep this from flooding the journal or growing unbounded even against an attacker varying every key field on every request: dedupe on the route pattern rather than the raw path (so varying the PTY route's agent key can't multiply the dedupe key); a global cap on lines emitted per window, with a single `suppressed=N` line reporting what was dropped once the window ends (itself rate-limited to at most one per window); a hard cap on the dedupe map's own size, enforced on insert; and a self-pruning dedupe map that stops at the first still-live entry. Allowed requests still log nothing.
