### Added
- **Session-limit watcher durably captures pane text when its own detection is inconclusive, so the next recogniser miss produces its own real fixture (BUTCHR-3/BUTCHR-12).** On 2026-08-29 three agents were refused with "You've hit your session limit" and sat idle 90 minutes past reset before an operator noticed by hand — `detectSessionLimitRefusal` never fired for any pane, and by the time anyone looked the pane text (no scrollback, ~2.5KB) had already scrolled away. Rather than guess-widen `TAIL_LINES` off a fabricated fixture, `watchSessionLimits` now writes the full ANSI-stripped pane text to a new directory (`BUTCHR_CAPTURE_DIR`, default `.captures` under the workspace root) on exactly two trigger classes: `unrecognised` (the cheap substring `/hit your session limit/i` matches but `detectSessionLimitRefusal` returned null — precisely "the recogniser might be missing a live refusal") and `no-reset-time` (recognised, but no reset clock time could be parsed). The normal recognised-with-a-reset-time path is deliberately never captured — it already works, and capturing it would be pure noise.
- Two bounds keep this cheap: at most one capture per `(issue, trigger class, pane incarnation)` — cleared once a poll finds the phrase gone from that pane entirely — and a global cap of `CAPTURE_MAX_FILES = 50`, oldest evicted first by the timestamp parsed out of each capture's own filename (`<ISSUE>-<trigger>-<compact-UTC-timestamp>.txt`) — never by a plain sort of the whole name, which would order by issue key first — and only among filenames recognised as butchr's own, so an operator-settable `BUTCHR_CAPTURE_DIR` pointed at a shared directory never has unrelated files evicted. Every capture attempt is wrapped fail-open: a write failure is logged once per pane (never retried every poll) and the poll continues regardless.
- `test/fixtures/pane-cap-session-limit-quoted-ticket.txt` — a HEALTHY pane with the phrase quoted in scrollback — is captured under `unrecognised` by design, with no discriminator added: the bound above makes the worst case a handful of small files an operator reads and discards, whereas any cheap-enough discriminator would itself be a guess about the trailing chrome this ticket does not yet understand, i.e. the exact `TAIL_LINES` widening that stays out of scope. A false negative on the one event this feature exists for costs far more than a discarded file.
- The same evidence-gone-before-anyone-looked-at-it shape has since recurred in two other subsystems (an unrecognised Claude Code dialog, and a poll-loop death invisible to `/health`); both are tracked outside this epic.
- New `BUTCHR_CAPTURE_DIR` env knob, documented in `README.md` and added to `ConfigEnv`/`Config`.
