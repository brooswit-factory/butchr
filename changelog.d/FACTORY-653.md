### Fixed
- **`hooks/file-execution-veto.py` no longer false-blocks the five command shapes the 8,072-command replay found (FACTORY-653, follow-up to FACTORY-625/#635).** Per the director's per-group ruling: `mkfs`/`dd if` text inside a `grep`/`rg`/`echo` pattern string is no longer treated as an invocation of either — both checks now require the match to be the segment's own command verb, not merely present as a substring, so a quoted pattern string (and a script like `sweep.sh` whose only match is such a pattern line) is approved while `mkfs.ext4 /dev/sda1` and `dd if=/dev/zero of=/dev/sda` at command position still block. Appends (`>>`, `tee -a`, heredoc — never a `>` overwrite) to an agent's own `~/.claude/projects/*/memory/*.md` are now allowed; nothing else under `~/.claude` is affected, and `echo x >> ~/.claude/settings.json` still blocks. `add-rocketr-account.sh` appending to `~/.config/rocketchat/secrets.env` is now allowed by that exact script's own basename only — a general append to `secrets.env`, or the same append from a differently-named script, still blocks. Appends to `~/.config/butchr-new/managed-sessions.env` are now allowed; per the director's ruling on the one open point, a `>` overwrite of that same file (the replay's entry 13) stays blocked on purpose and is not a regression. The one credentials-copy command stays flagged, as decided.
- `audit()` no longer silently drops every audit line, `would-block` included, when `--audit` names a bare filename with no directory component (`os.makedirs("")` raised and the `OSError` was swallowed) (FACTORY-651). `makedirs` is now only called when the path actually has a directory part. Production was never affected, since butchr always passes an absolute audit path, but a relative `BUTCHR_PERMISSION_AUDIT_PATH` would have lost the audit trail during the audit-only window the enforce decision depends on.
