### Added
- **`stand_down`: the issue tier's own sleep/wake verb.** An issue-tier agent (Epic/Story/Task) that has acted on everything it can see and is only waiting on a worker or a review can now release its admission-cap slot instead of holding it for the whole wait — previously the longest, most common idle hold in the fleet, with no way to free it short of the agent exiting. Refuses a project caller (which already has `check_in` for this purpose) and takes no arguments, same trust model as `check_in`.
- **Wake is edge-driven, reusing the existing notify stage — no new wake axis, no new per-poll Jira calls.** When the notify stage decides a currently-asleep watcher should hear about a change, a NEW gate (`src/agents/stand-down.ts`, wired into `src/resources/issue.ts`'s `createIssueEventRules`) decides whether that edge is genuinely new. A structural edge (status/daemon-label/pr:*-transition/summary) always wakes unconditionally. A comment-shaped edge (the only shape `stand_down`'s own last-act writes — `report_to_boss`/`tell_worker` — can produce) is compared against a seen-comment-id snapshot taken at stand-down, by SET MEMBERSHIP (reusing BUTCHR-227's `unseenIds`, not reimplementing it) — closing a measured self-wake hazard where a foreign write racing in the same poll window defeats the own-write ledger's exact-`updated`-match suppression.
- **Two new bounded failure modes.** A missed/wrongly-suppressed edge degrades into a bounded delay, not a permanent silent stall: `BUTCHR_STANDDOWN_MAX_MINUTES` (default 60) force-wakes a stood-down issue, logged distinctly from an edge-driven wake. A wake→stand_down→wake cycle is detected and reported as its own `[butchr:yieldloop]` complaint (`BUTCHR_YIELDLOOP_COUNT`/`BUTCHR_YIELDLOOP_WINDOW_MINUTES`, defaults 5/5 minutes) — a different fault from a crash loop, with its own remedy.
- **The crash-loop detector is deliberately blind to an orderly wake**, at the call site (not the detector): a spawn that is a declared stand_down's own wake is filtered out of the candidate list the issue-tier crash-loop check is handed, so an agent waking several times an hour on ordinary chatter is never reported as crash-looping.
- **The issue loop now has the same `atRest` machinery the project tier already had**: `checkFrozenAsleep` (a second, issue-tier `FrozenAsleepDetector` instance), and a second `CheckInExitRegistry` instance for `checkDeclaredDone`/`invalidateDeclaredDone` — releasing a stood-down issue's pane through the existing `plan.stop` → `herd.stop()` route, never a self-exit.
- **`briefs/epic.md`/`briefs/story.md`** now teach `stand_down` as the last act while waiting on a worker, replacing "stay in this session". **`briefs/task.md`** deliberately does NOT teach it yet: `submit_to_boss` is itself a status write, and standing down immediately after it is vulnerable to the identical self-wake race the comment-axis fix closes, just on the status axis — the brief documents this reasoning inline.

### Fixed
- **A dead branch in the yield-loop tracker's own window-emptying check**, found writing this feature's tests: the check ran on a timestamp array that already included the current wake (which is always within its own window of itself), so it could never actually observe an empty window — `yieldSpoken` would latch permanently after a ticket's first yield-loop complaint, silently suppressing every later, genuinely new cluster on that same ticket for the rest of its active lifetime. Fixed to check prior wakes before adding the current one.
