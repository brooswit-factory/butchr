### Fixed
- **The managed-session loader staffed non-definition files, including a backup copy of a real definition (FACTORY-750/FACTORY-755).** `searchSessionDefinitions` (`src/rules/session-definition-type.ts`) and `listSessionDefinitions` (`src/resources/session-definition-manage.ts`) decided eligibility purely by CONTENT: the only name-based gate, `isHiddenDefinitionFile`, only ever caught a dotfile. A byte-identical `*.json.bak-*` copy of a real manifest therefore parsed as valid and got its OWN agent key (derived from its own path, unrelated to the real definition's identity or freeze state) — a backup of a frozen definition would run un-frozen under a duplicate pane. New `isDefinitionJsonFile` (`src/resources/session-definition.ts`) is a POSITIVE allowlist — a candidate is only ever a definition when its basename ends in exactly `.json` (case-sensitive: `.JSON` is not accepted, a deliberate decision pinned by test, not an oversight) — checked at both call sites, always AFTER the unchanged `isHiddenDefinitionFile` gate, never folded into it: a dot-prefixed basename (even one literally named `.json`) still takes the existing silent, never-logged hidden-file path.
- A non-`.json`, non-hidden file (`notes.txt`, a `.bak` backup, ...) is now skipped and logged exactly once via a new dedicated channel (`onceSkippedNonDefinitionFile`, mirroring `onceInvalidDefinition`/`onceFrozenDefinition`/`onceDeprecatedTier`'s own once-per-path dedup) — distinctly from the invalid-definition channel, since it was never offered as a definition in the first place. A genuinely malformed `.json` file is unaffected and still reports through the existing invalid-definition channel.

### Tests
- `test/unit/session-definition-type.test.ts` / `test/unit/session-definition-manage.test.ts`: a byte-identical `*.json.bak-*` backup yields exactly one match/listing (the real `.json`, identity asserted); `notes.txt`/`README` skipped via the new channel, not reported invalid; the skip is logged exactly once across repeated calls and never re-logged; a dot-prefixed file (including a bare `.json` basename) still takes the silent hidden-file path, logging nothing; a genuinely malformed `.json` still reports invalid; uppercase `.JSON` is pinned as rejected; pre-existing frozen/deprecated-tier/oversized-path behaviour is unchanged alongside the new filter.
