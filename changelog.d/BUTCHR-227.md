### Fixed
- **The project tier's comment/epics wake axes no longer depend on Confluence/Jira comment ids being monotonic with creation time.** Durability holds; the wake does not — every comment was always a real, durable row, but a comment arriving with a lower id than one already recorded could be silently never observed: `newestCommentId` (now removed) computed a max-by-numeric-id watermark, and a genuinely new but lower-id comment left that max byte-identical to the previous poll's, so the comparison correctly reported no change against the wrong observed value. `ProjectWatermark`'s `comment`/`epics` scalars are replaced by `commentsSeen`/`epicsSeen` SETS: the predicate is now set membership (an observed id not yet in the seen set is unseen), both writers (`check_in`'s full-batch write and `speakOnOwnChannel`'s self-suppression write) UNION into the stored set rather than overwriting it, and a project entity property's serialized size is now asserted against Jira's stated ceiling at write time and fails loudly rather than risk a silent truncation. The legacy `comment`/`epics` scalars are never deleted (kept as forensic evidence of the regression) and are migrated at read time only — a stored scalar seeds one truthfully-seen id, never a threshold, so a regressed or ratchet-pinned historical value degrades gracefully instead of re-deriving the exact assumption that failed. The version axis (page version numbers, genuinely monotonic by construction) is untouched — it is a separate defect, owned elsewhere.
