### Added
- **A keyless managed-session pane blocked on an unanswerable dialog is no longer silent (FACTORY-45).** `onBlocked` (`src/agents/escalation-loop.ts`) previously logged only `"... blocked with an unanswerable prompt but no issue key — cannot escalate"` for a filesystem-provider `managed-sessions` agent, since it has no Jira/GitHub/Zendesk issue to comment on. It now also logs a distinctive, greppable `[managed-escalation]` line (agent key, definition path, pane id, the dialog's question and numbered options verbatim, and its fingerprint) once per (pane, fingerprint) episode, and marks the session "stalled" on a new `/health` sibling field, `managedSessionEscalations` (cleared when the herd no longer reports the pane blocked at all). Every OTHER keyless pane (an unowned/legacy workspace, a query-level agent, ...) keeps today's log-only behavior unchanged; keyed-issue escalation is unaffected. Real dialog recognition/auto-answer is out of scope here — that is drovr's job (see FACTORY-46) — this only reacts to a dialog the existing auto-answer machinery already declined to answer.
