### Added
- **`scripts/audit-alias-calls.ts` gains a `--since-start` time window, and now states the window in force for every identity, every run (BUTCHR-86/BUTCHR-85).** Previously every run read each discovered daemon's ENTIRE journal, with no time scoping and no way to tell from the output whether a low drift count reflected the current fleet or one that stopped existing weeks ago (one identity was observed with 464,442 total journal lines from all its restarts combined). `--since-start` scopes each identity's read to "since that identity's own currently-running process started", using its own `/health` `build.startedAt` (BUTCHR-54) — never a second, divergent probe. The default (flag absent) stays the whole journal, unchanged, so existing scripted callers are not silently re-scoped; every identity's report line now carries an explicit `window: ...` line either way, so an operator can always see exactly what span a given identity's counts cover.
- An identity whose build identity is unknown (still the common case on a fleet where deploy-on-merge hasn't cycled every daemon yet) cannot be scoped to its process start under `--since-start`. Rather than silently falling back to the whole journal alongside identities that ARE scoped — which would make per-identity counts incomparable without saying so — this is widened loudly: the identity's `window:` line states that `--since-start` was requested, that this identity could not honor it, and why.
- `decideReadability`'s own-identity zero-lines rule is now window-aware: over the whole journal, a live daemon returning zero journal lines is still treated as proof the READ failed (unchanged). Under a `--since-start` window, zero lines from a live, freshly-restarted daemon is a legitimate quiet result, not proof of failure — so a windowed, live, zero-line self-read is now `readable: true` with `totalLines: 0`, rather than forcing the whole run to INCONCLUSIVE. `computeVerdict`'s CONDITION_MET/NOT_MET/INCONCLUSIVE semantics themselves are unchanged.
- Any timestamp used to scope a journal read goes through `spawnSync(..., { shell: true })`. Rather than quoting an arbitrary string, the window is carried internally as a validated Unix-epoch-seconds integer (`JournalWindow`), converted from `/health`'s ISO `startedAt` before it ever touches a command string — so there is no space, quote, or shell metacharacter for a malformed timestamp to smuggle through in the first place.
