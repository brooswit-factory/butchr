### Added
- **`/health` now reports the notify stage as its own component, so a daemon that polls Jira perfectly but never delivers a nudge goes red (BUTCHR-57).** `startLoop`'s liveness heartbeat previously fired only at the end of the FETCH stage (search + reconcile + related + label sync); the NOTIFY stage (diffing polls, applying suppression, and calling `deps.notify`) had none, so a poll cycle whose fetch succeeded and whose notify stage failed — or died as a silent unhandled rejection, since `@brooswit/sundry`'s `watch()` never awaits its `onChange` callback — still reported `{"ok":true}`. `/health` now returns `{ ok, components: [{name:"pollLoop",...}, {name:"notify",...}] }`, where `ok` is the AND of both components and the endpoint returns 503 when either is not ok. `components[0]` is still `pollLoop` in the same shape as before, so a consumer reading it positionally is unaffected; a consumer that assumed exactly one component needs updating.
- The notify stage's own `ComponentHealth` is fed by a positive heartbeat recorded when a full notify pass concludes without throwing — including the zero-nudges case (nothing changed in Jira this poll), so a genuinely quiet fleet stays green. `startLoop`'s second `watch()` argument now runs on every poll tick rather than only when the polled snapshot's content-hash changes (via `watch()`'s injectable `hash` option), and its whole body is wrapped so it can never let its returned promise reject — `watch()` doesn't await it, so an unwrapped rejection would be silent. A rejecting notify pass is instead logged as `  WARNING: [notify] stage threw: ...` and the notify component goes stale like any other missed heartbeat. It reuses the poll stage's existing `BUTCHR_POLL_STALE_MS` threshold rather than adding a second knob, since the notify stage now runs on the same per-poll cadence as the fetch stage. `src/daemon/health.ts` gained `combineHealth()`, an additive helper that ANDs several `LoopHealth` components' `ok` and concatenates their `components[]`; `createLoopHealth`'s existing single-component contract is unchanged.
- Note on scope: this heartbeat covers whether the notify stage RAN TO COMPLETION each poll, not whether any individual nudge was actually delivered — `deps.notify` in `src/daemon/index.ts` already tolerates an undeliverable nudge (an agent legitimately not running) by `.catch()`-ing `herd.nudge` into a logged, non-throwing outcome, by design. A green `notify` component means the stage is running, not that every computed nudge landed.
