### Fixed
- **Agent-view row label regression: the visible `.key` on `/` and `/dashboard` is the bare provider-native resource id again, not the full agent key (FACTORY-408).** FACTORY-407 (PR #532) widened `AgentDashboardRow.resourceKey` to the full `<resourceProvider>:<ruleId>:<resourceId>` key for correlation, hrefs and anchors — correct, but `renderAgentRow` (`src/web/dashboard-page.ts`) also used that same field as the row's visible label, so an ordinary issue-tier row silently grew from `FACTORY-68` to `jira-work:epics:FACTORY-68`. `resourceKey` itself is unchanged (still the full key, still used for correlation/hrefs/anchors); only the `.key` span now decodes it (`decodeAnyAgentKey`, same pattern `buildTier` already used) back to the bare id — `FACTORY-68`, not the full key — for an ordinary resource row, and to `<resourceProvider>:<ruleId> (query)` for a `singleton`/`persistent` rule's query-level agent, which has no single resource to name. A new test pins the exact `.key` content for both shapes, closing the `toContain`-style gap that let the original regression ship silently.
