### Fixed
- **The project tier's own-channel read-back (`createOwnChannelComments`, `src/tools/speak.ts`) now carries a real `created` timestamp and a defended order, instead of a hardcoded `created: ""` and untrusted API return order (BUTCHR-171).** `AtlassianOps.getPageComments` (`src/tools/atlassian.ts`) is widened to an optional `created`, sourced in `src/tools/atlassian-real.ts` from the footer comment's `version.createdAt` — MEASURED via confluence.js's own schema (`z.ZodCoercedDate`) and runtime (`schema.safeParse`), so this arrives as a real `Date` and is converted with `.toISOString()`, never passed through raw or synthesised. This is a LAST-EDITED time, not a distinct "originally created" time — accepted deliberately since no current caller reads a foreign, post-posting-edited comment closely enough for the gap to matter. Row order is no longer trusted from the API (which requests no `sort`): `createOwnChannelComments`'s project branch now sorts newest-first by NUMERIC comment id itself, a post-condition that holds regardless of API return order.
- **This closes a same-fingerprint `ANSWER` replay hazard on the project tier**: `escalation-loop.ts`'s recency filter (`Date.parse(r.created) < escalatedAtMs - CLOCK_SKEW_GRACE_MS`) was inert for every project-tier row (`Date.parse("")` is `NaN`, and `NaN < x` is always `false`), so a stale pre-escalation `ANSWER` matching the current fingerprint could be replayed after a daemon restart cleared in-memory dedupe state. The filter is now live for both tiers.
- **The 15-minute follow-up nudge is now durably deduped across a restart**, the same way the initial escalation already was: it reads its own channel and adopts a prior follow-up by marker before re-posting, via a new `FOLLOWUP_STAGE` discriminator (`src/agents/escalation-loop.ts`) combined with the existing parenthesised fingerprint spelling — deliberately non-overlapping with the escalation's own colon-spelled `fingerprint: <fp>` adoption predicate, so neither is ever mistaken for the other in either direction.
