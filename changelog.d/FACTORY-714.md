### Added
- **Each already-running pane's persisted Claude session id is reported to herdr once at daemon startup (FACTORY-714/FACTORY-713/FACTORY-704, re-aimed).** A real rehearsal found herdr itself relaunches a restored pane with `claude --resume <id>` in ~0.1s whenever it already holds that pane's `agent_session` — far faster than any daemon-side reconcile poll could ever react — and that the actual production gap was never a race to gate: it is that nothing ever told herdr the id, because the Claude `SessionStart` hook integration that would normally do so is not installed. `reportPersistedAgentSessions` (`src/agents/report-agent-sessions.ts`) closes that gap directly: for every pane herdr lists without an `agent_session` and with no in-flight launch (`launch_pending`), it reports the session id butchr already discovered and persisted for that workspace, via `herdr.pane.reportAgentSession` (source `herdr:claude`). Idempotent and one-time per daemon start — wired alongside the existing `relabelOwnedWorkspaces()` startup sweep (`src/daemon/index.ts`), same fire-and-forget, never-throws shape. Logs a truthful `[agent-session-report] N reported, M already registered, K with no persisted id` summary — it claims only what it actually did, never a future resume outcome it cannot observe.

### Removed
- **`RestoreSettleGate` (FACTORY-710/FACTORY-708/FACTORY-704), its `BUTCHR_RESTORE_SETTLE_BOUND_MS` config knob, and its wiring into the issue rule loop.** A scratch-herdr rehearsal (FACTORY-704's RE-AIM) showed the gate provides no protection on the real system: on the actual state (herdr relaunching restored panes itself, independent of anything butchr's reconcile loop does), the gate never settled by stability and always fell through to its 60s bounded wait before fresh-spawning exactly what it existed to protect — strictly worse than doing nothing, since it only delayed the inevitable fresh spawn. The fix above (reporting the id herdr needs, directly) addresses the actual mechanism instead.
