### Fixed
- **`briefs/` is now a gated path, so a brief-only rewrite can no longer ship with a green release gate, no changelog fragment, and no version bump (BUTCHR-40/55).** The release gate's `requiresRelease` predicate (`scripts/release/gate.ts`) only matched `src/`, `schema/` and `package.json`, but the five brief templates under `briefs/` are compiled into the shipped binary at build time (`Bun` `with { type: "text" }` imports in `src/agents/workspace.ts`) and are the operating instructions every newly spawned agent reads on its first turn — so a PR that rewrote what every future agent is told to do previously passed the gate green with nothing to record the change. `briefs/` is added to the gate's `GATED` list and to the two prose restatements of the same rule (`changelog.d/README.md`, and the versioning paragraph near the top of this file) so all three agree; confirmed with a RED/GREEN run of `scripts/release/check.ts` against the real PR base (`origin/BUTCHR-40`) on a throwaway briefs-only commit, reverted before this PR.
- **Regression coverage added in two layers.** `test/unit/release-gate.test.ts` gained a direct case (a briefs-only `changedFiles` with no fragment fails, naming exactly what to add) plus a generalising case that walks every `.ts` file under `src/` for a build-time asset import (`with { type: ... }`) and asserts `requiresRelease` covers whatever path it resolves to — so the next embedded asset added outside `src/` fails this test instead of silently reopening the same hole, rather than only re-asserting the five current briefs by name.
