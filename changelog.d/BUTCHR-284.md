### Added
- **A configurable, fleet-wide admission cap on resident agents (`BUTCHR_MAX_AGENTS`, default 8).** Nothing previously bounded how many agents this daemon kept RESIDENT at once, so the reconcile loop would happily try to have dozens of agents alive on a host it shares with a second, mutually-invisible butchr daemon — measured OOMing the host twice. A fixed COUNT cap (not a memory watermark: a watermark reads memory as free at t=0, exactly when a post-reboot stampede would admit the whole fleet before any of it has allocated anything; not a per-project quota: a fairness mechanism, not a capacity one) is enforced by ONE shared `AdmissionController` (`src/agents/admission.ts`) built over the raw, unscoped herd and wired into BOTH the issue and project resource loops (`src/daemon/index.ts`) — a per-tier cap would leave the host itself unbounded, since each tier's own `scopedHerd` view only ever sees its own agents.
- **Over-cap spawns are WITHHELD, never dropped.** Given a per-poll budget `max(0, cap − residency)`, only that many NEW agents are started this poll; the rest are simply not attempted and are picked up automatically on a later poll once a slot frees. `desired`, `plan.stop`, and Jira status are never touched by admission control — an over-cap ticket stays desired, retried, and is never stopped (proven by test, not merely asserted). A respawn (stop-then-spawn of an agent that is already resident — net zero change in residency) never consumes budget.
- **Fail-safe against an unreadable or implausible residency census.** A `residency()` call that throws withholds every candidate this poll rather than risk admitting a full burst against a false zero. A READABLE zero is treated the same way UNLESS it is plausible: a fresh boot with no prior trusted observation (a legitimate cold start) is trusted immediately, and a drop to zero this poll's own plan actually explains (it stopped at least as many as were last trusted running) is trusted too — anything narrower is treated as an untrustworthy read (the exact shape BUTCHR-282 measured: a readable, confidently-empty herdr list against a fleet that is, in fact, alive) and withheld, bounded to a small number of consecutive implausible polls before the zero is accepted anyway, so a genuinely-draining fleet is never deadlocked forever. This is a bounded mitigation on the polls this admission gate runs, not a fix for BUTCHR-282 itself.
- **The withholding is audible.** One log line per poll where anything was withheld, naming the cap, the observed residency, and a ratio (withheld/wanted) with the withheld ids — never a per-ticket Jira comment (the issue tier polls every 15s; that would be a comment storm).
- **`/health` reports the cap and current fleet-wide residency** as a sibling field alongside `build`/`coverage` — sitting at the cap is a normal, healthy state and never flips `ok`.
