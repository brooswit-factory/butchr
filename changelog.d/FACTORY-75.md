### Added
- **Managed-session definitions and rule-launched agents can now pick their model AND their effort independently, on a 0-100 scale, instead of one 5-point `tier` (FACTORY-75).** Two new fields — `modelPower` (which model launches) and `effort` (how hard it thinks) — replace `tier` on `SessionDefinition` (`src/resources/session-definition.ts`) and add `modelPower`/`effortPower` to `Rule.agentPreferences` (`src/rules/rules.ts`). Both axes are resolved through per-vendor tables in the new `src/resources/power-scale.ts` (Claude: Haiku/Sonnet/Opus/Fable; Codex: its own 4-model tier reused verbatim), and a shared effort table (`low`/`medium`/`high`/`xhigh`/`max`) translated per vendor at launch (`--effort` for Claude; `model_reasoning_effort` in `.codex/config.toml` for Codex, since Drovr's own Codex launch type has no effort field). See `docs/power-scale.md` for the full tables, naming rationale, and the four operator-requested canonical target pairs.
- **Auto-reconcile on change:** editing a definition's/rule's `modelPower`/`effort` (or a table edit shipped in a new daemon build) so it now resolves to a different model or effort than the running agent's stops that agent and lets normal reconcile start it again — exactly once, never a respawn loop. Same FACTORY-43 shape (persist the resolved value at spawn, compare against the LIVE current resolution at stale-check time via a new `HerdrHerd.resolvedAgentOf` seam), extended to a comparison Drovr's own `checkManagedAgentArgv` has never covered (`--model`/`--effort`).
- `tier1`-`tier5` are DEPRECATED but still fully supported — a `tier`-based definition bypasses the new tables entirely and resolves via the pre-existing `tierToModel` with NO effort override, reproducing today's launch behaviour byte-for-byte on both vendors (logged once per definition via a new deprecation notice). Migrating existing definitions to the new fields is not part of this change.
