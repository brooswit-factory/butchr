### BREAKING

- **Clevr's fixed extension id (`chrome-extension://geffpgminecanhmpafbliajpeleoocan`) is now the ONLY allowed origin for `GET`/`POST /resources/for-url` and `GET /agents/:agentKey/pty` — hardcoded, not configurable.** `BUTCHR_EXTENSION_ORIGINS` and the whole operator-allowlist concept (unset-defaults-to-fixed-id, additive override, explicit-empty fail-closed) are removed from config, docs, tests and `.env.example`. This is a deliberate narrowing of configurability to one hardcoded id, per the operator's own decision (FACTORY-330 comment 27837), not a bug fix — the previous default-plus-override scheme (FACTORY-475/FACTORY-477) is gone. **The extension id changes whenever Clevr's manifest key ships**, so the operator's Chrome install needs a reload or reinstall to keep working. A daemon whose environment still sets `BUTCHR_EXTENSION_ORIGINS` (e.g. an existing systemd drop-in) does not fail to start; it logs exactly one startup warning naming the variable as ignored. **The existing systemd drop-in in admin-assembly that used to set this variable becomes unnecessary and should be removed in the same deploy** — that removal itself is out of scope for this PR. Guard behavior is otherwise unchanged: absent `Origin` is still `403`, any other origin is still rejected, and CORS headers are only ever emitted for the one allowed origin, never `*`.
