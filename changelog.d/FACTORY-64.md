### Added
- **WSL Windows host install/verify tooling and docs (FACTORY-64, story FACTORY-59, epic FACTORY-58).** Turns the hand-built "zippy" Windows host (Butchr + herdr inside WSL Ubuntu) into a documented, scripted, repeatable install, so a second Windows host is a documented install rather than tribal knowledge. A native Windows pane backend remains out of scope — herdr is Linux-only; everything here runs inside WSL.
- `scripts/wsl-host/install.sh` (WSL-side bash bootstrap) execs into a new, fully unit-tested TypeScript CLI, `scripts/wsl-host/cli.ts` (`install`/`verify`), following this repo's own `scripts/deploy/watchdog.ts` precedent: every shell-out/file access is reached through one injected `WslHostIo` object. `install` checks/installs prerequisites (bun, git auto-installed; claude/codex/herdr detected only, with a clear next-step when they can't be auto-provisioned), idempotently edits `/etc/wsl.conf` (`[boot] systemd=true`, optional `[user] default=`), enables lingering, places the herdr binary, renders and writes `butchr.service`/`herdr.service` (+ its `LimitNOFILE` drop-in) systemd user units, and creates (never overwrites) `butchr.env`/`managed-sessions.env` empty and `0600`.
- `scripts/wsl-host/verify` / `cli.ts verify` and the Windows-side `scripts/wsl-host/Verify-WslHost.ps1` report health as three distinctly-worded, distinctly-exit-coded states — `WSL: DOWN`, `WSL: UP, daemon: DOWN`, `WSL: UP, daemon: UP` — never conflating "WSL itself isn't up" with "the daemon inside it isn't," with an unreachable/unknown signal always treated as unhealthy rather than assumed fine.
- `scripts/wsl-host/Register-WslHostTask.ps1` registers a generically-named (`Butchr-WSL`, overridable), idempotent Windows scheduled task that starts the WSL distro and both units at logon (plus a repeating trigger to counter WSL's own idle shutdown) — deliberately never touching any other scheduled task, and never named after (or targeting) the zippy host's own hand-built tasks.
- New doc `docs/windows-wsl-host.md`: prerequisites, step-by-step install, both systemd units' contents and rationale, the Windows task's contents and rationale, how to read the health check's three states, token/secret handling, WSL's NAT-networking caveat, a troubleshooting section, an explicit "what was and wasn't tested off-Windows" section, and a known-limitation note (daemon startup still requires Atlassian credentials unconditionally — tracked separately as FACTORY-65, not implemented here).
- New tests: `test/unit/wsl-host-wsl-conf.test.ts`, `test/unit/wsl-host-units.test.ts`, `test/unit/wsl-host-health.test.ts`, `test/unit/wsl-host-cli.test.ts`. No changes to the existing Linux install/systemd path, `docs/codey-deploy-runbook.md`, or `scripts/deploy/*`.
