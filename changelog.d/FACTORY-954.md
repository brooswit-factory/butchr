### Changed
- **`decide()` (`src/resources/issue.ts`) now allowlists what a RELATED (boss) watcher is ever notified about, instead of falling through to the same general classifier `primary` (self) uses (FACTORY-954, implementing story FACTORY-951).** Before this, a related watcher was woken by ANY status transition, daemon-label change, summary/assignee/description change, issuelinks diff, or any comment id moving — `excludeBookkeepingComments`/`isBookkeepingComment` only ever stripped bare `[butchr:*]` chatter from the comment cursor, so routine child activity (an In Progress poke, a priority-only edit's leftover `updated` bump, an unaddressed comment) woke the boss exactly as loudly as a genuine status report. A related watcher now only ever wakes for: (1) a status transition whose `to` is "In Review" or "Done"; (2) a comment whose body is a worker->boss marker — either the ticket's own identity tag (the one shape `report_to_boss`/`ask_boss` give every comment a worker posts on its own channel; `submit_to_boss` posts no comment at all, covered by the status-transition arm instead), or one of the allowlisted `WAKE_MARKERS` daemon escalations (`[butchr:blocked]`/`[butchr:respawn]`/`[butchr:stall]`/`[butchr:unresponsive]`). Everything else (label, summary, assignee, description, issuelinks, or any comment that isn't boss-addressed) now returns `deliver: false` outright for `related`, never through the stand-down gate (`finalize`) — which can wake a sleeping watcher as a side effect, so this is checked BEFORE that gate rather than after it. `primary` (self) space is completely unaffected: every `finalize(...)` call site for it is untouched. `appeared`/`disappeared` (existence changes) and the primary-only `pr:*` reason are also unaffected for either space — they were never part of the noise this ticket's own problem statement named.
- **A `[review]` reply was checked against this ticket's base commit and found to travel the opposite direction only** (`tell_worker`, boss -> worker, tagged with the BOSS's own identity, never the worker's) — it can never reach this predicate's input as an incoming related-space comment, so it is deliberately not matched by the new allowlist.
- **No @-mention routing exists in this codebase for Jira comments** (grepped at this ticket's base commit — only Rocket.Chat-room mentions exist, unrelated to Jira issue comments) — the ticket's item 3 is therefore scoped OUT, not silently skipped: there is nothing to allowlist.
- **FACTORY-948/949 interaction, stated rather than silently resolved:** a sibling story is concurrently carving an `agent:*`->`agent:blocked` daemon-label transition out of `isDaemonLabelOnlyDiff` suppression, delivered only on the related edge. That carve-out is not present at this ticket's base commit, so it is not specially allowed by this ticket's allowlist either — a `{ label: ... }` reason is "everything else" here and returns `deliver: false`, including that transition, until whichever of these two tickets lands second reconciles with the other (see `deliverToRelated`'s own doc comment in `src/resources/issue.ts`).
- A related watcher that is currently ASLEEP (BUTCHR-307's stand-down gate) no longer fails toward waking on an `{ undetermined: ... }` reason — that reason never carries a confirmed, boss-addressed comment body to check, so it is now excluded from the related-space allowlist same as an awake watcher's identical case. `primary` space's own fail-toward-waking behavior for `undetermined` is unaffected.
