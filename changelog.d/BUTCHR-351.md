### Fixed
- **`[notify-suppressed]`'s reader (`parseSuppressedLine`, `src/jira-watch/suppressed-log.ts`) now actually parses under `journalctl -o cat` and every other prefix-less capture (BUTCHR-351, round 2 of BUTCHR-322).** Production's own `log:` dep wiring (`src/daemon/index.ts`) applies a two-space indent unconditionally, prefix or not — the reader's anchor used to rely on a genuine journalctl transport prefix's own trailing whitespace to absorb that indent, so a real, unmodified line failed to parse (`null`) whenever no prefix was present. A genuine suppression then read as "not a record" — the exact silent false negative this instrument exists to prevent. Fixed by tolerating optional whitespace between the (optional) prefix and the tag, mirroring `parseAliasAuditLine`'s existing `TOOLS_LINE` precedent (`src/tools/alias-audit.ts`). Pinned by a test that builds the line through the production log closure's own shape, not the bare emitter return value.
- **A daemon-label-only diff coinciding with a ticket's comments going from non-empty to empty (a deletion, not an addition) no longer wakes a sleeping watcher unconditionally.** The suppression arm that observes this edge (`crossDaemonSuppressed`/`ledgerHitSuppressed`, `src/resources/issue.ts`) used to omit the delivery's comment id entirely when the newest comment id read back `null`, which made `decide()` fall through to the general classifier and name the coinciding label change as a STRUCTURAL reason instead — bypassing BUTCHR-307's stand-down `unseenFor` gate and waking a sleeping watcher the pre-BUTCHR-350 code would have suppressed, a behaviour change BUTCHR-322's own scope forbids. `SuppressionVerdict.commentId` and `NotifyReason`'s `comment` member are now `string | null`: `null` carries the same positive evidence of movement as a string id, but names a deletion rather than an addition, keeping the reason non-structural (`{ comment: null }`, never a bare `commentId` that lies about an id existing). Rendered as `(comment:deleted)`/"had a comment removed" — never the literal string "null".
- The `arm=stand-down` suppression volume, previously argued only qualitatively ("bounded by how many watchers are currently asleep"), now states its numeric ceiling: at most 240 `[notify-suppressed] arm=stand-down` lines per watched key per sleep episode, from the issue tier's existing 15s poll interval and the default 60-minute `standDownMaxSleepMinutes` cap.
