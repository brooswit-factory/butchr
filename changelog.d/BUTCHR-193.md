### Added
- **The three closing doors now refuse a caller (or, for `finish_worker`, the worker being closed) that still has an open worker of its own (BUTCHR-193).** `finish_worker`, `finish_without_a_boss` and `submit_to_boss` previously never looked downward at all — every ownership check in this codebase walked UP via `findBossKey`, and nothing walked down. That gap let a boss reach Done/In Review while a worker it undertook to close was still open, with nothing to catch it: measured live once (BUTCHR-127 went Done at 05:21:37 with its worker BUTCHR-159 still open, and BUTCHR-159 was not closed until 07:36:45 — 2h15m later, and **not through the sanctioned path**: its boss had been Done for over two hours, `finish_worker` refuses any caller that is not the worker's own boss, and BUTCHR-159's `Implements` link still points at BUTCHR-127, so nothing had re-homed it either. It was forced Done from outside the boss/worker path, through the same deprecated `jira_transition` alias this guard cannot cover — an instance of the bypass documented below, not a case of the rule being upheld by hand). A fleet-wide audit (§6 of this ticket, method and positive control in the PR body) found the count currently at zero across project BUTCHR — this ships ahead of the next instance, not in response to one still open.
- New `findWorkers` (`src/tools/docs.ts`), `findBossKey`'s own mirror: reads a caller's own workers off its ALREADY-FETCHED `getIssue` payload via the outward `Implements` link stubs Jira hydrates with `fields.status` at no extra call — pure and total over the payload, tolerant of missing/garbage `issuelinks`, exactly like `findBossKey`.
- New shared `openWorkers` guard (`src/tools/relationship.ts`): "open" means any status other than Done, UNLESS the worker carries `butchr:shelved` (`EXEMPT_LABEL`) — a recorded, reasoned deferral via `shelve_worker`, not silent abandonment. The label isn't present on the outward link stub (measured against a real labelled worker), so it costs one extra `getIssue` per non-Done worker, paid only on the path that is already about to refuse; the common case (no workers, or all Done) costs nothing beyond what each verb already fetched.
- Every refusal names the offending worker(s) by key AND status, and both discharge verbs by name (`finish_worker`, `shelve_worker`) — an agent that hits it can act without reading any ticket.
- `finish_worker` now looks at the WORKER BEING CLOSED's own workers (the caller's grandchildren), not the caller's — it's the worker's own undertaking to close its workers that the call is about to make unreachable.
- `submit_to_boss` is guarded too, deliberately: it's the earliest of the three doors an agent can hit, so the refusal reaches the agent that can actually fix the problem, at the moment it becomes that agent's problem, one Jira read added to a verb each ticket calls roughly once in its life.
- `finish_without_a_boss`'s new downward check is additive and orthogonal to its existing upward has-a-boss refusal (BUTCHR-92, still shelved/un-started) — that refusal's condition, message and position are unchanged; the two compose without touching each other. Unlike BUTCHR-92's shelved narrowing, this refusal always has a named, callable exit (`finish_worker` the worker for real, or `shelve_worker` it with a reason), so it does not reproduce BUTCHR-92's circle (a refusal with no exit for anyone).
- No exemption, no grandfather clause, no carve-out for tickets already open when this ships — BUTCHR-92/BUTCHR-62 rejected that shape of fix deliberately, and this follows the same reasoning.
