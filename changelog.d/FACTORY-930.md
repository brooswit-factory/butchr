### Fixed
- **A failed spawn no longer consumes a deliberate `stand_down`'s stop-cause marker** (epic FACTORY-843, story FACTORY-850, formal review of PR #739): `decideRespawnResume` (and the non-claude branch of `HerdrHerd.spawnExclusive`) used to clear this workspace's durable stop-cause marker as soon as a spawn DECISION was made, before the launch it was deciding for had actually run. If that launch then failed (blocked, providers exhausted, or the resumed pane dying immediately), the marker stayed cleared, so the very next spawn attempt read no marker at all, misclassified the stop as unintended, and resumed the agent's prior Claude session — silently breaking `stand_down`'s "you are a fresh session" contract. The marker is now snapshotted before either call site can clear it and re-persisted verbatim if every launch attempted for that `spawn()` call ultimately fails, so a stood-down workspace's marker survives a failed spawn attempt instead of being lost to it. The existing property that one SUCCESSFUL respawn still clears the marker (so a later genuine crash resumes) is unchanged.
