### Added

- **`Rule.notifyDeliveryMode`: per-rule choice between the MCP channel and a direct typed prompt for update/notification delivery (FACTORY-1010).** Optional, one of `"channel"` or `"prompt"`. Absent is today's behavior exactly, unchanged: `deliverNotice` (`src/notify/deliver.ts`) tries the channel first and falls back to the prompt on any unavailable/refused/thrown push. `"channel"` sends ONLY via the channel — on a miss it returns a clear non-delivery result (`{ via: "none", reason }`) rather than silently trying the prompt. `"prompt"` sends ONLY as a direct typed nudge, never even attempting the channel push. Neither explicit value ever sends both. Threaded through every rule-owned seam that routes through `deliverNotice`: the `jira-work` rule engine (including linked-change and PR-review-state nudges) and the `github-issue`, `github-pr`, `jira-idea`, `zendesk-ticket`, `filesystem` and `confluence-page` rule loops — resolved once per agent key via a new `ruleNotifyDeliveryMode` lookup (an agent key carries exactly one owning rule, so this is a direct lookup, never a multi-rule merge). Deliberately NOT wired into the idle-poke engine (a stall-remediation wake nudge with its own per-ISSUE multi-rule config merge, a different shape) or the managed-sessions loop (its agents come from `SessionDefinition`, not a `Rule`) — see `docs/notify-delivery-mode.md`.
- `deliverNotice`'s result and `[notify]` log line now distinguish an EXPLICIT choice from the default fallback: an explicit `"channel"` success is `{ via: "channel", explicit: true }` ("Claude channel delivered (explicit mode)"), distinct from the default success's unchanged `{ via: "channel" }`; an explicit `"prompt"` result carries no `fallbackReason` (that field means "the channel was tried and lost", which cannot happen in that mode).
- Validated on write (`src/rules/rules-write-registry.ts`'s `validateRuleFieldPatch`, part of `EDITABLE_TOP_LEVEL_FIELDS` — never risky, never requires `confirm`) with `null` meaning REMOVE the field (same `stalledMinutes` null-means-unset precedent), surfaced read-only in `GET /api/rules`, and editable from the Rules page's edit dialog as a "notification delivery" select ("butchr's default" clears a previously-set value back to the omitted/default behavior).
