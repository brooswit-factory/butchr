### Added
- A Rocket.Chat REST client (`src/resources/rocketchat.ts`) and an idempotent account-lifecycle manager (`src/accounts/manager.ts`, `src/accounts/identity.ts`) for `Rule.account`'s `temporary`/`permanent` policies (BUTCHR-395/S4). Standalone and not yet wired into agent start/stop (a follow-up task): `ensureAccount` create-if-missing (race-safe, adopts an existing or lost-record account instead of duplicating), `releaseAccount` unprovisions a `temporary` account on `stop`/`archive` only (never on `respawn`/`daemon-restart`) while `permanent` is always retained, and a configurable guardrail refuses new accounts before Rocket.Chat's 50-user allowance is hit.
- `Config.rocketchat` (optional, same all-or-nothing shape as `github`): `ROCKETCHAT_URL`, `ROCKETCHAT_ADMIN_USER_ID`, `ROCKETCHAT_ADMIN_TOKEN_FILE`, `ROCKETCHAT_USER_CAP_THRESHOLD` (default 45). A daemon with none of these set behaves exactly as before; a rule using `account !== "none"` with Rocket.Chat unconfigured gets a typed refusal from the account manager at the point of use, never a startup crash.
- `docs/rocketchat-accounts.md` documents the identity mapping, the managed-marker safety guard, the managed Personal Access Token as the one integration resource cleaned up on release, the persistence location (a workspace-root JSON file, chosen over a per-agent workspace file), and the full `ensureAccount`/`releaseAccount` contract. `docs/execution-modes.md`'s `account` section, which said the lifecycle was "not yet implemented", now points here.
