### Added

- **Rule schema gains `execution` (`swarm` | `singleton` | `persistent`, default `swarm`) and `account` (`none` | `temporary` | `permanent`, default `none`), independent of each other and accepted for every resource provider.** A rules document that omits both loads to exactly today's rules plus the two defaults — no migration, no changed agent keys. `swarm` is unchanged in every respect. `singleton`/`persistent` and `temporary`/`permanent` validate and store now; the reconciliation behaviour for `singleton`/`persistent` (spawning/stopping the rule's one agent, delivering it scope-wide events) and the account lifecycle itself are separate, later work (BUTCHR-398 and story S4 respectively) — setting either field does not yet change what any agent does. See `docs/execution-modes.md`.
- **A stable, collision-free identity for the one agent a `singleton`/`persistent` rule will run**, alongside the existing per-resource `encodeAgentKey`: `encodeQueryAgentKey({resourceProvider, ruleId})` → `<resourceProvider>:<ruleId>:%40query` (the `@` is percent-escaped in the real, produced key), derived from provider + rule id alone (never a matched resource), so the same rule always names the same one agent across daemon restarts. Its workspace sits as a sibling of that rule's own per-resource workspaces (`<root>/<provider>/<ruleId>/%40query`), never their parent. `decodeAnyAgentKey` decodes either an `encodeAgentKey` or `encodeQueryAgentKey` value; `workspaceDirFor`/`agentIdOfWorkspacePath`, every provider's ownership predicate, and the legacy-workspace startup preflight now recognise a query-level key so it is never mistaken for a legacy/unowned workspace, and `callerIdentity`/the `agy` workspace bridge refuse a query-level MCP identity safely rather than crashing. Spawning, stopping, and event delivery for a query-level agent are not implemented by this change (BUTCHR-398).
