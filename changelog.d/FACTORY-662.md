### Added
- **The web write path's shared trust model, plus its first rules endpoints (FACTORY-662).** Every config-write route now goes through the same gate: `GET /api/session` hands out a per-process CSRF token to a same-origin, same-UID caller; every write route requires the dashboard's own Origin/Host, that same-UID peer check, `Content-Type: application/json`, the CSRF token (constant-time compared), and a 64 KB capped body read — all checked from headers alone, before the body is ever parsed. `POST /api/rules/:id/enabled` and `PUT /api/rules/:id` edit only `ui-`-prefixed (web-UI-seeded) rules, through a field allowlist built fresh from the locked current read for that rule's own array index (never a wildcard — a static `"rules.*.enabled"`-style allowlist would have permitted writing ANY rule, not just the target one). Enabling a rule is refused while its `query` is still the placeholder, and above a configurable ticket-count ceiling without an explicit confirm. `POST /api/rules/plan` reports a heuristic spawn/stop/restart/scope estimate without writing anything. `POST /api/undo/:backupId` restores a prior backup through the same guard. Every accepted or rejected write appends one audit-log line and raises a non-deduplicated ops alert (never the CSRF token or a rule's brief). Dashboard responses now carry `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, and `X-Frame-Options: DENY`. FACTORY-657's live reload is stubbed behind an interface pending that ticket's own merge.
