### Added
- **`src/rules/rule-form-catalog.ts`: the single source of truth for the rules page's provider/model/effort/permission-mode dropdowns and lizard-mode toggle**, built from this codebase's own existing constants (`AGENT_HARNESSES`, `AGENT_EFFORTS`, `RULE_PERMISSION_MODES`, the model-power tables) — never a second, hand-maintained list. Served verbatim by a new `GET /api/rules/catalog` route, behind the same dashboard-origin + same-UID peer guard `GET /api/rules` already uses.
- **`PUT /api/rules/:id` now also accepts `harness` (per `agentPreferences` entry), `permissionMode`, and `lizardMode`.** Every value is validated against the same catalog (a custom model id against a shell/argv-safe pattern, `^[A-Za-z0-9][A-Za-z0-9._:/-]{0,63}$`); any unknown value 400s. Setting `permissionMode: "bypassPermissions" | "auto"` or `lizardMode: true` is never a default and now requires an explicit `confirm: true` on the write (surfaced as a new `requiresConfirm`/`confirmReason: "risky-permission"` from `POST /api/rules/plan`), reusing the existing plan/confirm flow. `PUT /api/rules/:id`'s audit line now names each changed field's old -> new value, not just the field name.
- The Rules page's "Set up your first rule" form now has a provider (harness) dropdown, a model dropdown (shipped list + "Other…" custom id) sourced from the new catalog, and a permission-mode dropdown + lizard-mode toggle alongside the existing effort picker.
