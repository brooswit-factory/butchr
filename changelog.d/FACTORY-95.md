### Added
- **Herdr workspace labels are now short, human-readable per-provider display ids instead of the raw agent key (FACTORY-95, implementing FACTORY-90, epic FACTORY-83).** Every resource provider gets its own short-id method (`docs/execution-modes.md` documents the full table): `jira-work`/`jira-idea` show the bare issue key (e.g. `FACTORY-20`); `jira-project` shows the bare project key; a `filesystem` resource shows `<parent>:<name>` (e.g. `brooswit-factory:rinth`); a managed session (its own FACTORY-83-recorded exception to the generic filesystem rule) shows its bare definition name (e.g. `admin-assembly`, never `session-definitions:admin-assembly`); `github-issue`/`github-pr` show `<repo>#<number>` with the owner dropped; `zendesk-ticket` shows `#<id>` with the subdomain dropped. An ordinary resource agent's full label combines its short id with its rule id (`"FACTORY-51 · jira-work"`); a query-level (singleton/persistent) agent with no single resource shows its bare rule id. Two resources that would otherwise reduce to the same label (the same `<parent>:<name>` under different roots, or two query-level rules from different providers sharing a rule id) are disambiguated deterministically — one keeps the bare label, every other colliding key gets a stable `-<hash>` suffix derived from its own full agent key — and every collision logs one WARNING naming the whole group. New spawns get this label directly; a spawn that collides with an already-running agent also relabels that running workspace in the same call (in either sort order), so no two live workspaces are ever visibly left sharing a label between daemon restarts. Every already-running, butchr-owned workspace is also relabeled in place (no agent restart, `workspace.rename`) once at daemon startup, and the same result whichever path computes it for a given agent. Ownership for relabeling is proven the same way FACTORY-89/FACTORY-92 already require — a pane's `cwd`, never herdr's own label.
- **The full agent key is now preserved in herdr's own per-workspace metadata** (`workspace.reportMetadata`, field `agentKey`, source `butchr`) at spawn time and during relabel-in-place, so it stays retrievable for any butchr-owned workspace even though the visible label no longer carries it.
