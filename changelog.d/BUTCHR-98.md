### Fixed
- **A project agent's session-limit captures could never be evicted, because the eviction regex required an issue-key shape (BUTCHR-98).** `session-limit-watch.ts` writes a session-limit capture as `` `${issue}-${trigger}-${timestamp}.txt` `` (trigger is `unrecognised` or `no-reset-time`), but a project caller's resolved id is a bare Jira project key with no `-<digits>` suffix (e.g. `BUTCHR`, not `BUTCHR-68`) — the same defect BUTCHR-96 fixed in the sibling `escalation-loop.ts`, since both resolve `issue` through the same `issueOfAgentName`. `CAPTURE_NAME` required `-\d+`, so a project-shaped capture was written but never recognised as "ours": it was invisible to the eviction sweep and `CAPTURE_MAX_FILES` never applied to it, so captures accumulated without bound. The regex now admits an optional `-\d+` segment, matching both an issue id and a bare project key, while staying disjoint from escalation-loop's own capture names (`-escalation-`) via the literal `-unrecognised-` / `-no-reset-time-` segment — asserted by the existing cross-module disjointness tests plus new tests confirming a project-shaped capture is recognised and evicted at the same cap as an issue-shaped one.
