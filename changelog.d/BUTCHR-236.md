### BREAKING
- **`set_doc`'s result no longer contains `body` — it never confirmed anything, and now the shape says so.** `set_doc` (both the issue caller `setDoc` and the project-root caller `setProjectDoc`, `src/tools/docs.ts`) used to return `{ id, url, title, body }` where `body` was simply the caller's own input argument echoed back — a "confirmation" that proved nothing about what actually landed, for any document size, even a successful small write. It also scaled with document size, so a successful write to a large doc (field-observed: 81,019 characters) came back as an oversize-result error, indistinguishable from a failed write — the worst possible failure mode for a verb that is a FULL-BODY REPLACE, because both a caller's natural responses to that error (blind retry, or reconstruct-and-overwrite from a stale read) are destructive.
- **New result shape, `SetDocResult`, bounded to a few hundred bytes at any document size, for both callers:** `{ id, url, title, version: number | null, wrote: { chars, bytes, sha256 }, stored: { chars, bytes, sha256 } | null, landed: "confirmed" | "unconfirmed", identical: boolean | null }`. `landed` is the deliverable: `"confirmed"` means the page was re-read after the write and returned a body; `"unconfirmed"` means the update call itself succeeded but the read-back did not — almost certainly landed, but not the same as confirmed, and callers must not blind-retry a FULL-BODY REPLACE on it. Nothing here throws except a genuinely failed write.
- **Byte-for-byte equality is not achievable on this surface (measured): Confluence normalises storage XHTML on write** — a literal em dash reads back as `&mdash;`, a literal quotation mark as `&quot;`, on ordinary prose, not as a rare edge case. So `identical: false` is the *ordinary* result of a healthy write, not an error, and is demoted to a convenience: the primary, machine-readable signal is comparing `wrote` against `stored` (normalisation makes `stored` slightly larger; truncation or corruption makes it dramatically smaller). `version` is the server-reported page version on read-back (`null` when unavailable), a bounded and monotonic signal that a write took effect.
- A caller reading the old `body`/`DocResult` shape off a `set_doc` result must switch to the fields above; a caller that needs the written body should call `get_doc()` instead. `set_doc`'s tool description (`src/tools/defs.ts`) documents the new shape and what to do with `"unconfirmed"`.
