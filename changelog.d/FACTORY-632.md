### Fixed
- **`discoverClaudeSessionId` no longer mistakes a transcript from a PRIOR launch of the same workspace for this launch's own when the two land in the same wall-clock millisecond (FACTORY-623/FACTORY-568).** Its `created >= after` bound compared a transcript's sub-millisecond-precision birth time against an integer, whole-millisecond-truncated `after` (`Date.now()`); whenever a stale transcript's creation and the new launch's start fell in the same millisecond, the stale transcript was wrongly accepted, its id re-persisted, and a later model/effort/permission change could silently `--resume` a different, already-finished conversation while reporting it "PRESERVED". The bound now requires `created >= after + 1ms` whenever `after` is a whole-millisecond integer, closing the gap: any transcript written before the call that produced `after` is still unconditionally rejected, at any clock granularity. A transcript genuinely tied to the new launch remains accepted — a real launch takes far longer than a millisecond to write its first transcript line.
- Hardened the two test fixtures that exercise this path (`withResumableSession` in `test/unit/herd.test.ts`, and the FACTORY-418 ordering test in `test/unit/herd-session-id-invalidation-ordering.test.ts`) to use a real, awaited delay before the next launch, rather than relying on a thin wall-clock gap or an ineffective `utimesSync` backdate (which moves `mtime`, never `birthtime` — the value this filter actually reads).
