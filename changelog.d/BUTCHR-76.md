### Changed
- **`start_worker`, `finish_worker`, and `adopt_worker`'s agent-facing tool descriptions now say they withdraw the shelved-exemption label, closing a gap BUTCHR-50 left open (BUTCHR-76/77).** BUTCHR-50 shipped the behavior — those three verbs clear the label as part of reversing a shelve decision, because the label means CURRENTLY shelved, a state, not a history — but never updated `src/tools/defs.ts`'s description strings to say so. An agent reading only the tool description had no way to learn the withdrawal happens at all; it was only discoverable by reading `src/tools/relationship.ts`. This is a prose-only fix for an incomplete description, not a correction to a wrong one: no description ever asserted that only `shelve_worker` touches the label, and `shelve_worker`'s own "ADDS the shelved-exemption label" was, and remains, true.
- `start_worker` and `finish_worker` now each state that they withdraw the label first, if the worker carries it, cleared BEFORE the transition (never after), and skipped entirely — at no extra Jira call — when the worker doesn't carry it.
- `adopt_worker` now states that a `"start"` disposition withdraws the label too, and that this clear is **not** gated on the idempotent-re-adoption short circuit: even a fully idempotent re-adoption (already linked, assigned, and In Progress) still clears a stale exemption, at no extra Jira call, reusing the labels already fetched to decide idempotence.
- `shelve_worker`'s own description is left unchanged, by decision rather than oversight. Considered adding a clause noting the reversing verbs withdraw what it sets; chose not to, because the three reversing verbs now state their own withdrawal directly, `shelve_worker`'s existing "ADDS ... additively" claim stays fully true on its own, and a forward-reference to three other tools' behavior would be the "bolted-on footnote" this ticket's own brief warned against rather than a fact about this call.
- No behavioral change: description strings only, in the three verbs' entries in `src/tools/defs.ts`.
