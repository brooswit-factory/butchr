### Added

- **`DELETE /api/rules/:id` — delete a rule from the Rules page (FACTORY-731, story FACTORY-727).** Behind the same write guard chain as every other rules write (dashboard Origin, same-UID peer, CSRF, the shared per-client write rate limit), and honours `ifMatch`/etag, refusing a stale one with the same actionable message the UI already surfaces verbatim. Refused, unconditionally (never bypassable with `confirm: true`), while the rule is enabled ("disable it first") or has a live agent ("wait for them to finish or stop them first") — live-agent detection reads the SAME poll-fed agent-dashboard snapshot every "is this rule staffed" check in this daemon already reads, never a fresh census of its own; see `ruleHasLiveAgent` (`src/agents/query-agent-inventory.ts`) for the one-poll-interval race this accepts and why. `confirm: true` is otherwise mandatory and server-enforced (new dedicated `confirmReason: "rule-delete"`, added to the existing plan-route union rather than overloading one); the refusal names the rule's id and query, never a bare "are you sure". A backup is taken before the delete (the existing atomic/backed-up write path, FACTORY-658), and the existing `POST /api/undo/:backupId` restores it byte-for-byte. Every delete, accepted or refused, writes an audit line. The Rules page gets a Delete button (disabled while a rule is enabled or has a known-live agent) and a confirm dialog naming the rule and its query.
