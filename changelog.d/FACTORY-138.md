### Changed
- **Butchr's own default for a Claude launch is now `permissionMode: acceptEdits` paired with `lizardMode` eligible, replacing reliance on Drovr's `bypassPermissions` fallback (FACTORY-127/FACTORY-138).** A Claude agent spec that names no `permissionMode` used to get no `--permission-mode` flag at all, so Drovr's own `launch.permissionMode ?? "bypassPermissions"` fallback applied and the agent ran with no permission prompts whatsoever. `agentLaunchConfig` (the shared launch-config builder every Claude spawn and its own stale-argv check both go through) now fills that default explicitly, exported as `DEFAULT_PERMISSION_MODE`. An explicit `permissionMode` on a spec, rule, or managed-session definition — `bypassPermissions` included — still wins over the default unchanged, and `jira-project` agents keep their own unconditional `"auto"` (untouched; a separate story removes that override later). accept-edits auto-accepts file edits only, so Bash/MCP tool-permission prompts still fire — which is why this default never ships without lizard mode also defaulting to eligible: a `SessionDefinition.lizardMode`/`Rule.lizardMode` that is absent (field never set) is now eligible for the daemon's permission-answer timer to auto-clear those prompts; only an explicit `lizardMode: false` opts out. This pairing closes the DROVR-37 freeze shape (an accept-edits agent with nobody answering its Bash/MCP prompts) for every currently-unset agent, not just ones that opted in today. `lizardMode` never reaches the launched process's argv and needs no respawn — it is read live every permission-answer tick.
- **One-time fleet-wide respawn at deploy.** Every currently-running Claude agent was launched with no `--permission-mode` flag (Drovr's `bypassPermissions` fallback applied silently); after this change the expected argv for an unset spec carries `--permission-mode acceptEdits`, so `staleIssues()`'s stale-argv check flags every such agent once and it is respawned with the new default. Managed sessions and rules with an explicit `permissionMode`, `jira-project` agents, and Codex/agy agents are unaffected. This is a deliberate, one-time restart, not a loop: the stale check derives its expectation from the same builder that produces the launch argv, so a freshly-launched agent never re-reads as stale on a later poll (covered by a dedicated test). Rollback: set an explicit `permissionMode: bypassPermissions` per rule/definition, or revert this change fleet-wide — either triggers one more respawn; nothing persisted needs migrating.
