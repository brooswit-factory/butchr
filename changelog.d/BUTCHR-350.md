bump: minor

### Added
- **New `[notify-suppressed]` journal line: a suppressed notify ping is now distinguishable from a change this daemon never observed (BUTCHR-350, implementing BUTCHR-322).** Before this, the issue tier's suppression stack (`createIssueEventRules`) wrote nothing at all when it swallowed a ping — a deliberately-suppressed message, a change nobody made, and a watcher that wasn't resident all left exactly the same trace: silence. Two suppression classes are now logged unconditionally: `arm=agent-fold` — the own-write ledger's AGENT arm (KAN-838) discovering that MORE THAN ONE comment id is newer than its recorded baseline in one fetch window, meaning at least one of them is a foreign message folded into this suppression and never delivered to the ticket's own agent; and `arm=stand-down` — BUTCHR-307's sleep gate suppressing a non-structural edge for a currently-asleep watcher whose seen-set already covers every fetched comment id. Two other suppression arms (a routine `agent:*`/`pr:*` label echo, on either the own-write-ledger DAEMON arm or the cross-daemon check) are DELIBERATELY NOT logged — measured on a live daemon's own journal, they fire on the order of 150-200 times/hour, more than the entire `[notify]` delivered volume; logging every echo would dwarf the rest of the journal for a class that is, definitionally, routine background noise, not a lost message. See `src/jira-watch/suppressed-log.ts`'s own top comment, and this ticket's Confluence doc, for exactly what a missing line does and does not prove for each class.
- Reader `parseSuppressedLine` (`src/jira-watch/suppressed-log.ts`), anchored the same way `parseOutcomeLine`/`parseAliasAuditLine` are (tolerates any single-line `journalctl --output=` transport prefix, refuses a tag merely embedded inside another line's own free text).

### Fixed
- **A delivered `[notify]` line no longer mislabels a real, newly-arrived comment as "reason not determinable" in a way indistinguishable from "the poll genuinely never checked" (BUTCHR-350 §3D).** Confirmed structural, not a race: `(comment)` is only ever named when the poll's own (before, after) diff already contains a daemon-label change (the only trigger that reaches a comments() fetch); a PURE foreign-comment bump (nothing else changed) never reaches that fetch on its own first delivery, so it fell through to the same bare "not determinable" text a genuine I/O failure produced — collapsing two different facts into one string. `NotifyReason`'s `comment` member now carries the actual moved-to comment id (`{ comment: string }`, widened from a bare `true`) so a LATER delivery that does learn the id (e.g. the very next routine `agent:*` flip, once its own label-only diff triggers the check) renders `(comment:<id>)` — letting a reader recognise that pair, for the same key, as one underlying change rather than two independent ones. The "no reason" fallback itself is replaced by three honest, distinguishable `{ undetermined: ... }` sub-reasons — `"unchecked"` (no arm had an I/O reason to look this poll), `"check-failed"` (a fetch was attempted and rejected — reuses this codebase's existing "could not check" vocabulary), and `"checked-unchanged"` (a sibling arm's already-paid-for fetch this same poll positively ruled out a moved comment) — computed from already-fetched per-poll state, never a new Jira call, and never changing what is delivered vs. suppressed.
- **The `KAN-838` residual's own doc comment now states the truth: a foreign comment folded into the own-write ledger's AGENT arm is NEVER delivered to the ticket's own agent, not merely delayed to "that poll".** The fold's own cursor-advance (unchanged by this ticket) permanently absorbs the foreign comment's id, so every later poll's comparison finds no further movement and stays suppressed — verified against the existing KAN-838 regression suite, not merely reasoned about.
- BUTCHR-307's stand-down gate (`finalize`) correctly treats the new `{ undetermined: ... }` reason the same as `{ comment: ... }` — non-structural, gated by the sleeping watcher's own seen-set — rather than the self-wake hazard a naive widening would have reopened (an agent's own comment, landing while it is asleep, waking it unconditionally instead of being checked).
