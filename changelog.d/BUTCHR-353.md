### Added
- **The stall-remediator's wake comment gains a "correctly waiting" branch, and stops giving harmful advice to a boss that is (BUTCHR-353).** Until now `wakeComment` (`src/agents/stall-remediation.ts`) modelled only *done* and *stuck*, offering exactly two pieces of advice — close/transition the ticket, or act on it now — both of which are actively harmful to a boss that is genuinely waiting on one of its own workers: closing/transitioning a boss waiting on a queued spawn cancels that spawn, and one waiting on a live review hop has that review torn down instead; "act now" means re-asserting a disposition that is already correct, which admission control simply withholds again. Measured firing wrongly on three unrelated tickets, including the very story chartered to fix this class of gap.
- **A worker withheld at the fleet-wide admission cap is now named, reusing BUTCHR-352's own vocabulary rather than inventing a second one.** The stall remediator has no live probe of a worker's agent — a boss's worker is staffed under a different Atlassian account than the boss by this fleet's own tier→account split, so a probe wired here would be structurally blind to every worker it could ever be asked about (confirmed live: `probeOutOfScope: true` on every check performed while building this). It is always on the LABEL path, so it reuses `staffingFromAgentLabel`/the new `staffingFromWorkerLabels` wrapper (`src/tools/relationship.ts`, both now exported) rather than re-deriving "marker present → waiting" from scratch — the same discipline that cost BUTCHR-352 three review rounds: a marker is trusted ONLY alongside `agent:none`; a stale marker (any other `agent:*` value) or a stranded one (no `agent:*` label at all) never produces a confident "you are correctly waiting".
- **A worker sitting In Review, awaiting this ticket's own review, is now named too (new scope, decided by measurement: this costs zero extra Jira reads).** A worker's key and status are already on the stalled ticket's own `issuelinks` (`JiraIssue`, populated by `search()`'s existing `fields` param) — the SAME payload `src/labels/sync.ts` already fetches every poll to drive everything else it does — so naming an In Review worker needs no additional read at all, and a live status observation is trusted over a possibly-stale `admission:withheld` marker on the same worker.
- **An unanswered `[ask]` from one of the stalled ticket's own workers is now named.** Measured live: a boss read `agent:stalled` for 11 minutes while its worker was blocked on an unanswered `[ask]` on the worker's own ticket, and the old wake text only ever asked "idle or done?" — each agent was waiting on the other for about 25 minutes. An ask counts as answered once a later comment tagged with the stalled ticket's own identity (a `tell_worker` reply) lands on the worker's ticket after it.
- **Cost, stated and bounded**: for a stalled ticket with N non-Done workers, at most 2N extra Jira reads (one label read, one comment read, per non-Done worker) — paid ONLY on the one poll that is actually about to post a wake comment (past every existing short-circuit: already-remediated, quota-blocked, adopted-existing, rate-capped), never on every poll of a becalming, and never for a Done worker.
- **A stall with none of these three conditions still produces exactly today's wake text, unchanged, byte-for-byte** — pinned by test.
