### Added
- **A crash-looping agent — spawned, dying, and respawned again next poll, forever — is now audible instead of silently repeating (BUTCHR-141).** `planReconcile`'s `spawn = desired − running` has no memory across polls: a resource that can never succeed (a startup crash, a session-limit refusal that never clears, a swallowed kickoff, a workspace that fails to build) is spawned again on every single poll, unbounded, with nothing recording it and nothing saying so. `reconcileNow`'s new optional `checkCrashLoop` hook (`ReconcileOptions`, `src/daemon/loop.ts`) is called with this poll's `plan.spawn` and `desired.keys()`, BEFORE the spawn loop runs — and, deliberately, its result is never consulted: this increment does not gate or suppress a spawn in any way, only observes and speaks. `git diff` on `src/reconcile/plan.ts` is empty.
- New `src/agents/crash-loop.ts`: `BUTCHR_CRASHLOOP_COUNT` (default 5) spawns of the same resource within a rolling `BUTCHR_CRASHLOOP_WINDOW_MINUTES` (default 60) window — not consecutive polls, since the issue tier (15s) and project tier (5min) poll at very different cadences — posts one observational, rate-capped, dedupe-by-adoption `[butchr:crashloop]` complaint on the resource's own channel via `speakOnOwnChannel`, naming the resource, the count, and the window. Wired into BOTH the issue and project loops (`src/daemon/index.ts`), each with its own tracker instance. Pruning is keyed on the resource leaving `desired` (its ticket left the active statuses), never on being absent from a single poll's `plan.spawn` — keying it the other way would silently reset the count on a SLOWER crash loop (spawn, live for one poll, die, respawn) and the alarm would never fire.
- Guards the fleet-wide false-positive case: a poll where essentially the whole `desired` set lands in `plan.spawn` at once (`herd.runningIssues()` reporting empty while herdr is actually up) is treated as evidence about herdr, not about any individual resource — none of that poll's spawns are counted, only delaying detection, never fabricating a false alarm across the whole active ticket set simultaneously.
- **`ownChannelComments` (the reader symmetric to `speakOnOwnChannel`) is extracted from `src/daemon/index.ts` into an importable `createOwnChannelComments` (`src/tools/speak.ts`)** — a move, not a rewrite, with its dependencies injected instead of closed over. `index.ts` previously bootstrapped a real Atlassian/herdr daemon at import, so this reader could only ever be tested by hand-reproducing its representation-sensitive mapping; it is now importable directly, and both existing callers (the frozen-asleep detector and the blocked-dialog escalator) are rewired to it — exactly one project-aware comment reader remains in the codebase.
